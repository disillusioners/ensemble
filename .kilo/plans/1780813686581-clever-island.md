# Plan: Apply "Preload Context" to OpenCode Send Message

## Goal

Mirror the explore tool's auto-preload-context behavior in the OpenCode `external_opencode_send_message` tool. Before the message is sent to the remote OpenCode service, automatically look up the caller's shared-context directory (using the same `context_key` derivation as `explore`), score existing context files against the outgoing message, and prepend the top-N matches (capped at `INJECTION_TOKEN_CAP = 2000` tokens) to the prompt. This avoids burning remote OpenCode LLM time/cost on the trivial task of discovering the project context the caller already has.

## Background

### Current Explore Behavior (`daemon/tools/knowledge_tools.py:382-413`)

`explore()` does this before invoking the explorer agent:

1. Resolves `context_key = manager._instance_repository.get_tree_root_id(current_instance_id)` (fallback: `current_instance_id`).
2. Calls `get_shared_context(context_key, query)` (in `daemon/services/context_injection.py:491`).
3. Prepends the returned injection string to the explorer message.

The injection format (see `daemon/services/context_injection.py:462-488`):

- `# Shared Context` heading
- `## Context dir: …`
- `## Pre-loaded Context (auto-matched)` with up to 3 entries (top match always, 2nd/3rd only if score > 60%), each truncated to fit a 2000-token budget
- `## Available Context Files` table (up to 30 files) for files not pre-loaded

### Current OpenCode Tool (`daemon/tools/external_opencode.py:133-203`)

`external_opencode_send_message` accepts a `message` and ships it verbatim to the remote OpenCode session. It already special-cases control strings (`continue`, `retry`, `abort`, `start-work`) via the dispatch path but always ships the literal `message`. No context lookup happens.

### Skill Guidance (`agents/_prompt_system/innate-skills/opencode/skill.md:9-19`)

The skill currently tells the agent to **manually** gather context (read files, run explore, etc.) and **manually** include it in the prompt. This is exactly the cost we want to amortize.

## Design Decisions

1. **Where to inject** — `external_opencode_send_message` is the single funnel for any prompt going to a remote session; this is the right place. `init_session` only sets the working dir, no prompt — leave it alone.
2. **Always-on, not opt-in** — matches the explore tool's behavior and reduces ambiguity for the calling agent. The caller can always add their own context on top.
3. **Skip control messages** — `"continue"`, `"retry"`, `"abort"`, `"start-work"` are dispatch signals, not tasks. Injecting context into them is noise and risks breaking the OpenCode server's special-prompt routing.
4. **Use the literal `message` as the scoring query** — same call signature as explore. Tokenization & scoring live in `context_injection.py` and are already battle-tested.
5. **Run sync I/O on a thread** — `get_shared_context` is sync; wrap with `asyncio.to_thread` to keep the event loop responsive.
6. **Never raise from auto-injection** — wrap the whole thing in `try/except`; failures log and fall through to the unmodified message. Mirrors explore's "graceful degradation" pattern.
7. **No new dependencies, no new files** — only edits to `external_opencode.py`, `opencode/skill.md`, and one test file.

**b. New private helper** (placed after `_format_response`):

```python
async def _preload_shared_context(message: str) -> str:
    """Auto-match shared context files against the outgoing message.

    Mirrors explore()'s behavior: resolves the caller's context_key, scores
    existing context files against the message, returns a tiered injection
    string (or empty string on any failure / no match). Never raises.

    Args:
        message: The outgoing prompt (used as the scoring query).

    Returns:
        Injection string to prepend to `message`, or "" to skip injection.
    """
    try:
        context_key = manager._instance_repository.get_tree_root_id(current_instance_id)
        if not context_key:
            context_key = current_instance_id
    except Exception:
        context_key = current_instance_id
    try:
        injection = await asyncio.to_thread(get_shared_context, context_key, message)
        return injection or ""
    except Exception as e:
        logger.debug("[OpenCode] Preload context failed: %s", e)
        return ""
```

(Note: `manager` and `current_instance_id` are captured from the enclosing `create_opencode_tools` closure — already a pattern in the file.)

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `get_shared_context` is sync and called from async; could block event loop | Wrap in `asyncio.to_thread` (matches `explore`'s pattern) |
| Injection runs on every send, adding latency | `get_shared_context` is in-process disk I/O only; no network. Typical context dir is a handful of files. Negligible vs. the network round-trip to OpenCode. |
| Pre-injected context breaks OpenCode's control-message routing | Explicit skip list for `continue` / `retry` / `abort` / `start-work` (case-insensitive, stripped) |
| Token explosion if caller sends huge messages | `INJECTION_TOKEN_CAP = 2000` enforced inside `get_shared_context`; output is always capped |
| Behavior change surprises existing tests that assert on the exact prompt body | `TestSendMessageContextPreload` covers the new behavior; other tests mock `_send` and don't inspect the exact body, so they remain green |

## Out of Scope

- Saving the opencode session's result back to the shared context dir (the explorer's `_save_explorer_result` analogue). Could be a follow-up, but adds complexity (needs server-side "completed" hook) and is not asked for.
- Changing the OpenCode server protocol or the registry.
- Adding a per-message `preload_context: bool` flag — keep it always-on for simplicity; can be added later if a use case arises.
