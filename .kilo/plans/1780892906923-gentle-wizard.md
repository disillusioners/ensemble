# Plan: Drive `Need Update KB` from `read_file` tool call (drop agent self-report)

## Goal

Replace the fragile, agent-driven `## Need Update KB: true|false` heading parse with a
deterministic system check: **inspect the explorer's checkpoint, and if the `read_file`
tool was called, set `need_update_kb = True`**. Remove all related code that depends on
the agent emitting (and the system stripping) the heading.

This mirrors the existing `_check_rag_queried_via_checkpoint()` pattern, which
deterministically derives a flag from checkpoint tool calls instead of trusting the LLM
to self-report.

## Implementation steps

### 1. New helper in `daemon/tools/knowledge_tools.py`

Add a sibling to `_check_rag_queried_via_checkpoint` (around line 60) that scans the same
checkpoint state but matches a single tool name:

```python
# File-browse tool name whose invocation indicates the explorer had to look
# beyond RAG — used as the deterministic signal that KB lacks the information.
KB_GAP_TOOL_NAME = "read_file"


async def _check_read_file_called_via_checkpoint(
    checkpointer,
    instance_id: str,
) -> bool:
    """Check if the read_file tool was called by inspecting checkpoint messages.

    Mirrors _check_rag_queried_via_checkpoint: deterministic, source-of-truth
    for whether the explorer had to read project files (i.e. KB likely lacks
    the information the caller needs). Returns False on any error.
    """
    # Same unwrap + aget + scan logic as _check_rag_queried_via_checkpoint
    # but matches name == "read_file" instead of membership in RAG_TOOL_NAMES.
```

**Decision**: keep it as a separate helper (not folded into the RAG helper) for clarity
and minimal blast radius. Refactor of the shared scan logic can be a follow-up.

### 3. Update `explore()` body (lines ~460-525)

Replace the `should_update_kb` block with the new check. Sketch:

```python
# Deterministic KB-gap detection: did the explorer have to read project files?
# (BOTH rag and read_file are checked; read_file alone is the new "Need Update KB" signal.)
rag_queried = False
read_file_called = False
if child_instance_id and hasattr(manager, "_checkpointer") and manager._checkpointer:
    rag_queried = await _check_rag_queried_via_checkpoint(
        manager._checkpointer, child_instance_id
    )
    read_file_called = await _check_read_file_called_via_checkpoint(
        manager._checkpointer, child_instance_id
    )

# Return early if error (AFTER checkpoint inspection)
if is_error:
    return result

# Fire-and-forget: enqueue kb-importer job when the explorer had to read files
# (i.e. KB didn't already have the answer). No more agent-flag dependency.
if read_file_called:
    if not pid:
        logger.warning(...)
    else:
        asyncio.ensure_future(_enqueue_kb_update_job(
            manager=manager,
            query=query,
            explorer_response=result,
            project_id=pid,
            source_instance_id=current_instance_id,
        ))

# No more heading-stripping — agent no longer emits the heading.
# (Optionally: still pass original `result` to kb-importer as today.)

# Auto-save (existing, unchanged): triggers when RAG was queried.
if rag_queried:
    ...  # _save_explorer_result as before
```

**Error path note**: The RAG/`read_file` checks run before the `is_error` early-return
(matches today's behavior), but the kb-importer enqueue is *only* on the success path —
so a fully-failed explorer that managed one read_file call still won't spawn a job with
garbage content.
