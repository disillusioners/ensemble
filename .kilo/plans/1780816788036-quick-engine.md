# Plan: Remove `ENSEMBLE_SHARED_CONTEXT_DIR` and replace with context tools

## Goal

Stop exposing the on-disk context directory path (`ENSEMBLE_SHARED_CONTEXT_DIR`) to agents. Replace it with a pair of **context tools** that take a `context_key` parameter:

- Internal agents (LangChain tools) can call them to list/read context files.
- External agent systems can call them via the **hosted MCP** server (`daemon/mcp/kb_server.py`).

The auto-preload feature remains unchanged in behaviour: when an agent is about to act on a message, the daemon still scans the context directory for matching files and prepends the top-3 to the prompt. The only difference is the *output format* of the preload (path is gone, `context_key` is shown).

---

## 1. Backend service layer — `daemon/services/context_injection.py`

### 1a. Change preload output (preload feature preserved)

**Remove** the `## Context dir: {path}` line from `_format_injection()` (around line 462-463) and from every empty-format return in `get_shared_context()` (lines 519, 526, 533, 540).

**Add** a `context_key: <key>` line in its place, supplied by the caller. Concretely:

- `_format_injection()` gains a new `context_key: str` parameter. First emitted line is `f"context_key: {context_key}\n"`.
- `get_shared_context(context_key, query)` already knows the key — it just passes it through to `_format_injection()` and to the four empty-format returns.

**New output shape (example):**

```text
# Shared Context
context_key: dc15efc2-d1cb-495d-abdf-8d5f522edc84

## Pre-loaded Context (auto-matched)

### auth-flow_20260601_120000 (90% match)
…content…
```

For the "no context yet" case:

```text
# Shared Context
context_key: dc15efc2-d1cb-495d-abdf-8d5f522edc84

## Pre-loaded Context
There is no context yet.
```

The internals of `get_shared_context` (token cap, scoring, top-3 rule, available files index) stay as-is.

### 1b. New low-level functions for the new tools

Add a new module `daemon/services/context_tools.py` (or extend `context_injection.py` — separate file is cleaner). Public functions are **sync** (filesystem I/O) and will be wrapped in `asyncio.to_thread` by callers:

```python
def list_context_files(context_key: str) -> list[dict[str, Any]]:
    """List .md files in {tempdir}/ensemble/context/{context_key}.

    Returns list of {"filename", "slug", "size_bytes", "modified_at", "concise_preview"}.
    Returns [] if the directory does not exist (never raises).
    """

def read_context_file(context_key: str, filename: str) -> str | None:
    """Read a specific context .md file. Validates filename is basename only
    (no path traversal) and that the file lives inside the context dir. Returns
    None on any failure.
    """
```

Security: reject `filename` containing `/`, `\\`, or `..`. Resolve the canonical path and verify it is a child of `tempdir/ensemble/context/{context_key}`.

The new `daemon/services/context_tools.py` reuses the same context-dir resolution helper used by `get_shared_context` — extract that into a small private helper (e.g. `_resolve_context_dir(context_key) -> Path`) shared by both modules. Move the helper into `daemon/services/context_tools.py` and have `context_injection.py` import it.

## 2. LangChain tool category — `daemon/tools/context_tools.py` (new)

New file mirroring the structure of `daemon/tools/knowledge_tools.py` and `daemon/tools/external_opencode.py`:

```python
CATEGORY_NAME = "Context"
CATEGORY_DOC = """\
Context tools for reading the shared markdown context directory
keyed by a context_key (the tree-root instance id of the caller).

Internal agents can call list_context and read_context directly. External
agent systems connected via the hosted MCP can call the equivalent
ensemble_context_list and ensemble_context_read tools.

The auto-preload behaviour (top-3 matches prepended to outbound prompts) is
handled separately by the daemon and does not require these tools.
"""

def create_context_tools(manager, current_instance_id) -> list:
    @register_tool_category("context")
    @tool
    async def list_context(context_key: str) -> str:
        """List all .md files in the shared context directory for `context_key`.

        Args:
            context_key: The context key (CONTEXT_KEY from your system prompt,
                or the tree-root instance id). Required.

        Returns:
            JSON string: list of {filename, slug, size_bytes, modified_at,
            concise_preview}.
        """
        ...

    @register_tool_category("context")
    @tool
    async def read_context(context_key: str, filename: str) -> str:
        """Read a specific context file by filename.

        Args:
            context_key: The context key. Required.
            filename: The bare filename returned by list_context. No path
                separators allowed.

        Returns:
            File contents (utf-8) or an error string.
        """
        ...
    return [list_context, read_context]
```

Both tools require `context_key` (no auto-fallback for internal agents — keep the API uniform with the hosted MCP). To avoid surprising internal callers, the tool's docstring tells them to read it from the `## Context Key` section of their system prompt.

Register the new category in `daemon/tools/_tool_registry.py` (the `CATEGORY_MODULES` dict).

Wire it into the tool factory at `daemon/tools/instance.py` (the `create_instance_tools` function) alongside the existing `knowledge`, `external_opencode`, etc. factories.
