# Plan: `related_context_keywords` Param for `external_opencode_send_message`

## Problem

`external_opencode_send_message` in `daemon/tools/external_opencode.py:291` auto-prepends shared-context files by passing the **full outgoing message** to `get_shared_context(context_key, query, "external", ...)`. The matcher (`daemon/services/context_injection.py:92` — `_match_score`) computes `intersection / len(query_tokens)`. For long, prose-heavy prompts (the common case — review/plan prompts are hundreds or thousands of chars), the intersection is dwarfed by total query tokens, so scores are low, top-3 matches don't cross `MATCH_THRESHOLD` (0.10) or the 0.60 cutoff for slots 2–3, and the pre-load block ends up empty or stale (fallback to most-recent file, regardless of relevance).

The fix: let the calling agent supply **focused keywords** that drive the matcher, with a deterministic then LLM-based fallback when the agent doesn't.

## Design

### Public API change — `external_opencode_send_message`

Add a new optional keyword argument. The agent that issues the call knows its own intent better than the daemon can guess from the raw prompt, so agent-provided keywords are the best path.

```python
async def external_opencode_send_message(
    project: str,
    session_name: str,
    message: str,
    agent: str = "orchestrator",
    model: str | None = None,
    council: bool = False,
    related_context_keywords: list[str] | None = None,  # NEW
) -> str:
```

- Type: `list[str] | None` (a list is more token-efficient than a free-form string and matches what the LLM extractor will produce).
- Default: `None` → "agent did not provide" → fall back chain kicks in.
- Empty list `[]` is treated the same as `None` (defensive normalization).
- Whitespace-only / stop-word-only entries are dropped silently by the preprocessor.
- Hard cap: 12 keywords, 40 chars each — guards against agents dumping their entire prompt.
- Passed verbatim to `get_shared_context(context_key, " ".join(keywords), ...)` when present and non-empty after normalization.

### Resolution chain (in `_preload_shared_context`)

Order: **agent-provided → LLM-extract (quick model) → deterministic heuristic → skip**.

1. **Agent-provided.** If `related_context_keywords` normalizes to ≥1 keyword → use as the `query` argument to `get_shared_context`. Skip steps 2 & 3 entirely. Log: `[OpenCode] Using agent-provided keywords (n) for context preload`.

2. **LLM-extract (best-effort, generous timeout).** New helper `daemon/services/keyword_extraction.py` exposing `async extract_keywords(message: str) -> list[str]`. One-shot `ThinkingChatOpenAI` call with:
   - Model: new `model_keywords` config field (see "Config" below). Default empty → falls back to `model` (same pattern as `model_title`).
   - Temperature: `0.0` (deterministic extraction).
   - System prompt: "Extract 3-8 short noun-phrase keywords from the user message that would best match filenames/topic-slugs of project context files. Return ONLY a comma-separated list, no prose, no quotes."
   - Timeout: `asyncio.wait_for(..., timeout=40.0)` (configurable via `daemon.services.keyword_extraction.KEYWORD_EXTRACTION_TIMEOUT_S`, default **40s**). Rationale: this is a harness/engineering platform, not a chat UI; keyword extraction sometimes takes a while and short timeouts defeat the point. Opencode calls themselves already take much longer, so +40s on the keyword pre-step is in the noise. On timeout → step 3.
   - Output: split on `,` / `;` / newline, strip, dedupe, cap at 12, drop entries >40 chars, drop pure-stop-word entries.
   - Log: `[OpenCode] LLM extracted n keywords in Xms`.

3. **Deterministic heuristic.** When LLM is unavailable / times out / returns nothing usable, fall back to a local extractor that doesn't need the network. New helper `_heuristic_keywords(message: str) -> list[str]` in the same module:
   - First non-empty line up to 80 chars (most agent prompts lead with the topic).
   - Plus noun-phrase candidates: capitalize-words (e.g., `Auth`, `PaymentModule`), CamelCase tokens, identifiers after the first verb ("Refactor X" → "X"), backtick-quoted terms (`` `auth` ``), and the 3 highest-IDF tokens from the first 500 chars after stop-word filtering (reuse the existing tokenize + filter logic from `context_injection.py` — refactor it into a small shared helper if duplication gets ugly, otherwise just import the private tokenize).
   - Cap at 8 keywords.
   - Log: `[OpenCode] Using heuristic keywords (n) for context preload`.

4. **Skip.** If the keyword list is still empty after step 3, log `[OpenCode] No keywords resolved; sending message without context preload` and return `""` (no injection). The send itself still proceeds unchanged.

### New module — `daemon/services/keyword_extraction.py`

Public surface:
- `async def extract_keywords(message: str, *, config: "Config | None" = None) -> list[str]` — LLM path with 3s timeout, returns `[]` on any failure (never raises).
- `def _heuristic_keywords(message: str) -> list[str]` — synchronous, pure-Python.
- `def _normalize_keywords(raw: list[str] | str | None) -> list[str]` — used by the tool to sanitize agent input (strip, dedupe, stop-word drop, length cap, list cap). Exported for unit testing.

Module-level constants:
- `KEYWORD_EXTRACTION_TIMEOUT_S = 40.0` (configurable at import time for tests; tests override to ~0.5s).
- `_MAX_KEYWORDS = 12`
- `_MAX_KEYWORD_LEN = 40`
- `_HEURISTIC_MAX_KEYWORDS = 8`

LLM call uses the existing `ThinkingChatOpenAI` + `clean_llm_config` from `daemon/graph.py` (same pattern as `title_generation.py:81`). Build a fresh client per call (cheap; this is a fire-and-forget, no caching needed — the LLM call is on the send critical path but is bounded to 3s, which is acceptable for `send_message` since it's already async).

### Wire it into `_preload_shared_context`

`daemon/tools/external_opencode.py:136` — refactor the body:

```python
async def _preload_shared_context(
    message: str,
    related_context_keywords: list[str] | None = None,
) -> str:
    # 1. Resolve context_key + project metadata (unchanged)

    # 2. Resolve query string via the 3-step chain
    keywords = _normalize_keywords(related_context_keywords)
    if not keywords:
        keywords = await extract_keywords(message)  # 40s timeout, best-effort
    if not keywords:
        keywords = _heuristic_keywords(message)
    if not keywords:
        logger.debug("[OpenCode] No keywords; skipping context preload")
        return ""

    query = " ".join(keywords)

    # 3. get_shared_context call unchanged, but pass `query` instead of `message`
    try:
        injection = await asyncio.to_thread(
            get_shared_context, context_key, query, "external",
            project_id=project_id, project_name=project_name,
            critical_notes=critical_notes or None,
        )
        return injection or ""
    except Exception as e:
        logger.debug("[OpenCode] Preload shared context failed: %s", e)
        return ""
```

Update the call site at `external_opencode.py:291` to pass the new param through:
```python
injection = await _preload_shared_context(message, related_context_keywords)
```

The control-message bypass (`_OPENCODE_CONTROL_MESSAGES`) stays exactly as is — control messages skip the entire preload path, so the new param is irrelevant for them.

## Risk & Rollout

- **Backwards compatible**: `related_context_keywords` is optional. Existing callers (reviewer, approver, planner, jober, etc.) keep working unchanged — they just get the LLM-extract path, which is bounded at 40s.
- **Latency**: Worst case adds 40s to the first `send_message` call per session (LLM extract). This is acceptable: this is a harness/engineering platform (not a chat UI), keyword extraction sometimes takes a while and a short timeout defeats the purpose, and the opencode call it gates is itself multi-minute. Fire-and-forget tool is already async. If even this becomes a bottleneck in practice, can be moved off the critical path via `asyncio.create_task` and a per-message in-memory cache keyed by `hash(message[:200])` for the session lifetime — proposed as a follow-up, not in this PR.
- **Cost**: One small LLM call per `send_message` when no keywords provided. With `model_keywords=quick`, cost is negligible. Generous timeout is fine because the gated opencode call dwarfs the extraction cost anyway.
- **Determinism**: `_heuristic_keywords` is pure-Python and deterministic; LLM call uses `temperature=0.0`. Match scores are already non-deterministic only by directory mtime order, which is unchanged.
- **Failure isolation**: every step in the chain has a try/except and returns a sensible default. The send itself never breaks.

## Follow-ups (NOT in this PR)

- Cache extracted keywords per `hash(message[:200])` per session for the session's lifetime — avoids re-extraction on retry.
- Consider making `_preload_shared_context` also run for the LLM extraction in the background (`asyncio.create_task`) and let `send_message` send without waiting, then update via a follow-up patch request. Out of scope for v1. (Lower priority now that the timeout is generous — the synchronous path is fine.)
- Surface the resolved keywords in the prepended injection header (e.g., `# Pre-loaded Context (matched on: auth, login)`) so the remote agent knows the intent behind the match. Cosmetic; later.
