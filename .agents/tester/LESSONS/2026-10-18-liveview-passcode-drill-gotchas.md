# Live-View Passcode Drill Gotchas (2026-10-18 closure commission)

Commission: liveview-passcode-1 full verification + e2e closure @ 1121f2604 (worktree
`/home/nea/ensemble-src-wt-liveview-passcode`). All lessons battle-tested by 3 independent
real-daemon drill workers (journey :8081 / brute :8083 / parity :8085).

## 1. Fenced daemon boots MUST pin `PORT` (not `DAEMON_PORT`)
- Symptom: drill boot aborts with Errio-98 (address in use) or binds the WRONG port.
- Root cause: `config.yaml:111` substitutes `port: ${PORT:-8088}`; the ambient shell of any
  agent on this host inherits `PORT=9797` from the LIVE daemon. The daemon listener follows
  config.yaml, not a `DAEMON_PORT` env.
- Fix: every fenced boot script does `export PORT=<drill-port>` explicitly (8081/8083/8085
  pattern). Hit independently by two workers.

## 2. Ambient env-poison refused by the fail-closed DB assert (working as designed)
- Ambient `POSTGRES_DB=ensemble_prod` / `POSTGRES_HOST=10.44.0.2` present in worker shells.
- The mandatory pre-boot assert `POSTGRES_DB == ensemble_dev` (abort otherwise) caught it
  twice across workers. Never weaken that assert; always `source` the worktree `.env` AFTER
  scrubbing, then assert.

## 3. `ViewPasscodeRotationRequired` on re-mint under a rotated key
- A passcode row persisted in a drill DB from a previous run under a DIFFERENT drill Fernet
  key makes the next `mint` raise `ViewPasscodeRotationRequired`.
- Recovery (documented, exercised): `refresh` → new passcode + generation bump. Drill
  scripts should either use a per-run scratch DB/row or expect-and-refresh on first mint.

  legitimately REGENERATED by C1 (commit `1121f2604`) to a five-file run (−999 lines).

  `git show 1483a3984:.agents/shared/planning/live-view-passcode/evidence/phase4-suite-transcript.txt`.

## 5. Whole-tree pytest collection is impossible on this repo (g7 trap)
- `pytest` with no path scoping hits `tests/packs/g7*` which `sys.exit`s → INTERNALERROR
  during collection. Always scope by explicit paths/targets-files (the sweep worker hit this
  once via a silent directory→whole-tree fallback; fixed by targets-as-literal).

## 6. Suite flake variance is ±~12 rows per single run
- Baseline 93F vs branch 82F on identical code families: 13 baseline non-greens recovered,
  2 new rows (1 flaky-under-load, 1 env-deterministic). Single-run snapshots of
  `tests/unit` carry that noise; diff against the baseline LIST, then re-run the delta
  standalone before diagnosing.

## 8. Rate-limit/strike interplay (assert anchors)
- Successful verify CONSUMES a rate-limit token (never a strike): a pristine bucket shows
  `200×5 → 429…` only on a fresh IP; after one success you see `200×4 → 429…`.
- 429 never consumes a strike (unit pin `test_live_views_public_lane.py:1128/1162`).
- Strike ledger lives on the PG passcode row (`failed_attempts`, `locked`); atomic single
  UPDATE with `WHERE locked = 0`; survives daemon restart byte-identically.
