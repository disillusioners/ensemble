# FE Baseline-Attribution Leg Recipe + Reporter-Count Gotchas — 2026-10-06

## 1. FE-only branch? Verify the premise, then reuse the BE

`git diff --stat <base>..<tip>` proving frontend-only means the daemon/DB can serve BOTH legs unchanged — one `dev.sh` BE on :8079 carried 6 legs (~750s traffic) while the FE above it swapped. If any non-frontend file appears, BE reuse is invalidated — fail loud.

## 2. FE swap recipe (branch↔base A/B on one port)

1. `git worktree add --detach /tmp/<name>-base <base-sha>`
2. `cp -al <feature-wt>/frontend/node_modules /tmp/<name>-base/frontend/node_modules` — hardlinks, ~2s, zero disk duplication (verify shared inode on `.bin/ng`)
3. Verify current FE pid's cmdline binds :4199 AND cwd, then stop it (never by bare name/pid)
4. `ng serve --port 4199` from the base tree — cached builds swap in ~14s
5. Sanity: grep a branch-only symbol in the served tree's template (chip-wrap = 2 hits branch / 0 base) — proves which code is under test

## 3. Attribution discriminator matrix (make all quadrants explicit)

| Branch | Base | Verdict |
|---|---|---|
| FAIL | FAIL (identical) | PRE-EXISTING confirmed — no re-run needed |
| FAIL | PASS | ONE base re-run; two base-passes → branch-suspect BLOCKING |
| FAIL ×N isolated | mixed | flaky test — quarantine with retry-budget evidence |
| FAIL ×N isolated | FAIL ×N isolated (same signature) | pre-existing flaky-mostly-failing — branch innocent |

Also tabulate **halted siblings at base** alongside failures: when both legs fail at the same test index and halt the SAME siblings in the SAME order (workers=1, fullyParallel=false), the halt pattern is itself load-bearing symmetry evidence.

## 4. Playwright `line`-reporter counts mislead — always read `.last-run.json`

- "X did not run" under `fullyParallel:false` actually means "siblings skipped after an earlier failure halted the file" — they are neither skips nor absences.
- The summary line can disagree with `[N/M]` progress when conditional `test.skip(true, …)` entries exist.
- Authoritative source: `test-results/.last-run.json` → `failedTests`.

## 5. Halt-on-failure silently drops the risky tail

A late heavy test (e.g. O17 SSE keepalive, >30s idle window) NEVER EXECUTES if an earlier test in the same file fails — across BOTH legs. A "warning about the risky test" pack design that relies on it running is illusory. Split risky tests into their own spec file, or the safety net you think you have does not exist.

## 6. Isolated `-g "<title>"` retry budgets settle flaky-vs-deterministic

3× `timeout 80 npx playwright test <file> -g "<test>" --reporter=line` on EACH leg (no earlier-test halt can mask). 0/3 branch + 0/3 base with identical signature = pre-existing mostly-failing flake (the lone historical pass is noise). Spec self-flag comments ("signal-driven flip lags the Escape press") usually name the mechanism and point to a test-side timeout fix, not product code.

## 7. Small operational wins worth reusing

- Manual dev-lane bring-up mirroring `playwright.config.ts` webServer blocks verbatim (proc_run) + reuse across serial packs — amortizes the ~190s BE boot.
- Snapshot-lane config clone (`playwright.<gate>.config.ts` reusing `boot-e2e-snapshots-daemon.sh`) is the established pattern for gates needing clipboard permissions — config-level `use.permissions` is the repo's only clipboard precedent; per-test `context.grantPermissions` is not.
- Playwright-run PNG artifacts in a tracked tree leave the worktree dirty — restore before handoff; never commit fixtures regenerated by failing specs.
