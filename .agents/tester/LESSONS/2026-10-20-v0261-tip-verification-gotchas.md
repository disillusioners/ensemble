1. **A pinned-sha brief goes stale in minutes on this repo — every lane must re-derive the tip.** The brief pinned the build tree `a4f28c26b`; `origin/latest` advanced to `efee25a27` (3 docs-only commits) *while the lanes were being dispatched*, and **four** lanes independently hit it (W-C, L4, L4b, L3). Never hard-stop on a stale assertion when the equivalence is one command away.
2. **`env -i` allowlist boots need `SYSTEM_ENCRYPTION_KEY`, or the ari-tools P3 substrate looks broken.** A boot-smoke round with the key scrubbed produced `[LiveViews] passcode substrate init failed … ViewPasscodeCipherUnavailable` — the feature's passcode substrate appears dead when the *harness* withheld the key. With the key present the shipped binary logs `passcode substrate ready: strike_ceiling=10 grant_ttl=86400s rate_limit=5/5-per-min`. Rule: when building an allowlist env for a binary that touches Fernet, either include `SYSTEM_ENCRYPTION_KEY` or explicitly assert which substrate you expect to be unavailable — and disclose which one you did.
