## Gotchas discovered (durable)

1. **`tests/integration/` files may carry NO `integration` marker.** `test_maintenancer_spawn_resolves_tools.py` (13 tests) is path-convention-only — `-m integration` silently deselected 13/22 of the triple-pin pack while the sibling file's 9 marker-carrying tests ran green. A "0 collected" retry trigger is insufficient; fire the no-marker fallback whenever a REQUIRED pin (e.g. the septet assert) sits in a deselected test. Filed as improvement note to `test-pack-execution` skill (retry on partial deselect ≥50%, not just 0-collected).
2. **Actual secrets tool names are FLAT snake_case** — `secret_generate_ssh_keypair`, `secret_generate_api_token`, `secret_store`, `secret_list`, `secret_read_public`, `secret_retire` — NOT plan §5.2's dotted `secrets.*` (provisional). Registry, registration tests, and frozen-name discovery agree on flat. When dispatching probes/asserts, derive names from `daemon/tools/secrets_tools.py`, not from the plan doc.
3. **Ambient shell of ensemble-VM workers carries LIVE `POSTGRES_*` (ensemble_prod @10.44.0.2) + live `SYSTEM_ENCRYPTION_KEY`.** Every pack/probe ran under `env -u SSL_CERT_FILE -u SSL_CERT_DIR -u POSTGRES_* -u DATABASE_URL -u PG*` (+ `-u SYSTEM_ENCRYPTION_KEY` where the no-key path is under test) with an in-script fence assertion. The secrets PG integration fixture reads `PG_TEST_*` (not `POSTGRES_*`) and self-provisions scratch DBs — point `PG_TEST_USER/MAINT_DB` at your OWN `sudo -u postgres` throwaway role/db; do not assume the default `ensemble`/`ensemble_dev` role exists or is yours.
4. **Marker regex duality**: repo `ENS_SECRET_MARKER_RE` (secret_service.py:161-173) is strictly TIGHTER than the commission-frozen `^__ENS_SECRET__[0-9a-f-]{36}__$`. Minted markers satisfy both — probe both, report divergence if any.
5. **Seam-mirror pins vs real boot**: dev's 4 boot-tolerance pins are honest unit mirrors (class docstring says so explicitly). The reviewer flag was closed by a REAL `InstanceManager` full-boot probe on PG scratch (no-key → `is_available=False`, typed `SecretCipherUnavailable` fail-closed) — and durably by commit `f2b1e0537`. Pattern: when pins mirror a heavy seam, the verification probe should drive the seam itself once, then leave a pin.
6. **Parallel waves advance HEAD**: 3 verification workers committed test-code mid-wave (43a1a4528, f2b1e0537) — every subsequent worker saw "HEAD drift" vs the dispatch SHA and flagged it. Benign for test-only commits; instruct workers that test-only advance is expected (they handled it correctly).
7. **Quality-analysis worker stalled 1h16m with zero messages** (read-only code-inspection task). Terminated + single replacement delivered in ~18 tool calls. Lesson: budget-box open-ended analysis tasks explicitly ("~10 min; mark PARTIAL and move on").
8. **Probe false-positive discipline works**: probe-ac run-1 flagged its own injected actor string as an unclassified leak candidate; verbatim investigation + clean re-run + full disclosure turned it into evidence strength, not noise. Keep structural scans with explicit self-input whitelisting.
9. **Engine-builder env priority (F-1 root cause)**: `daemon/repositories/factory.py:256-260` reads POSTGRES_HOST/PORT/DB/USER/PASSWORD from `os.environ` WITH PRIORITY OVER the passed PostgresConfig; `DATABASE_URL`/`DATABASE_URL_POSTGRES` are NOT read there. ANY test that constructs a real manager/engine must fence IN-TEST (`monkeypatch.delenv` the 5 vars BEFORE construction + assert resolved-db == fixture scratch) — invoker-level `env -u` is not durable safety. Fence-proof pattern: inert poison (closed port 59999 / fake db name) × {fenced → PASS, fence-disabled → FAIL Connection-refused}; NEVER use live values as poison.
10. **Reviewer label authority**: when commission-prompt numbering and committed docstrings diverge (4a/4b here), the committed docstrings are authoritative — verify the artifact, don't trust the prompt.
