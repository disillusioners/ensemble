```python
    "status", "started_at", "completed_at", "result_summary",
    "error_message", "cancelled_at", "failed_at",

```
Keep the caller signatures intact (they still pass these kwargs; they're just ignored). This is the least invasive fix. NOTE: `failed_at` is special — see B5.

### B5. `failed_at` — the LIVE retry marker
`failed_at` is **NOT a redundant column** in the current design — it's the live retry marker that `job_retry_engine.py` reads to distinguish a FAILED-path `done` row (retryable) from COMPLETED/CANCELLED `done` rows (terminal). See `repository.py:942, 952`, `job_retry_engine.py:175, 279`, `job_queue_service.py:1068`.

**However**, `failed_at` WAS removed from the JobItem model in Phase B (it's one of the 7). The plan (line 271) explicitly lists `failed_at` for removal, with the rationale (line 275): *"move_to_dlq already snapshots error_message/retry_count/failed_at into DeadLetterItem (Phase 4 must complete first)"*.

**Problem:** The retry engine's `failed_at is None` check (`job_retry_engine.py:175, 279`) and `job_queue_service.py:1068` will break because `job.failed_at` raises AttributeError on the new model. But the plan says to drop it.

**This is a genuine conflict.** The plan assumed Phase 4 would have migrated the retry engine to use a different marker. It didn't.

**Decision needed from orchestrator (DO NOT fix autonomously):**
- Option (i): Re-add `failed_at` to the JobItem model (deviate from plan, keep retry engine working). **Recommended** — it's one column, low cost, unblocks everything.
- Option (ii): Migrate the retry engine to use a different marker now (e.g. a new `was_failed` bool, or derive from Instance status). Larger scope.

If option (i): add `failed_at: str | None = Field(default=None)` back to JobItem, keep all read/write sites as-is, and note this as a deviation from the plan for a future batch.

## transition-state issues

### B15. `job_recovery_service.py:162-163` — PAUSED path
```python
from_status=JobStatus.PROCESSING.value,  # maps to 'active'
to_status=JobStatus.PAUSED.value,        # maps to 'active'
```
Maps to `(active → active)` which is NOT in VALID_TRANSITIONS. Pause is an Instance concern now.
**Fix:** This path should be removed or converted to a no-op (staying ACTIVE). The validator should allow same-state transitions as no-ops. **Add `(X, X) for all X` as implicitly valid** OR make the recovery service skip the transition call for pause.

### B16. `job_feedback_observer.py:1138-1139` — orphan-race re-arm
```python
from_status=JobStatus.COMPLETED.value,  # maps to 'done'
to_status=JobStatus.PROCESSING.value,   # maps to 'active'
```
Maps to `(done → active)` — NOT in VALID_TRANSITIONS. This is the legitimate re-arm after late child register.
**Fix:** Add `(done, active)` to VALID_TRANSITIONS as the "rearm_after_complete" transition. This is a real, necessary path.
