## DETAIL CARDS (by commission target)

### Card 1 — Message-arrival path (EV-20..EV-24)
Full hop chain: adapter (`base.py:147-150` `_on_message`) → `SourceRegistry._handle_message` (`registry.py:1008`) → dedup `check_and_mark_processed` (`:1032`, table `processed_external_messages`, `persistence.py:260`) → `InstanceMapper.get_or_create_instance` (`:1123`) → **live RAM injection** `set_injection` (`:1256`) when text-only + live graph, **else durable** `enqueue_message_job` (`:1318`). Per-user locks are **outbound-only** (`dispatcher.py:810-835`); inbound has none. Telegram acks offset after success (`:747`) → at-least-once. Busy-guard on the agent/API path = `has_live_graph_task` verifier routing graphless targets to durable enqueue (`messages.py:534`, `registry.py:1216`) — a router, not a rejection. FIFO via `queue_type='fifo'` + `concurrency_limit` 1-20 (`job_queue/models.py:194-213`); "queued" is a status flag computed at `:3542`, never a drop.
**Trigger-feasibility:** arrival is already an event; the depth-increment moment is EV-24's enqueue — ideal hook point, fires nothing today. Adapter trigger models are mixed poll/push (EV-21) — a central engine must not assume push.

### Card 2 — Instance terminalization + the KNOWN DEFECT (EV-01..EV-04, EV-09; GAP-02/03)
Four distinct fire paths, three key shapes:
- **Task-keyed** `emit_terminal` (`dependency_bus.py:667`): matches `source_task_id`; correct for single-turn children.
- **Pair-keyed corrective** `emit_terminal_for_child_instance(parent_instance_id, child_instance_id)` (`dependency_bus.py:885`, docstring `:907-917`): matches `(target_instance_id, metadata.child_id)`; callers pass `parent_instance_id = instance.parent_id` — the **structural parent** (`child_reports.py:6256` for COMPLETED; `error_reporting.py:765` for ERROR/FAILED).
- **Child-keyed target-agnostic** `fire_for_terminated_target(target_instance_id)` (`dependency_bus.py:1373`, docstring `:1405-1410`: matching "by `follow_up_payload.metadata.child_id` … NOT by `source_task_id`") — fires ALL pending watchers waiting on the instance regardless of who armed them. **TERMINATED-only**, called from the terminate path (`instance_lifecycle.py:3091` → `_cancel_bus_watchers_for:312`).

**DEFECT (confirmed by direct read, critical note eca98397d):** the nudge-armed watcher (EV-09, minted at `instance_ops.py:700-730` with `target_instance_id = NUDGER`, `metadata.kind="nudge_complete"`, `metadata.child_id=worker`) is deliberately out-of-tree (the normal child-watcher helper tree-guards, `tools/instance.py:1258-1261`; the nudge helper `instance_ops.py:580-600` exists precisely to bypass that). On COMPLETED/ERROR/FAILED only task-keyed + structural-parent-pair-keyed emits run → **a watcher whose target ≠ structural parent can NEVER fire except via TERMINATED.** Sibling defect on ERROR/FAILED (`error_reporting.py:765` — same pair shape). Observer-side asymmetry compounds it: held `mission_terminal` re-fire gate is `{TERMINATED, FAILED}` only (`job_feedback_observer.py:1116-1125`); COMPLETED held rows depend on the `_finalize_job` outbox.
Exactly-once everywhere via guarded `transition_state` (`WHERE state='PENDING'`, rowcount==0 → skip, `dependency_bus.py:835-849`). Pair-emit stamps `enqueued_at` WITHOUT enqueueing a FollowUp (`dependency_bus.py:1108-1118`) — gate-clear only, content arrives via PROCESS_REPORT (GAP-07).
*Post-read closure: at v0.31.22 the S1 target-agnostic child-keyed fire (`fire_for_terminal_child`, `dependency_bus.py:1921`) landed and is wired on COMPLETED + ERROR lanes — this card remains code-truth at HEAD `bf4bfde6e`; see § v0.31.22 corrections.*
**Trigger-feasibility:** the bus is the strongest terminalization signal (child_id + outcome in payload), but an engine trigger on "instance terminalized" needs a target-agnostic child-keyed fire on ALL terminal statuses — today only TERMINATED has it; the discovery helper is the missing plumbing.

## Cross-cutting trigger-feasibility summary (for the architecture disc)

- **Best existing substrates for engine triggers:** `EventBus.create_event` (durable + global-subscriber proof via JobFeedbackObserver), `dependency_watchers`/`[JOB_EVENT]` (exactly-once CAS + outcome payloads), `report_injections` + `mission_commissions` state tables (durable obligations + stamps), attestation ledger (durable epochs), and — on latest — `room_messages` kinds.

- **Failure-posture decision required per event class:** FAIL-MISS (RDRS/commissions) vs fail-OPEN (attestation ledger, room nudge, report-integrity guard) vs drop-counted (RAM guard) — the engine must choose and label, not inherit implicitly.
