## D-1 — Husk detector: NEW detector #7 `never-dispatched-husk`, single-homed evidence expression, 24h constant (AMENDED by arch §1)

**What.** Add a SEVENTH detector to `_build_health_report` (`daemon/tools/instance_read.py:1055-1300`), appended LAST (pure addition; existing indices stable). **Why.** The husk class is invisible to all six existing detectors and all four write-side lanes BY CONSTRUCTION (GT-1; research §A.2 per-healer early-exit table; read-side §11.1) — there is nothing to compose. 24h sits 43× above the 2h sweep bounds, 4× above the 6h horizon, 1440× above the 60s race guard (read-side §3.2 ladder), fires on the 12-day and 16-day targets with 12×/16× margins, and matches the daily operator cadence. **The premise correction (arch §1.1):** reusing `filter_never_dispatched_ids` as the E1/E2 probe would silently false-negative any non-idle / version>1 evidence-free row, and the method is bound by the lockstep pin to the completion-gate domain — the twin `ChildReportsService._ghost_child_filter` (`child_reports.py:2864-2901`) carries the identical four-conjunct predicate, and `tests/unit/test_pause_never_dispatched_ghosts.py` pins BOTH sides INCLUDING the blindness (`test_running_status_never_matches`, `:140-153`): a future tightening of the ghost conjuncts would silently re-scope husk detection, and satisfying the husk need by editing them would break pause-cascade skip semantics. The single-homed expression factory satisfies "no third fork" structurally: the patch introduces ZERO new copies of the evidence predicate (D-19). Note also the 2h/8h fake-fleet trap (`test_instance_ops_behaviour.py:158-165` holds evidence-free rows aged 2h/8h): the 24h constant keeps detector #7 out of those pins — any future threshold < 8h silently starts flagging them.

**Forecloses.** A `husk_minutes` tool argument (schema churn + refusal-token surface); threshold derivation from `stale_minutes` (a turn-in-flight judgement ≠ an evidence judgement); reusing `filter_never_dispatched_ids` as the husk probe (premise-corrected); a local re-implementation of the no-task/no-message EXISTS legs; touching `child_reports._ghost_child_filter` in this patch (routed clean-up, D-19); a census `husk` boolean (the census row shape is untouched — D-2 non-goal); tuning the threshold per-call at operator request later (the house pattern for that is a config field, a separate change).

**Forecloses.** Option A (paging the summary over the full fleet — round trips scale with fleet size and the census stays window-shaped); `GROUPING SETS` (SQLite incompatibility); hand-adding an `idle` key; a per-callsite copy of the KB predicate (closed by the shared `_kb_filter`); changing `_census_row`'s shape (explicit non-goal — a husk still renders `stale: false` in the CENSUS; the class is surfaced by `instance_health`, the tool whose stated job is "what looks wedged" `:903-906`); a `never_active` census field (a reasonable FOLLOW-UP but a separate decision with its own pin if the commission wants it).

## D-3 — Scan: Option A offset-window loop; honest `truncated` on all three flag sites (AMENDED by arch §3.2/§4)

**What.** `FLEET_SCAN_MAX_WINDOWS = 20` (new constant; ≤ 20 000 rows/report) beside `FLEET_SCAN_LIMIT = 1000` (now the WINDOW size). `_build_health_report` loops `manager.list_instances(limit=FLEET_SCAN_LIMIT, offset=i*FLEET_SCAN_LIMIT)` with the CORRECTED loop shape (arch §3.2):
- capture `total` from the **FIRST window only, never reassign**;
- accumulate into a **DICT keyed by `instance_id`** (dedupe — a row shifted across a window boundary is read twice, not double-counted);
- break **ONLY** on `not rows` (end-of-set) or the window cap — **NEVER** on `len >= total` (a concurrent insert lands at the FRONT of `created_at DESC`, shifts every later row down, makes `len` reach `total` early, and silently skips the tail);
- `scan_truncated = (distinct_read < total_first) OR (cap fired without an end-of-set window)`;
- add `scan_stop_reason ∈ {end_of_set, window_cap, time_budget}` so the flag is actionable (otherwise "fleet > 20 windows" and "cut for time" collapse into one boolean);
- `FLEET_SCAN_TIME_BUDGET_SECONDS = 10` (new constant, D-20) checked BEFORE each window; on exhaustion break with `scan_truncated=True` + `scan_stop_reason="time_budget"`;
- **STREAM per window** — evaluate the detectors incrementally / keep only candidate-relevant fields; do NOT materialize the fleet (`windows.extend(rows)` ≈ 20k dicts + child lists ≈ 20–40 MB @20k — the "memory bounded per window" claim was FALSE as originally written, arch §4).

`instance_list.truncated` becomes `bool(total_matching > applied_offset + len(census))` (total = all matching rows, not the tail; an empty page ⇒ True ONLY when `total > offset` — the EXHAUSTED case `len(rows)==0 ∧ total ≤ offset` reads `false`; iteration-003 remedy 4) — **exact for the `:543` site only AFTER F12** (a status filter silently dropped at the lifecycle→repo seam makes the formula meaningless for filtered calls — arch §3.1); `fleet_capacity_summary.scan_truncated` becomes `false` by construction after D-2. Add ONE disclosure sentence to `instance_health._full_doc_` (`:903-940`): paging is OFFSET over a live fleet; rows created or pinned mid-scan may be counted twice or missed; `scan_truncated=true` means the oldest rows may not be covered.

**Why.** Option A ships no new repository/manager surface (right blast radius for a defect patch), and its truncation semantics fall out of the loop bound onto the existing flag. Determinism is guaranteed: the flat ORDER BY ends `instance_id ASC` (`repository.py:1158-1174`) so offset paging neither skips nor duplicates. A partial cover starves the OLDEST rows — exactly the day-scale husks — so `scan_truncated=True` must be read as "the oldest rows are not covered" and must stay LOUD. **F3 hard-depends on F4**: the two targets sit in the oldest 730 of 1730 rows, outside the current window (read-side §3.5 "Critically"); the F3×F4 pin uses a fleet fixture larger than the window so the coupling cannot silently regress. Keyset pagination is rejected because it would need a new repository sort surface, and a snapshot-bounded query is impossible through the manager API (every `list_instances` opens its own session).

**Forecloses.** Option B repo-level full-fleet method (new manager surface + the whole fleet materialized as dicts); keyset pagination (new repo sort surface); neutralizing the pinned tier; computing `truncated` from the repository's constant `False` (`repository.py:1176-1177` — left untouched; the tool computes); `len >= total` as a break condition (the concurrent-write drift bug, arch §3.2); whole-fleet materialization (the corrected shape streams).
