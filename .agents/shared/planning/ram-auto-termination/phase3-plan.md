## Objective

Wire the Phase 2 guard into the **bash tool** so that a bash execution whose
process tree exceeds the configured ceiling (**3 GiB / 3 072 MiB default**) is
terminated tree-wide and the calling agent receives a typed `ram_limit_exceeded`
envelope carrying the **deciding** value and the honest-peak bound. Every bash
execution below the ceiling must behave **exactly** as it does today.

**This lane goes first by ruling** (arch §8 item 2): the Oct-30 ballooners were bash
`python3` commands.

## The four registries — ambiguity RESOLVED

Rev 1 said "unregister the registry" without saying which. The bash lane touches
**four** registries. Resolved explicitly; the RAM arm's behaviour on each is fixed:

| Registry | Kind | What the RAM arm does | Why |
|---|---|---|---|
| **Guard registry** (`ram_guard.guard`) | RAM, keyed by `tracking_id` | **Release** the entry (state → `RELEASED`) — **after** the verdict is published (§4.3.1) | It is the guard's own bookkeeping; releasing it stops the watch |
| `pid_registry` (`daemon/services/resource_monitor/pid_registry.py`) | RAM, spawn-fed | `mark_exit(exit_kind="ram_killed", peak_rss_kb=<bytes→KB>)` — **one-shot**, the live row is deleted at `:423`; **runs only after the verdict is published** | The exit-kind vocabulary is the process-outcome taxonomy; `ram_killed` **must** be added to `VALID_EXIT_KINDS` (`:127-138`) or `mark_exit` **raises** `ValueError` (`:409-413`) |
| `BashProcessRegistry` (`daemon/tools/bash.py`) | RAM, `instance_id → (pid, pgid)` | **Unregister**, mirroring the timeout arm (`:1073`) — **after** the verdict is published | It is the killpg-tracking map; a stale entry is a kill target for a later sweep |
| `bash_spawn_registry` (`daemon/repositories/bash_spawn/models.py`) | **durable** | **Leave the row OPEN** | The reaper's env-stamp escapee sweep **only sweeps open rows**; closing the row on a RAM kill **silently disarms the escapee net**. The row closes later via the existing `ram-tier-dedup` path at terminal cleanup (arch DQ5) |

## Exit Criterion

- A bash execution that exceeds the injected ceiling is **terminated tree-wide** and
  the agent receives the envelope whose **deciding value** is `>= limit_bytes`.
- The envelope carries **both** `limit_bytes` (configured) and
  `rearm_threshold_bytes` (enforced trigger) and the **enforced-threshold clause**
  in the message.
- The **publication ordering** is pinned by a recording fake: the verdict survives
  the success arm's one-shot `mark_exit`.
- The **bounded wait** (**1270 ms**, `async`, derived from `RAM_GUARD_PENDING_MAX`) is
  implemented and observable.
- The durable `bash_spawn_registry` row is **OPEN** after a RAM kill (asserted).
- The lane exit is a **NOTIFICATION**: the guard entry is released on the six bash
  exit paths **only when the watch is finished** (`group_member_count == 0`), and a
  **claimed** record's release is **deferred to the lane** — asserted per path, with
  the **sub-leg that the entry SURVIVES the success path while a group member is
  live**.
- The claim-token race is deterministic; the coincidence flags are correct.
- An under-limit bash execution is **byte-identical** to the base-commit behavior
  (output, exit code, `exit_kind`, `peak_rss_kb` semantics, registry state).
- The kill-switch OFF path is a **complete no-op** — no measurement, no registration,
  no writes, no child-env stamp.
- The bash-lane test pack passes with **net-new reds = 0** against the base commit.
