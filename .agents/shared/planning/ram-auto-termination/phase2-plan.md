## Objective

Build the `daemon/services/ram_guard/` substrate that answers one question — "how
much RAM is this process tree using **right now**, and what is the **deciding**
value?" — with **no tool wiring at all**, plus the envelope producer, the event
**hook**, the guard thread, and the kill ladder that the bash lane (Phase 3) and
the proc lane (Phase 4) both consume.

**Boundary (discharged from the approver's sweep note):** this phase's objective is
*"no tool wiring at all"*. Two rev-2 tasks straddled that line and are corrected
here — **T9** now owns the substrate-side unit discipline only (the bash-lane
bytes→KB conversion is Phase 3 T10), and **T15** now owns the guard-side release
API + the liveness sweep only (the enumeration of the six bash exit paths is
Phase 3 T8). The **DQ6 consumer-gate artifact** lives here as a **pins-only**
artifact (no tool wiring) and is referenced, never re-derived, downstream.

**Rev 2 said "summed RSS against a ceiling". That is falsified** (arch §1.1 P7,
DQ1): summed RSS over-counts a fork-without-exec tree by ≈ the member count
(**measured 8.9×** on a 9-member tree). The substrate implements the **ruled
hybrid**: a cheap RSS trigger per tick and a **mandatory one-shot PSS confirm**
at breach that is the **deciding** value — with the **bounded** over-count
re-arm (§4.1a).

## Module decomposition (arch doc §7 — frozen)

```
daemon/services/ram_guard/
  __init__.py     facade: get_ram_guard(), register/read_verdict/release
  tree_reader.py  scan_proc / resolve_members / read_tree_rss / read_tree_pss / exceeds  (pure, injectable)
  verdict.py      SpawnRecord, PeakRecord, breach predicate, OVERCOUNTED re-arm (§4.1a)
  ladder.py       ram_kill_ladder + the P0–P7 pre-kill predicates + the P8 post-kill probe
  guard.py        the thread + registry + GuardCounters + liveness sweep + the emitter call site
  errors.py       format_ram_envelope (one producer, two surfaces) + build_ram_event_payload (the allow-list)
  events.py       RamBreachEmitter type alias ONLY (stdlib typing; no emitter implementation here)
daemon/services/ram_guard_events.py   OUTSIDE the package: the bus-backed emitter impl + the loop bridge
```

**Import direction (arch §7, AMENDED — the literal replacement for the frozen
sentence):**

> Import direction: `tools/* → ram_guard` only; `ram_guard → stdlib` only. `ram_guard` imports NOTHING from `daemon/` — no `tools/*`, no `resource_monitor`, no `repositories`, no `event_bus`, no `main_loop_bridge`, no `bash_spawn_reaper`. The event dependency is satisfied by an INJECTED callable (`RamBreachEmitter`), whose implementation lives OUTSIDE the package (`daemon/services/ram_guard_events.py`) and is wired at the composition root (the FastAPI lifespan).

The stat parse is reimplemented injectably because `list_group_members` hardcodes
`/proc` and is per-spawn-priced.
