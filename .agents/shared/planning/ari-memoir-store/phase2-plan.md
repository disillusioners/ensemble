# Phase 2 — Repository + hybrid retrieval service

**Depends on:** P1. **Flags consumed:** #6 (named writers), #10 (timeline semantics + the `since`/`until` name binding), #11 (recall budget), #1 (pin admission), #5 (write bounds).

## 1. Objective

The data-access layer with NO general-purpose update (mutability partition enforced structurally), and the hybrid retrieval service implementing design §7 with the **adjudicated RRF arithmetic**: candidate pool 100 per ranker, 1-based local competition ranks, absent-ranker ⇒ absent term (not zero), a total final comparator, the NULL-safe idle basis, and the corrected PG lexical SQL.

## 2. Decisions

| ID | Decision | Rationale (verified anchors) | Rejected alternatives |
|----|----------|------------------------------|------------------------|
| D2.1 | Repository public surface is a CLOSED set: `insert_episode`, `mark_recalled`, `set_pin`, `clear_pin`, `store_embedding`, `record_embedding_attempt`, `mark_superseded` (defined, uncalled in v1), `get_pending_embeddings`, `fetch_keepsakes`, `fetch_latest`, `get_approved_persona`, `seed_persona_if_absent`, `lexical_rank`, `timeline_window`, `count_pins`/`keepsake_zone_tokens` | flag #6 partition: one named writer per mutable family; NO body/identity UPDATE exists anywhere | a generic `update_episode(**cols)` (the exact hazard the flag names) |
| D2.2 | Lexical ranker is driver-aware behind ONE interface. **PG:** `SELECT id, ts_rank_cd(tsv, plainto_tsquery('english', :q)) AS score FROM memoir_episodes WHERE tsv @@ plainto_tsquery('english', :q) ORDER BY score DESC LIMIT :cand` — **`tsvector` is the FIRST argument**; PG has no `ts_rank_cd(tsquery, tsvector)` overload (architect-verified against a live PG 16.15 catalogue; the reversed form raises `psycopg.errors.UndefinedFunction`). **SQLite/dev:** the Python BM25 house helper (`skill_search_service._bm25_score`, the `critical_notes_selector` precedent `:12-20`) over fetched candidates | the reversed argument order raises on the **operative driver only** — the SQLite fallback stays green, so the defect would surface in production. Stock PG has no BM25; **ts_rank_cd** is the closest stock approximation (coverage-density ≈ TF + proximity), and RRF consumes only **ordinal** ranks, so the absolute score family is immaterial to fusion | the reversed SQL (does not exist in PG); literal "BM25" claims on PG (dishonest); pgvector/paradedb extensions (R4) |
| D2.3 | Semantic ranker: embed the QUERY once per call, then cosine in Python over candidates `WHERE embedding IS NOT NULL AND embedding_model = :model AND embedding_dims = :dims` — the dims predicate is mandatory, not optional | `_cosine_similarity` shape at `daemon/services/critical_notes_selector.py:230-238` (mirrors `SkillEmbeddingService.cosine_similarity` `:634`); the house cosine **silently zips to the shorter side** (`skill_embedding_service.py:634-659`), so a same-model-id/different-dims vector would score as confident nonsense | SQL-side cosine (none exists for JSONB without extensions); model-id-only filtering (dims drift stays silent) |
| D2.4 | **Candidate pool: 100 per ranker** (`MEMOIR_RANK_CANDIDATES`, a module constant). The two pools are **independent**; their **union** is the candidate set | recall returns k ≤ 20; a rank-1 hit contributes 1/61 ≈ 0.0164 and a rank-100 hit 1/160 ≈ 0.00625 ⇒ 100 candidates capture ≥96 % of the achievable RRF mass while keeping the PG scan bounded | an unbounded candidate scan (unbounded cost at corpus growth); one shared pool (the two rankers must see the same universe independently) |
| D2.5 | **Rank convention: 1-based, per-ranker, local.** Within a ranker, rows sort by `(score DESC, id ASC)` and receive **competition ranks** (equal scores share a rank; the next distinct score skips: 1, 2, 2, 4). A row **absent** from a ranker's list contributes **NO term** for that ranker — "absent" means the term is **missing**, not that the row scores zero | design §7's degradation sentence ("neither dropped nor zero-scored") governs the prose; competition ranking is the standard convention for tied scores | dense ranking (changes the RRF mass of ties); global ranks across rankers (the rankers have different score families — their ranks are only comparable per-ranker); zero-scoring absent rows (contradicts the design's degradation sentence) |
| D2.6 | **Fusion:** `score = Σ_r 1/(RRF_K + rank_r)` with `RRF_K = 60` — a **module constant, not a config knob** (a fusion constant, not a budget; the briefing's budget model governs rendered-token budgets only). Terms are summed in a **fixed ranker order** (lexical, then semantic) so float addition is deterministic; **no rounding** (rounding manufactures ties and breaks monotonicity) | design §7 binds k=60; the flag-#3 model governs budgets only | a configurable k (a constant in disguise); rounding the fused score (manufactures ties, breaks monotonicity); unordered summation (float addition is order-sensitive) |
| D2.7 | **Final comparator is TOTAL:** `(-prior_multiplied_score DESC, importance DESC, event_at DESC, id ASC)`. The prior **multiplies** the fused score for non-keepsakes (keepsake multiplier = **1.0**, never decayed), so it **may** reorder rows that importance had separated — intended, and importance is **re-applied after** the multiplication. Idle basis = `now − coalesce(last_accessed_at, created_at)` | design §7 binds the prior's form and the keepsake exemption; the design's `idle = now − last_accessed_at` is **NULL-unsafe** for a never-recalled row (coalesce to `created_at`); `id ASC` makes pagination stable | a comparator that stops at importance (not total ⇒ ties are non-deterministic); `idle = now − last_accessed_at` with NULL (never-recalled rows break the prior) |
| D2.8 | Stats discipline: `mark_recalled(ids, now)` — ONE column-targeted UPDATE `SET last_accessed_at=now, access_count=access_count+1 WHERE id IN (…)`, called ONLY by the recall service, and marking **exactly the ids in the shipped projection** (post-clamp, post-ranked-drop). Episodes dropped for budget are **not** returned and **must not** be marked; the marked-id list and the rendered-id list are asserted by **equality**, not containment | design §7 "the only path that updates"; DD-12 "a briefing is not an act of attention"; the metrics-read M-1 doctrine (measure the SHIPPED bytes, never raw rows) | counting timeline reads (read-path write amplification); marking the pre-clamp candidate set (episodes the agent never saw) |
| D2.9 | Timeline = filter-then-rank with the window parameters named **`since`** / **`until`**: inclusive ISO-8601 bounds on `event_at` (UTC-normalised; `since ≤ until` validated by the tool), filtered by an indexed range scan; `q` present → the **lexical-only** ranker (D2.2) over that set; `q` absent → `event_at DESC`. **NO** cosine, **NO** RRF, **NO** recency prior, **NO** keepsake priority; timeline writes **NO** stats | design §5.4 names the window parameters `from`/`to` — **Python keywords** — so the blessed signature is unimplementable literally; the rename is a **name binding, not a behaviour change** (recorded as a surgical supersession). The recency prior would actively distort a historical window ("what was true in March" must not be demoted for being March) | timeline-as-second-recall (two tools, two expectations); keeping `from`/`to` (unimplementable as Python parameter names) |
| D2.10 | Recall budget: `k` default **5**, hard max **20** (out-of-range ⇒ typed refusal, not a silent clamp); per-episode body clamp **1,200 tokens** with the house truncation marker `[…body truncated, N chars total]`; total envelope **≤6,000 tokens** with **ranked-drop** (the head results stay whole) + a count/hint footer; enforced on the **shipped projection** with a final re-check before return | harmonized with the briefing estimator (`estimate_tokens`, `daemon/loader.py:1027`); the metrics-read M-1 doctrine (shipped projection, never raw rows — the named regression class) | uniform squeeze across episodes (destroys the head results); silent clamping of `k` (the agent cannot tell its request was reduced) |
| D2.11 | The recall footer additionally carries the **embedding-identity disclosure**: `active_model=<id>` and `embedding_excluded=<N>` (candidates skipped for identity/dims mismatch), with a partial-recall note when N > 0 | this is the closure of flag #7's stated fear ("semantic recall silently misses N episodes") — the per-tick line is an OPERATOR surface; the agent surface is where the loss is observable | leaving the drift invisible to the agent (a silent partial recall is indistinguishable from a complete one) |
| D2.12 | Pin admission: `set_pin` REJECTS when `count_pins(agent) >= 12` OR `keepsake_zone_tokens(existing) + est(candidate_render) > 4000`; the error names the binding constraint and the current pins (id/title/pinned_by/tokens) | the reject-don't-evict shape of `daemon/tools/critical_notes.py` (`_MAX_ENTRIES` `:70`, cap check + candidate naming `:537-546`); the count cap alone does not make the stable zone's "never truncated" true (12 × a legal ~2,800-token body ≫ the 4,000-token zone) | count-only cap (a long body blows the zone); evicting an older pin to make room (DD-3 — a keepsake that can be silently evicted is not a keepsake) |
| D2.13 | Write bounds (hygiene, not normalization): body ≤ ~2,000 words (house request-length family; hard char cap ~16,000 chars with typed refusal), title ≤200 chars, stars ≤16 entries × ≤120 chars each (post-trim), importance validated 1–10, `event_at` ISO-parsed else refusal | request-shape bounds change no string's content — they are not the star normalization the v2 star-table will do | silent clamping (refusals teach; clamps corrupt) |
| D2.14 | **Write-path purity (DD-20):** `daemon/tools/memoir.py` contains **zero** references to the embedder, to `client.embeddings`, or to `store_embedding`; the write body performs **exactly one** `insert_episode`; no `await` of the embedding worker appears in the tool module; the embedder is reachable **only** from the worker module | DD-20 ("memory capture must not be a latency tax on conversation") needs an ASSERTABLE pin — without one, an implementer can inline the embedder with nothing to stop it (mutation leg: an inline `await embed(...)` in the write body ⇒ the pin goes RED) | a comment-only rule (unenforceable) |
| D2.15 | The ONE INSERT's **exact column set**: `id, agent_id, title, body, created_at, event_at, importance, stars, is_keepsake, pinned_by, pinned_reason, pinned_at, embedding=NULL, embedding_model=NULL, embedding_dims=NULL, embedded_at=NULL, embedding_attempts=0, embedding_error=NULL, last_accessed_at=NULL, access_count=0, superseded_by=NULL`. `tsv` is DB-generated and is **not** in the INSERT. `keepsake=true` needs **no second statement** — the pin columns are part of the same row, and the pin-admission SELECTs (`count_pins`, `keepsake_zone_tokens`) are **reads** that **PINNED-PRECEDE the single INSERT** (W3: an order inversion would write the 13th keepsake and THEN refuse it — cap exceeded ⇒ the 4,000-token zone bound blown ⇒ DR-1's 24,000-char ceiling crossed ⇒ the agent told the write failed when it exists ⇒ P5 broken) | the write path is one INSERT and nothing else (DD-20); a column-list drift (e.g. forgetting `embedding_attempts=0`) silently breaks the worker's pending predicate | a second statement for the pin columns (two writes = two failure modes, and it would violate the one-INSERT purity pin) |
| D2.16 | The per-row embedding write-back is **one atomic column-targeted UPDATE** (`embedding`, `embedding_model`, `embedding_dims`, `embedded_at` set together) | a partial write leaves `embedding IS NULL AND embedded_at IS NULL` true ⇒ the row is re-embedded **forever**; the pending predicate and the write must be one statement | separate writes (infinite re-embed) |
| D2.17 | The service and repository SQL is **driver-agnostic**: no statement references `tsv` except the PG lexical ranker itself | the lane supports SQLite and PG; on SQLite there is no tsv and the lexical ranker is the Python BM25 helper | tsv-aware statements in shared code (breaks SQLite) |

## 4. Acceptance criteria

| ID | Criterion |
|----|-----------|
| AC1 | Repository surface test: exact method set; no general update; UPDATE statements column-targeted (mutation: add a body-touching UPDATE → pin RED) |
| AC2 | Ranker equivalence-of-interface: the same query on PG (real) and SQLite (Python BM25) both return ordinal-ranked candidate lists; PG uses the GIN index (EXPLAIN leg); **the PG leg proves the argument order** — `ts_rank_cd(tsv, plainto_tsquery('english', :q))` (mutation: swap the arguments ⇒ the PG leg fails with `UndefinedFunction` ⇒ RED) |
| AC3 | Fusion: synthetic corpus pin — the RRF math is exact (hand-computed fixture: candidate pool 100, competition ranks 1/2/2/4, absent-ranker rows carry NO term, `RRF_K=60`, fixed summation order, no rounding); the final comparator is total and stable; importance re-applies after the prior multiplication; the idle basis coalesces to `created_at` |
| AC4 | Timeline: `since`/`until` filter inclusively; q narrows lexically; keepsake and stale rows NOT prioritized/deprioritized; `mark_recalled` NOT called (byte-assert on stats); the parameter names are `since`/`until` (no `from`/`to` in the signature) |
| AC5 | Admission: 13th pin rejected (count); oversized pin rejected (budget) with names; 12 small pins accepted; unpin→re-pin works; keepsake-at-write reuses the same admission (fixture) |
| AC6 | Persona transitions: draft→pending_approval→approved ✓; draft→approved ✗ (refused); `approve()` with `auth_method != "session"` ⇒ `HumanLaneRequiredError` |
| AC7 | Write purity: the tool module references no embedder symbol; the write body performs exactly one `insert_episode`; the INSERT column list is pinned byte-wise (including `tsv` absent); the embedding write-back is one statement setting all four columns together; the marked-id list equals the rendered-id list (equality, not containment); **the admission reads (`count_pins`, `keepsake_zone_tokens`) PRECEDE the ONE `insert_episode`** (mutation leg: admission after the insert ⇒ RED) |
