# Phase 3 — Embedding worker

**Depends on:** P1 (P2's `store_embedding`/`get_pending_embeddings` contract can land in parallel; the worker consumes it). **Flags consumed:** #7 (whole phase), #13 (the knob gates the worker — read per tick).

## 1. Objective

The background async embedding compute: after `memoir_write` INSERT, lexical is live immediately (DB-side `tsv`) and the embedding lands when the worker reaches the row — never blocking the write (DD-20), degrading gracefully when the LLM lane is down (P3/DD-6), catching up after restart, and observable per tick. The worker is bounded in time, isolated in threads, honest about drift, and never dies on a bad tick.

## 2. Decisions

| ID | Decision | Rationale (verified anchors) | Rejected alternatives |
|----|----------|------------------------------|------------------------|
| D3.1 | Owner = dedicated lifespan asyncio task (`asyncio.create_task`, stored on `app.state.memoir_embedding_worker_task` — the naming precedent `daemon/api.py:2788` `app.state.readiness_refresher_task = readiness_task`), cancelled + awaited on shutdown (`:3585-3596` shape) | the house internal-loop family: readiness refresher (`api.py:2772-2777`, `:3585-3596`), bash-reconcile (`:940-975`) | job-queue dispatch (agent-work machinery; admission states/watchers = user-visible noise for an internal index loop); a generic sweep service (wrong shape: wants short-latency + catch-up) |
| D3.2 | Queue = `embedding IS NULL AND embedded_at IS NULL` (partial index from P1); boot catch-up = the first tick re-scans all NULLs — durability by construction | no side table, no outbox, no state to lose; restart-safe trivially | a pending-jobs table (durable but redundant — the NULL IS the state); a RAM queue (lost on restart) |
| D3.3 | Per tick: scan ≤ `embedding_batch_cap` (default 8) pending rows; embed `title + body` (title prepended, newline-joined — the critical-notes "summary+reference" shape); the client is the **existing** `openai` SDK against the existing LLM lane (the `skill_embedding_service` shape — `client.embeddings.create(model=embed_model, input=text)` at `daemon/services/skill_embedding_service.py:204`), sync client behind the dedicated executor (D3.5) | the existing lane (R4 — no new dependency, no new service); model/base/key from the shared `EMBEDDING_*` config family (`daemon/config.py:4374-4397`) | a new embedding client/dependency (R4 violation); an async client (no house precedent) |
| D3.4 | **The embed call MUST carry a request timeout**: client `httpx.Timeout(timeout=30.0, connect=5.0)`; per-call budget **30 s**; the tick's **total** embed budget **≤45 s** | the house client sets **no** timeout (`skill_embedding_service.py:196-205` sets only api_key/base_url/http_client) ⇒ the SDK default `httpx.Timeout(timeout=600, connect=5.0)` applies, and the failover `wall_clock_cap_s` fires only **between** attempts — a slow-drip lane would stall a tick for 10 minutes | the house client's default (600 s per call); a longer per-call timeout (the tick budget is the real bound) |
| D3.5 | **Dedicated executor, never the shared default:** module-level `ThreadPoolExecutor(max_workers=2, thread_name_prefix="memoir-embed")` (house precedent `daemon/services/db_offload.py:75,272`). **`asyncio.to_thread` for the embed is FORBIDDEN.** Embeds are **SEQUENTIAL** (batch cap 8 = 8 rows in sequence, not 8 concurrent calls) | the default executor is `min(32, cpu+4)` workers shared with ~1,351 `to_thread`/`run_in_executor` sites carrying LLM and compaction traffic (house rule `daemon/mcp/stdio_wrapper.py:123-126`, `daemon/mcp/warmup_pool.py:112-114`), and a cancelled `to_thread` does **not** free the worker — a 600 s stall would pin shared workers | `asyncio.to_thread` (pins a shared worker for the full timeout); a larger dedicated pool (sequential embeds already bound the tick at 45 s) |
| D3.6 | Write-back WITH identity: `store_embedding(id, vector, model, dims, now)` sets `embedding`/`embedding_model`/`embedding_dims`/`embedded_at` in **one atomic column-targeted UPDATE** and clears `embedding_error` | per-row model identity is DD-6; `critical_note_embeddings` `model`+`dims` columns precedent (`daemon/repositories/project/models.py:293-347`); a partial write leaves the pending predicate true ⇒ infinite re-embed | trusting the configured model name at read time (config drift would silently mix identities); multiple writes (infinite re-embed) |
| D3.7 | **Write-back failure COUNTS AS AN ATTEMPT:** `record_embedding_attempt(id, error)` is called on **any** per-row failure (embed **or** write-back); `embedding_attempts >= 5` ⇒ TERMINAL (lexical-only forever, reason preserved) | otherwise a successful embed whose DB write fails leaves `embedding IS NULL` and `attempts=0` ⇒ **infinite re-embed**, never terminal, never reported | counting only embed failures (the infinite-re-embed loop); a dead-letter table (redundant with the attempts column) |
| D3.8 | **Dimension mismatch is a per-row TERMINAL, not a silent zip:** the worker compares `len(vector)` against the configured dimensions (the `EMBEDDING_*` family, `daemon/config.py:4374-4397`); on mismatch it records a **terminal** error (`embedding_dimensions_mismatch: expected=1536 got=3072`) and stores **nothing** | the house cosine **silently zips to the shorter side** (`skill_embedding_service.py:634-659`) ⇒ a 3072-dim vector scored against a 1536-dim query returns confident nonsense; per-row `embedding_model` does **not** cover a same-model-id/different-dims case | storing the mismatched vector (silent nonsense rankings); trusting `embedding_model` alone (dims drift is uncovered) |
| D3.9 | **Error classification is explicit and reuses the HOUSE classifier** — `daemon/llm_error_classifier.py` (`is_retryable_status_code`, the transient-channel patterns) — not hand-rolled. **401/403 = permanent** ⇒ the row goes terminal **immediately** (no 5-attempt burn against a dead credential) **and** the tick counts as an all-fail tick ⇒ the lane-down latch engages on the **first** occurrence; other 4xx (not 408/429) = permanent per row; **429 / 408 / 5xx / connection errors = transient** (the house retryable set `RETRYABLE_STATUS_CODES` plus 408) | classification decides retry-vs-terminal; the house set already encodes the retryable families; the latch must engage at once on a dead credential | hand-rolled status handling (drifts from the house); treating 401/403 as transient (burns 5 attempts against a dead credential) |
| D3.10 | Lane-down latch: after 3 consecutive ALL-FAIL ticks, drop to slow mode (300 s ticks) until the first success; a partial-success tick does not latch. Latch engagement, terminal transitions, knob parks, dimension mismatches and write-back failures each get **their own greppable log line** | the known live-proxy defect class makes graceful lane-down a first-class state; P3 "the lane being down must degrade retrieval, never the write" | hammering a dead lane every 30 s; one undifferentiated log line (a mutation leg cannot assert honesty) |
| D3.11 | **Tick-line semantics are defined** so a mutation leg can assert honesty: `[MemoirEmbed] pending=N embedded=K errors=E terminal=M tick_ms=T slow_mode=bool` where **`E` = rows that failed THIS tick** and **`M` = the TOTAL terminal rows in the table** (not this tick's count) | an ambiguous counter cannot be pinned; operator and agent need different slices (per-tick failures vs the standing backlog) | an ambiguous "errors" counter (unpinnable); per-tick terminal count (the standing backlog becomes invisible) |
| D3.12 | The tick interval is **read per tick**, so an operator can slow the worker during an incident without a restart; the knob is **re-read every tick** — when it is OFF the worker **parks** (a log line, task stays alive) and **resumes** when the knob is ON again | AM-27: the knob is read at CALL time, not only at boot; "OFF ⇒ the task is never started" covers **boot only**. A parked task that resumes means re-enabling needs no restart | reading the knob only at boot (an operator's OFF/ON flip would need a daemon restart); killing the task on OFF (loses the catch-up cadence) |
| D3.13 | The loop body is wrapped `try/except Exception` **re-raising `CancelledError`**, so a failed tick does **not** kill the task; shutdown = cancel + await | the house contract (`daemon/api.py:4588-4592`: `except asyncio.CancelledError: raise` / `except Exception as e: logger.error("[Readiness] refresh cycle failed: …")`); shutdown shape `:3585-3596` | an unguarded loop body (one bad tick kills the worker for the daemon's lifetime) |
| D3.14 | **Driver-agnostic:** the scan/update SQL must not reference `tsv`; on SQLite there is no tsv and the lexical ranker is the Python BM25 helper; the embedding columns and their UPDATE are driver-neutral | the lane supports SQLite and PG | tsv-aware worker SQL (breaks SQLite) |
| D3.15 | **No automatic backfill ships in v1.** The operator requeue procedure (clear `embedding_attempts`/`embedding_error` for a row) is documented in the runbook; the agent-visible disclosure of drift is the recall footer's `active_model` / `embedding_excluded=N` (phase2's D2.11) | v1 ships no re-embedding pipeline (roadmap v3: "pgvector + re-embedding pipeline — IF scale demands"); an automatic backfill would be a scope addition with its own budget | an automatic backfill (unbudgeted lane spend, plus a re-embed policy the design does not have) |
| D3.16 | The worker module is the **only** place the embedder is reachable from | DD-20 write-path purity (phase2's D2.14): the tool module must hold no embedder reference | a shared embedder helper imported by the tools (the latency tax returns) |

## 4. Acceptance criteria

| ID | Criterion |
|----|-----------|
| AC1 | Batch pipeline: N pending ⇒ ≤8 embedded/tick, identity columns set together in one statement, `embedded_at` ISO, `embedding_error` cleared; row-level independence (a crash mid-batch leaves the rest NULL, next tick proceeds) |
| AC2 | Lifespan: exactly one task with the knob ON, zero with the knob OFF; the task is on `app.state`; cancelled + awaited on shutdown (no orphan task); the tick-line `tick_ms` stays within the 45 s budget under a hung endpoint |
| AC3 | The embed runs on a thread named `memoir-embed` (prefix pin); **no `asyncio.to_thread` call site in the worker**; embeds are sequential (concurrency assertion: at most one embed in flight) |
| AC4 | 401/403 ⇒ terminal immediately + latch engages on that tick; other permanent 4xx ⇒ per-row terminal; transient (429/408/5xx/connection) ⇒ attempt++ and retry next tick; dims mismatch ⇒ terminal error recorded, **nothing stored**; write-back failure ⇒ attempt++ (no infinite re-embed) |
| AC5 | Tick-line bytes exactly per D3.11 (`E` = this tick's failures, `M` = total terminal rows); each event has its own greppable line; knob OFF ⇒ a park line and no embedding work, with the task still alive and resuming after the knob returns ON |
| AC6 | A tick that raises is logged and the next tick still runs (`CancelledError` re-raised); no worker SQL references `tsv`; the worker runs on SQLite |
| AC7 | Restart ⇒ catch-up without manual action; lane-down ⇒ the recall footer discloses `active_model` / `embedding_excluded`; the runbook documents the operator requeue (clear `embedding_attempts`/`embedding_error`) |
