# Phase 5 — Wake briefing

**Depends on:** P2 (persona getters, keepsakes, latest fetches). **Flags consumed:** #3 (the budget model — the core of this phase), #9 (once-per-instance, its corrections and accommodations), #1 (zone arithmetic consumer), #13 (knob re-read per assembly).

## 1. Objective

The turn-1 `[SYSTEM CONTEXT: Memoir]` block at the assembly seam: stable id `memoir:{agent_id}`, compaction-surviving, once per instance (**written by the consumer, not the builder**), two zones (stable never-truncated / dynamic oldest-first), the normalized budget model with its render-time backstop, deadline-bounded reads, and a knob-aware gate — memory as *presence*, never a loader injection (L1/DD-10).

## 2. Decisions

| ID | Decision | Rationale (verified anchors) | Rejected alternatives |
|----|----------|------------------------------|------------------------|
| D5.1 | New kind `CONTEXT_KIND_MEMOIR = "memoir"` + builder `_build_memoir_briefing_message(agent_id, instance_id, manager)` called from `assemble_context_messages` (verified `daemon/services/context_messages.py:1892`), emitted via `_make_context_message` (the stamp site `:175` — ADR-5 `injected_message=True` + `context_kind`, verified `:22`). **Agent-identity source:** `assemble_context_messages` has **no `agent_id` parameter** (verified `:1892-1905`) — the ari-only gate reads **`row.agent_id`** from the SAME off-loop repository read that fetches the once-flag (D5.5 already returns the row), never a caller-supplied key (DD-13/L3). **The memoir block is appended to the PERSISTENT half** (`persistent_msgs.append(...)`, the snapshot-digest template at `context_messages.py:2334-2337`; the ephemeral half is a documented no-op returning `[]`), and the builder therefore **runs twice on turn 1** (the messaging path at `instance_messaging.py:4877` and the ContextSlot at `daemon/graph.py:940` — whose persistent half is discarded, `graph.py:8524-8533`): only the persistent-half copy matters | the blessed seam (§8.1); the snapshot-digest builder is the structural template (`:358-392`) | a new middleware slot (the seam IS the assembly function); loader injection (L1 — forbidden); a caller-supplied `agent_id`/`agent_meta` identity source (DD-13/L3) |
| D5.2 | Stable id `memoir:{agent_id}` via a `_stable_id_for` branch (verified `:395`; the `kv:{context_key}` branch shape at `:481`) | one block per key, no duplicates (`add_messages` supersedes in place) | per-turn ids (duplicate blocks under compaction re-append) |
| D5.3 | **There is NO compaction-hoist membership set to add.** The hoist is **truthy-keyed on any `context_kind`** (`daemon/_content_hardening.py:227-250`: `is_hoisted_injected` preserves any injected message that carries a `context_kind`). | D5.4 | **The once-flag WRITE SITE is the CONSUMER, not the builder.** `assemble_context_messages` **builds only**. The flag is written in `daemon/services/instance_messaging.py` inside the `if not is_retry:` block **AFTER `assemble_context_messages` returns** (`:4877` call site), confirming the memoir block is present in `_persistent_msgs` via a **stable-id match (`memoir:{agent_id}`) or `context_kind == "memoir"`** on the returned persistent half; the write itself uses the `asyncio.to_thread(set_metadata, …)` shape of the `project_injected` write (`:4238-4242`) — but that `:4239-4242` block is the **project**-context write, which runs BEFORE the assemble call and has no access to the memoir block (the write must NOT be placed there) | `daemon/graph.py:8524-8533` **discards** the persistent half (*"`_persistent_msgs` is intentionally discarded — the messaging path already prepended those messages to `graph_input`"*) and `instance_messaging.py:4825-4826` skips the orchestrator on `is_retry`. A builder-written flag consumes the flag on a **thrown-away block** ⇒ the briefing is **permanently lost, silently, for that instance** | a builder-written flag (silent, permanent briefing loss — the worst failure mode in this lane) |
| D5.5 | The once-flag READ is **off-loop**: `await asyncio.to_thread(instance_repository.get, instance_id)` — the shape at `context_messages.py:373`; the same read yields **`row.agent_id`** for the D5.1 gate (ONE read, two consumers). **P-7 note (N-5):** design.md §8.1 cites `_is_project_injected` — that is a **stale lead**; the shipped symbol is **`_is_project_already_injected`** (`daemon/graph.py:952`), so a reader comparing against the design must NOT "fix" this plan back to the stale name | the cited `_is_project_already_injected` precedent (`daemon/graph.py:951-952`) performs a **synchronous on-loop read** inside `async def assemble` — copying it adds a new on-loop DB read per turn (the routed incident class) | copying the precedent's sync read (adds an on-loop DB read per turn) |
| D5.6 | Every briefing DB read is **deadline-bounded**: each read wrapped in `asyncio.wait_for(…, timeout=10)` (the house class `BOOT_DB_TIMEOUT_S = 10`, `daemon/constants.py:70`); the **whole-build budget is ≤5 s**; on timeout ⇒ **degrade** (no block, no flag write) — never delay the turn | the turn is the product; the briefing is a wake. The snapshot-digest precedent swallows *exceptions* but has **no timeout**, so a hung DB hangs the turn today — do not copy that hole | unbounded reads (a hung DB hangs the turn); aborting the turn on a briefing failure |
| D5.7 | **Zones per the adjudicated budget model:** **stable** = approved persona (≤2,000 tokens, admission-bounded) + ALL keepsakes (≤4,000 tokens, pin-admission-bounded) — rendered in full, NEVER truncated; keepsake lines are rendered from ONE **byte-pinned template** — fields `pinned_by` + `pinned_reason` + the provenance class, e.g. `- [keepsake] {title} (pinned_by={pinned_by}; provenance={pclass}) {pinned_reason}` (exact bytes pinned in the pack; the template is the input to `est(candidate_render)` in D2.12's admission arithmetic, so pinning it makes the 4,000-token zone arithmetic reproducible and the admission pin deterministic). **Dynamic** = latest ~5 episodes ≤3,000 tokens, oldest dropped first. **Hard absolute section ceiling: 24,000 characters** | tokens are the planning unit (house `estimate_tokens`, `daemon/loader.py:1027`); the ceiling is sized from the admitted stable worst case (6,000 tokens ≈ 24k chars) so that "never truncated" is **arithmetically** true. **This supersedes design §8.2's "~12k chars" figure** (surgically, per P-4 — `decisions.md` §4 row 3, DR-1): the "~12k" survives as the **nominal** size (typical fill ≈10–14k chars) | the 12k-truth reading (starves the persona to ~1,500 tokens and the keepsake shelf to ~83 tokens per pin — gutting the content the feature exists to carry) |
| D5.8 | **Render-time backstop (binding):** the stable zone is **never truncated**. If the stable zone alone exceeds **24,000 chars** (a pin predating the budget rule, or estimator drift) ⇒ emit the stable zone **in full**, drop the dynamic zone entirely, and append `[…stable zone is N chars — M over the 24,000-char ceiling; pin admission exceeded its budget]`. If it exceeds **48,000 chars** ⇒ **withhold the block entirely** (return `None`, do **not** write the once-flag) and log `WARNING [Memoir] briefing withheld — stable zone N chars exceeds the 48,000-char absolute bound` | "never truncated" and "hard ceiling" are reconciled by the **outcome**, never by truncating the stable zone | truncating the stable zone (breaks the one invariant that must never break); silently dropping the overage (the agent would not know its memory was clipped) |
| D5.9 | **Persona missing** (the seed failed at boot, or a migrated DB) ⇒ render the stable zone **keepsakes-only**, prefixed `[persona unavailable — no approved persona version]`, and **do** write the once-flag (the block was delivered; the persona is a separate gap) | the persona is content, not schema; a missing persona must not suppress the keepsakes that ARE available | aborting the block (the keepsakes would be lost too); writing no flag (the same keepsakes would be re-rendered every turn, forever) |
| D5.10 | The closing **affordance line** (byte-pinned): the block ends with a one-liner stating that memory remains queryable mid-session via `memoir_recall(query)` / `memoir_timeline(since?, until?, q?)` | answers "why doesn't she remember an hour ago" at the affordance level; DD-11 stands | re-injecting on schedule (v2's alarm-wake item, L4-constrained, NOT built) |
| D5.11 | **Frequency semantics, stated precisely:** the assembly seam runs on **every** turn, so the briefing **does** fire on a **scheduler-sourced wake** — L4 governs the **message STAMP**, not the **context BLOCK**, so L4 is **not** violated and **no source lane changes**; the bare-HUMAN scheduler stamp is a standing product ruling and is never "fixed" (the v2 alarm-wake refresh inherits that constraint). Once-per-instance is enforced by the flag, read fresh each turn (revive-safe). **Disclosed residual:** a long-lived instance's dynamic zone goes stale with **no signal** — by design (DD-11); the v2 alarm-wake refresh is the designated fix | the planner's earlier phrasing overstated two things and is corrected here: the briefing is **once per INSTANCE** (so "attribution visible at every wake" was an overstatement), and the briefing is not suppressed on scheduler wakes | reading the flag as "no briefing on wakes" (a source-lane change the lane has no mandate for) |
| D5.12 | Agent condition: the briefing builds ONLY for the ari agent — gated on **`row.agent_id == "ari"`** read from the D5.5 off-loop instance read (never a caller-supplied key) | ari-exactly extends to the briefing (the memory is hers); the seam has no `agent_id` param, and the row read is already required for the once-flag | briefing for all agents (data exposure + scope creep) |
| D5.13 | Knob: re-read **per assembly**; OFF ⇒ the builder returns `None` (no block) and **no flag write** (so a later enable delivers the briefing on the next turn — intended), and the memory is **unreadable** in the meantime (no other read path exists in v1) | the knob is read at CALL time (AM-27); OFF is the whole personality | a boot-cached knob (an operator's flip would need a restart); writing the flag while suppressed (the briefing would be consumed without ever being delivered) |
| D5.14 | Builder DB reads are off-loop (as D5.5/D5.6) and a failed read must NOT abort assembly (swallow + skip) | the assembly seam must never be hostage to memoir health; L2 (the DB is the only durable substrate — no filesystem caching of the briefing) | on-loop reads; caching the rendered block (staleness by design) |
| D5.15 | Escaping + ADR-7 discipline: `escape_for_context_block` on rendered content; the `[SYSTEM CONTEXT: Memoir]` title form | the module's own ADR-4/ADR-5 contracts (verified `:20-27`) | raw markdown injection (format contract) |

## 4. Acceptance criteria

| ID | Criterion |
|----|-----------|
| AC1 | Stable id exact; duplicate-append impossible (idempotent supersede); the block survives compaction **because it carries a `context_kind`** (no hoist-set edit exists or is made) |
| AC2 | Zones (DR-1's model): persona+keepsakes rendered verbatim under their ceilings; keepsake lines render from the **byte-pinned template** (`pinned_by`/`pinned_reason`/provenance class); the dynamic zone drops oldest-first; the disclosures are exact bytes |
| AC3 | The builder **never** writes the once-flag; the flag read is off-loop and the **ari gate reads `row.agent_id` from that same read** (asserted: no synchronous `instance_repository.get` on the loop in the memoir path; no caller-supplied identity reaches the gate); every read is `asyncio.wait_for(…, timeout=10)` and the whole build is ≤5 s; a hung DB ⇒ degrade (no block, no flag write) and **the turn is not delayed**; non-ari ⇒ no block ever; knob OFF ⇒ no block and no flag write |
| AC4 | The flag is written by the consumer **only after** the persistent half contains the memoir block; the graph path (which discards the persistent half) leaves the flag **unset**; the messaging path on a non-retry turn sets it exactly once |
| AC5 | The four mutation legs of T5.5 are RED→GREEN; **DR-1's** 24,000-char overage ⇒ stable zone in full + dynamic dropped + the exact overage disclosure; **DR-1's** 48,000-char case ⇒ block withheld + the exact WARNING + **no flag write**; the persona-missing case ⇒ keepsakes-only + the exact prefix + the flag written |
| AC6 | After compaction the block persists; dropping the block from the persistent half leaves the flag unset (the silent-briefing-loss guard) |
| AC7 | The phase notes state the landing semantics exactly as D5.11 (scheduler-sourced wakes included; once per instance; the stale-dynamic-zone residual disclosed) |
