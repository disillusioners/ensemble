## Objective

Close two seams that silently **drop the new image-ref form** so the live (SSE) leg of the chat renders the thumbnail correctly even when the bubble was created by the optimistic POST (phase 4) and the server has since persisted the message. The two seams are:

1. **SSE whitelist filter** (`sse.service.ts:474-476`) — currently accepts ONLY `data:image/...` strings. Anything else is silently dropped. The new `/api/tmp_images/<id>` server URL refs must pass the whitelist with a PREFIX-SCOPED guard so arbitrary strings (and any future SSRF-ish URL the BE might one day echo) cannot leak through.
2. **Merge-images pin** (`message-merge.util.ts:160`) — `mergeMessagesById` does an unconditional spread on the incoming message. An SSE echo or refetch that lacks `images` will overwrite the existing thumbnail list with `undefined`. Pin `images` through every merge pass the same way `failed`, `queue_id`, and `retry_content` are pinned (`message-merge.util.ts:173-198`).

Plus: cover the **202-injection images-drop defect** (per RAG finding 2026-09-19 — `set_injection` has no `images` param at `daemon/manager.py:2734+`; the 202 path drops `message.images`) so the live leg renders a correct bubble even when the outgoing message was injected into a RUNNING target instead of durable-queued.

## Scope

### In Scope

1. **SSE whitelist widening** — extend `mapToMessage` (`sse.service.ts:464-478`) so the `images` filter accepts BOTH `data:image/...` (legacy / inline-base64 messages, still valid for backward compatibility) AND `/api/tmp_images/<id>` (or whatever the canonical ref prefix the backend phase 1 publishes; the canonical prefix is exposed as a single exported constant `TMP_IMAGE_REF_PREFIX` so the prefix lives in exactly one place — phase 4 imports the same constant for the optimistic-bubble rendering, the daemon-side image URL builder uses the same path, etc.).
2. **`Message` model parity** — `Message.images?: string[]` (`frontend/src/app/models/index.ts:207-208`) stays the shape; values are now a MIX of legacy `data:image/...` rows and new `/api/tmp_images/...` refs. The two forms are visually identical in the rendered `<img [src]>`.
3. **Merge pin** — add an `images` pin to `mergeMessagesById` (`message-merge.util.ts:160`) symmetric with the existing `failed` / `queue_id` / `retry_content` pins (lines 173-198): when the existing entry has `images` AND the incoming entry lacks `images` (or carries `undefined`), pin the existing copy through the merge. This is the seam that closes the optimistic-bubble regression when an SSE echo lands without images.
4. **202-injection display-ref parity** — when the chat component POSTs to a RUNNING target (the `set_injection` path, currently at `daemon/manager.py:2734+`), the 202 response body does NOT carry the message's `images` because the backend has no `images` param on `set_injection`. The optimistic bubble already carries the refs (phase 4); the SSE echo that confirms the bubble will carry the message text but NOT the refs (until/unless the 202 branch is fixed on the backend). Plan assumes the backend fix lands (flagged as cross-lane) and provides the FE-side safety net so the live leg never regresses to an un-thumbnailed bubble while the backend fix is in flight.
5. **Single source of truth for the ref prefix** — export `TMP_IMAGE_REF_PREFIX = '/api/tmp_images/'` from a new `frontend/src/app/constants/image-ref.ts`. The SSE whitelist, the optimistic-bubble renderer, the click-to-popup viewer (phase 6), and any future place that needs to discriminate data URI vs server ref all import from this constant. **Identity-grep mirror-parity pin** asserts the literal string appears verbatim in the spec source.

### Out of Scope

- **Backend `set_injection` images param fix** — owned by backend phase 1/3. This phase provides the FE safety net; the BE fix is a separate cross-lane dependency.
- **Message-API conversion to text** — the daemon converts refs to text for the agent; the FE never sees that step.
- **Phase 6 popup viewer** — the ref URL form is correctly rendered in the existing thumbnail `<img [src]>` (`chat-interface.html:196`); phase 6 only adds the click handler and the dialog.
- **Cleaning up legacy `data:image/...` messages from the DB** — old messages keep their data URIs; new messages keep their refs; both render correctly. No migration needed.
