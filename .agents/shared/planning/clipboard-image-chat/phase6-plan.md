## Objective

Add a **click-to-popup image viewer** that opens a fullscreen-style MatDialog when the user clicks any rendered thumbnail in the message list (works uniformly for legacy `data:image/...` rows and new `/api/tmp_images/...` refs), and ensure the rendered thumbnail carries a **graceful onerror fallback** so a 410/404 from a 30-day-cleaned tmp file does NOT produce a broken-image icon or a vanished bubble. The dialog copies the proven Mermaid fullscreen shell (`mermaid-fullscreen-dialog.scss`) for the flex / overflow / 95vw×95vh layout — but NOT its `bypassSecurityTrustHtml` machinery (unneeded for `<img [src]>`) and NOT its Mermaid-specific source-block / copy-source UI.

## Scope

### In Scope

1. **New MatDialog component** — `frontend/src/app/components/image-viewer-dialog/` (new). Renders the image at native resolution inside the dialog body; close button + Escape key + backdrop click; the dialog fits the same `dark-modal-panel` + `image-viewer-panel` (Mermaid uses `mermaid-fullscreen-panel` — we use a parallel `image-viewer-panel` so the two dialogs share the dark theme without bleeding class rules).
2. **Click handler on rendered thumbnails** — `chat-interface.html:196` currently has `<img [src]="img" class="message-image" alt="Attached image" loading="lazy" />` with NO `(click)` binding. Add `(click)="openImageViewer(img, $index, message.message_id)"`; route through a new `onImageThumbnailClick(...)` handler on `ChatInterfaceComponent` that calls the dialog with the same `(img, message_id)` shape used elsewhere in the chat component for ephemeral viewer-style affordances.
3. **Graceful onerror placeholder** — `<img>` tags in `chat-interface.html:196` gain `(error)="onImageError($event, message.message_id, $index)"` that swaps the `src` to a fallback data URI (a small inline SVG "image expired" icon) AND records the failure in a `failedImages: Map<message_id, Set<index>>` signal so a re-render (e.g. message re-fetch on reconnect) doesn't replay the fetch for an already-known-cleaned file. **No blank/undefined rendering** — the retain-last-data discipline from the FE conventions applies.
4. **Click target hit-area** — the existing thumbnail style at `chat-interface.scss:629-645` already declares `cursor: pointer` and a hover transform — keep both. The dialog open is a strict `(click)` binding, NOT a `(keydown.enter)` binding, because the thumbnail is not in the keyboard tab order today; if accessibility review later demands keyboard activation, add `(keydown.enter)` in a follow-up phase.
5. **Dialog data shape** — `{src: string, alt: string, message_id: string}`. The dialog does NOT need to know whether `src` is a data URI or a ref URL; it just renders the `<img [src]>` and lets the same onerror logic run inside the dialog body for consistency. (The dialog body is a separate `<img>` and runs its own `onerror` if the user opens a cleaned-up image — same fallback SVG.)
6. **No state change to message model** — `Message.images?: string[]` (`frontend/src/app/models/index.ts:208`) carries the data; the dialog reads it directly via `MAT_DIALOG_DATA`; no model migration.

### Out of Scope

- **Backend cleanup service** — 30-day auto-clear is owned by backend phase 3. This phase only handles the FE side of "what does the user see when the BE has cleaned the file".
- **Image download / copy buttons in the dialog** — kept minimal; only the close button. A "Download original" affordance is a follow-up if user demand surfaces; not required by the requirements.
- **Zoom / pan inside the dialog** — out of scope. The image renders at intrinsic size; if larger than the dialog body, the dialog's `overflow: auto` lets the user scroll. CSS-only — no JS interaction.
- **Image rotation / EXIF orientation handling** — out of scope; the daemon's image-reader normalizes for the agent side; the display side trusts the uploaded bytes.
- **Accessibility for keyboard navigation onto thumbnails** — not in the requirements; the dialog itself is fully keyboard-accessible (close button, Escape, backdrop). A follow-up accessibility pass may add tabindex + `(keydown.enter)` and is logged as such.
- **Phase 4 / Phase 5 changes** — this phase is independent of the upload pipeline and the SSE whitelist widening; the dialog opens correctly for both legacy and new message images regardless of how those messages were created.

## Risks

| # | Risk | Impact | Likelihood | Mitigation |
|---|------|--------|------------|------------|
| 1 | **`stopPropagation` on a thumbnail triggers future bubble-click handlers unexpectedly** — if a future contributor adds a bubble-level `(click)` (e.g. for "open conversation in side panel"), the defensive stopPropagation in `onImageThumbnailClick` silently breaks the new feature. | Low | Low | Comment in the handler explains the defensive stopPropagation is bubble-side-quiet today; future bubble-click features must add their own guard OR the defensive stopPropagation is removed in a follow-up. | 2 | **The inline SVG fallback is too small / too large / unreadable** — a 200-byte inline SVG renders at the thumbnail's natural size (≤200px), which may be illegible. | Medium | Medium | Plan: a `message-image-failed` class at `opacity: 0.55` + `filter: grayscale(1)` + a fallback label via the `alt` attribute ("Image no longer available"). | 5 | **`MatDialog` is not yet imported by `ChatInterfaceComponent`** — adding the import is a small change but increases the chat-component's bundle size. | Low | Low | Acceptable; MatDialog is already a project-wide dependency (used by the Mermaid dialog, mermaid-actions.service, etc.) so the import cost is a tree-shake-stable addition. |

## Exit Criterion

This phase is DONE when:

- Clicking a rendered thumbnail (data URI or ref URL) opens a fullscreen MatDialog showing the image at native size, with a close button + Escape key + backdrop click.
- The dialog shell uses the project's dark theme (tokens copied from `mermaid-fullscreen-dialog.scss:5-13`); the `mermaid-fullscreen-panel` class is NOT applied to the image dialog (separate `image-viewer-panel` to keep the two dialogs from bleeding rules).
- The dialog does NOT import `bypassSecurityTrustHtml` — the image is a plain `<img [src]>`.
- An `<img>` that 410s after the 30-day cleanup swaps its `src` to a small inline SVG fallback ("image expired" icon), gains the `message-image-failed` class (`opacity: 0.55`, `filter: grayscale(1)`), and is recorded in `failedImages` so a re-render does NOT re-fetch.
- The dialog body has its own `(error)` handler applying the same fallback if the user opens the dialog on a 410'd image.
- Plain-TS specs (`image-viewer-dialog.component`, `image-viewer-actions`, extended `chat-interface.component`) all pass; `npx tsc --noEmit` and `npm run build` pass with the 10 known pre-existing warnings.
- Identity-grep mirror-parity pins hold: `image-viewer-panel` appears in production source; `message-image-failed` appears in the SCSS file.
- Live Playwright smoke (separate tester pass): open chat, paste, send, click thumbnail → dialog opens; reload chat with the cleanup simulated (intercept image requests with 410) → bubble shows the fallback SVG, not a broken-image icon.
