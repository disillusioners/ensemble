## D1 — STRIP at the generation seam (leader ruling; plan TO this, do not relitigate) — *amended per A7, A8*

**Decision:** Generated units carry ZERO `.env`-derived `Environment=` lines (zero-env unit). NOT EnvironmentFile=, NOT LoadCredential=.

**Rationale (evidence-confirmed):**
- systemd exposes `Environment=` to any unprivileged local bus user via D-Bus (man 5 systemd.exec:2703-2708; live census: `systemctl show ensemble-main -p Environment` as a plain user returns the live POSTGRES_PASSWORD value in cleartext). Threat-model precision (arch §2): the strip closes exactly ONE surface — the manager's stored unit `Environment=` list re-served over D-Bus to **any local uid** (system bus socket world-connectable, property reads unauthenticated; the unit file's `install -m 0600` does NOT gate this — the manager parses as root and re-serves the parsed list) — and for the closed class (local non-`nea`, non-root) the closure is **total**; that class had no other reachable secret surface.
- All six minted values (PORT + 5× POSTGRES_*) are byte-equal to their live `.env` twins and fully redundant at runtime: `launcher.sh` re-exports `.env` LAST at the env-first call site `launcher.sh:1649` (per-key export `:186`; structural precedence comment `:1646-1647` — W1-corrected).
- The live unit is a frozen write-once snapshot (clobber refusal `adopt-unit.sh:517-521`, exit 78) never re-rendered by promote/restart/rollback (`promote.sh:418-428`+`:652-656` restart_via_launcher; `restart.sh:234-239`; `lib.sh:3880-3960` handback) — the fix changes FUTURE generations only; live remediation is a documented user decision (phase3 runbook section).
- Converges with in-house zero-env precedents: `scripts/ensemble-prod.plist:70-71` (env deliberately ABSENT), `scripts/ensemble-watchdog-watcher.plist` (zero Environment mentions), the host's ensemble-demo unit (mode-consistent; content not read — disclosed).
- Emptying the unit rung is sound: **ZERO consumers depend on unit-env carrying PORT/POSTGRES_*** (12-consumer census, arch §4.1: daemon, supervision classify, journal sweep, proc_tools, stop-ensemble.sh, promote/rollback `resolve_env`, watchdog plist lane, deploy psql, layer1 drop-in candidate). The rung's only "consumer" was the D-Bus reader — the defect itself.

**Rejected alternatives — *reasons corrected per A7; outcome (rejection) unchanged*:**
- **EnvironmentFile=** — REJECTED, but not for the reason first written. Empirically it **WOULD close the D-Bus exposure** (verified first-hand on this host, systemd 255.4: `ssh.service`/`cron.service`/`networkd-dispatcher.service` all show empty `Environment=` + populated `EnvironmentFiles=`; only literal `Environment=` directives appear in the property), and the same-file form (`EnvironmentFile=$INSTALL_DIR/.env`) does **not** create a second secret file — the earlier "second secret file" reason is **RETRACTED**. The load-bearing reasons: (i) the **D9 house invariant** (barred regardless); (ii) systemd's env-file parser **diverges** from `launcher.sh` `load_env_file` (:146-189 — one-layer quote stripping, `export ` prefix handling, comment/blank skipping) per man 5 systemd.exec:2715-2767 — two parsers reading the same file is a **silent value-divergence risk**; (iii) it **changes the missing-`.env` failure mode** (systemd refuses the unit start vs today's launcher WARN + boot-block). The in-house `--property=EnvironmentFile=` precedent (`test/packs/hard_reboot_drill_e2e_test.sh:707`, A8) demonstrates mechanism, not suitability — acknowledged, untouched.
- **LoadCredential=** — rejected for the right reasons: app-side `$CREDENTIALS_DIRECTORY` reshape; no in-house precedent (repo grep hits only this plan's own text); re-exporting to env would re-create surface #2 (`/proc/*/environ`) anyway.
- **No cheaper mechanism exists** (door closed): systemd 255 has no per-variable hide-from-D-Bus directive; `UnsetEnvironment=` is exec-time only (man :2816-2818); restricting the system bus itself is host-wide and breaks non-root `systemctl` for everyone. **The strip is the cheapest closure** (arch §2.3).
