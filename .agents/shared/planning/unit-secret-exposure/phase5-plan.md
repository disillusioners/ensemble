## 1. Objective

Every `.env` write site leaves the file mode-0600. **Framing (A6): this is defense-in-depth HYGIENE — re-homing insurance, umask-regression insurance, archive-copy hygiene — NOT threat-model closure: the exclusion delta is ∅ for every account class** (`/home/nea` mode 750 + `nea` group with no supplementary members; 644→600 excludes nobody new). INCLUDED per the commission rule (trivially small): ≈5-7 functional lines + comments, ≤10 total. The stage.sh chmod is LOAD-BEARING: the marker rewrite `sed > tmp && mv -f` re-creates the `.env` inode, so the file's mode is re-derived from the temp's creation mode at every stage — pre-fold that was the ambient umask (silently resetting any 600 set by deploy/adopt); post-W2-fold the block is fenced (`umask 077`, stage.sh:687-688, restored :727) so the temp materialises at 0600, and the explicit `chmod 600` after each mv pins the final mode. Without fence+chmod the hygiene posture is unenforceable.

**⚠️ Live-boundary disclosure (W2):** the stage-time chmod touches the **LIVE install `.env`** (`stage.sh:679` — `ENV_FILE="$INSTALL_DIR/.env"` IS the live install during a real stage; re-anchored @eb90a600c). Benign, mode-only, ∅ exclusion delta — but it IS a boundary delta inside a no-live-contact lane: **DISCLOSED here, in decisions.md D5, and in plan-overview §8; the leader carries it into the morning report.** Not silent.
