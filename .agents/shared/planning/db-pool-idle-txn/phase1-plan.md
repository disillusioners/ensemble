# Phase 1 — Transaction hygiene (F3 + F4 + F6) and the F1 audit record

- **Phase objective:** remove the two mechanisms that survive the borrow-site census at HEAD — the repair-tool transaction-abort gap (Site A / F3) and the readiness-probe's unbounded server-side retention (Site D / F4) — make the mission boot mint idempotent (F6), and publish the honest audit record for RCA sites B and C (F1).

## 1. Objective

At the end of Phase 1:

1. The agent-facing repair tool's dry-run path contains **no explicit `BEGIN`** and **rolls back on every exit path**, including the failure of the rollback itself.
2. The readiness probes carry a **server-side** bound on their own statements, sized from their own asyncio budget, so an abandoned probe worker cannot hold a connection open indefinitely. The probe's *client-side* classification is unchanged, and the leak detector / grace machinery is **byte-identical**.
3. The mission boot mint is **idempotent**: a second mint for the same anchor returns the winning epoch and raises no `IntegrityError`, and the caller's transaction is not poisoned.
4. The lane publishes an **honest** audit record: ~689 borrow sites audited, **0 unclosed borrows**; RCA sites B and C recorded as audited-and-clean with their premise corrections.

## 2. Decisions (canonical records live in `decisions.md`)

| ID | Decision | Rationale (cite) | Rejected alternatives |
|----|----------|------------------|------------------------|
| **D-01** | **F3: DROP the explicit `BEGIN`** (not "move it inside the inner `try`") — and move the rollback into a `finally` so *every* exit path rolls back | SQLAlchemy autobegins on the next `execute`, so the ROLLBACKs — not the BEGIN — carry the "does not commit" property; no savepoint/isolation/multi-statement semantics depend on the literal BEGIN; the only observable difference today is a PG `WARNING: there is already a transaction in progress` plus the `BEGIN` string in `pg_stat_activity.last_query` (research-leak-sites.md:59) | **(a) Move BEGIN inside the inner `try`** — fixes the failure path but KEEPS the `BEGIN` fingerprint in `last_query`, so a future occurrence can still be mis-attributed to a dry-run preview, and keeps the double-BEGIN warning. **(b) Leave as-is + rely on the repair engine's 60s `idle_in_transaction_session_timeout`** — a backstop, not a fix (ens_db_tools.py:619-627) |
| **D-02** | **F3: the rollback moves to a `finally`** (not merely "keep the existing rollback statements") | The remaining uncovered path after D-01 is a failure **of the rollback itself** (:1488) — which today also lands in the outer `except:` (:1513) with no rollback. A `finally` is the only shape that covers SQL-error, SQL-success, and rollback-error uniformly | Leaving the two rollback statements in place — leaves the rollback-error path uncovered |
| **D-03** | **F3: agent-visible preview strings and docstrings are updated in the same change** (the dry-run wording is part of the tool's contract) | The strings are agent-visible surface: `"DRY-RUN DDL EXECUTED INSIDE BEGIN/ROLLBACK — no commit"` (:1482), the DML twin (:1496), the tool docstring (:963), the wrapper docstring (:1407), and the comments at :1076-1077. The module docstring's `BEGIN/COMMIT` mentions at :37 and :942 describe the **audit** contract (the committed path), NOT the dry-run → **left unchanged** | Leaving the strings stale — the tool would keep promising a `BEGIN; <DDL>; ROLLBACK;` wrapper it no longer emits (D-04) |
| **D-04** | **F4: probe-scoped `SET LOCAL statement_timeout`** as the primary vehicle (house idiom), sized at **2× the probe's asyncio budget**, PG-only | The house already scopes a per-transaction statement timeout to one tool's own transaction with `SET LOCAL` on a POOLED connection — `ens_db_tools.py:787-797`, with the comment "NOT engine-wide connect_args"; `SET LOCAL` is reverted by the pool's `reset_on_return='rollback'`, so it does not leak to the next borrower | **(a) A dedicated probe engine/pool** — REJECTED on coupling C1: it would decouple the readiness probe from the manager pool it exists to observe (detector leniency by relocation). **(b) Engine-wide `connect_args` timeouts only** — the whole daemon's blast radius for a probe-scoped need; retained as F2's defense-in-depth layer instead (Phase 2). **(c) Per-probe asyncio cancellation** — impossible: `asyncio` cannot cancel a running thread's synchronous DBAPI call (the saver probe's `future.cancel()` works only because that probe is an async coroutine on the loop, research-leak-sites.md:120) |
| **D-05** | **F4: the server-side bound is 2× the client budget**, so the client-side `wait_for` fires **first** and the probe's failure classification (`probe_timeout`) is unchanged | `asyncio.wait_for` (`readiness.py:1279-1281`) is the budget that classifies the failure; a server bound at or below it would race the client and could reclassify a timeout as a hard component red (R9) | Equal budgets (race), or a bound below the client budget (reclassifies) |
| **D-06** | **F4: SQLite is left untouched** (PG-only guard, exactly as `ens_db_tools.py:793` does it) | SQLite has no `SET LOCAL` and would raise `OperationalError`; the SQLite install path must remain byte-identical (R8) | A dialect-agnostic timeout via a driver-level knob — no such knob exists for the sqlite driver |
| **D-07** | **F4: an explicit end-of-transaction precedes the probe's connection return** | RCA fix-item 4 asks for "explicitly commit/rollback" on the probe path; `Connection.rollback()` is a documented no-op when no transaction is active (SQLAlchemy 2.0.48 `engine/base.py:998-1023`) — so it is safe to call unconditionally | Leaving the rollback implicit in the pool's reset — the RCA's literal ask is unmet and the intent is invisible to a reader |
| **D-08** | **F6: idempotent mint via a dialect upsert** (`ON CONFLICT (anchor_instance_id) WHERE <open-predicate> DO NOTHING`) + an **anchor-scoped** re-resolve, replacing the `founding_message_id`-keyed probe for the boot path | The partial unique index and its migration already exist in 3 places (`mission_record/models.py:307-313`, `daemon/migrations/versions/20261025_140000_add_mission_open_epoch_unique_index.sql:67-69`, `daemon/manager.py:8549`) — **no schema change**; the house has the exact SQL shape in `daemon/repositories/job_queue/repository.py:485-496` (`on_conflict_do_nothing(index_elements=..., index_where=...)`); and `DO NOTHING` raises **no** error, so the caller's transaction is no longer poisoned by a statement-level `IntegrityError` (the failure mode `_mint_epoch_locked` currently documents at :548-554) | **(a) Status quo + disclosure** — leaves the 4×/boot noise and the caller-txn poisoning. **(b) Guarantee the rollback** — already guaranteed (census: 0 unclosed borrows; the with-block closes → pool reset rollback); it would not remove the `IntegrityError`. **(c) A schema change** — not needed and forbidden without an amendment |
| **D-09** | **F6: the re-resolve probe for the boot path is keyed on the INDEX's own predicate** (anchor + `status = 'open'`), not on `founding_message_id` | The boot epoch has `founding_message_id=NULL`, and the current re-resolve probe is keyed on `founding_message_id` — the code itself says that probe "can NEVER be found by that probe" for a NULL-founding epoch (`mission_record_service.py:558-565`). The index predicate and the rung-1 probe predicate are the same (`mission_record/repository.py:69-93`) | Keeping the `founding_message_id` key for the boot path — it can never match; the upsert would then have no way to return the winning epoch |
| **D-10** | **F6 is scoped to the own-session (boot) path** (`session is None`); the caller-session path keeps its documented "poison the caller's txn and re-raise" semantics | The observed 4×/boot defect occurs on the boot path (no session); the caller-session path's re-raise is load-bearing for the fail-open/revive logic, and its re-resolve (keyed on `founding_message_id`) works there (R5) | Changing both paths — alters commissioning-lane semantics for a defect that does not occur there |
| **D-11** | **F1's deliverable is a new artifact in this planning dir** (`audit-findings.md`), **not** an edit to the RCA | The RCA lives in the main checkout and is under a **read-only fence** for this lane; the audit record must not be lost, and the planning dir is the lane's own artifact space | Editing the RCA (fence violation); a code comment (the census is a one-time audit, not a code invariant) |
| **D-12** | **Phase 1 lands no pool knob** on the manager engine | F2's knob set is one table with one pin; splitting it across phases risks a half-configured intermediate state and two competing pins. The **engine-level** half of F4's backstop lands in Phase 2 with the rest of the knob set; F4's *guarantee* in Phase 1 is carried entirely by the probe-scoped bound (D-04), which is independent | Landing `statement_timeout`/`idle_in_transaction_session_timeout` in Phase 1 — splits the knob table and its pin across two phases |
