## 2. The narrow — exact semantics

**Policy (one sentence):** *at most one **OUTSTANDING** (undelivered) report obligation per child; a **DELIVERED** prior report does not block a new turn's report.* This is **not** "one report per child, ever".

**`SUPPRESS MINT IFF (ARM_A OR ARM_B)`** — a single query with `or_`/`and_` (one round-trip, one scan):

- **ARM A — same-ANCHOR (same-token) duplicate.** `P-ARM-A-PY` below. Status set `S-A`. Anchor = full key `child + ':' + completed_message_id`. **Scope: ARM A is load-bearing on exactly ONE path** — the router/deferred re-entry (`daemon/manager.py:12698` → `:12738-12739`), the only path that re-supplies an identical non-degenerate anchor; there, with the prior report already DELIVERED (COMPLETED ∉ `S-B`), **ARM A is the only arm standing between the chain and b4's exact shape** (2 obligations / 1 child, parent gets 2 reports) — the write-once index cannot arbitrate it (it keys on `(parent_instance_id, child_instance_id, child_message_id)` — `daemon/repositories/report_injection/models.py:234-242` — so a different anchor is a different obligation, not a conflict). Proven non-vacuous by mutation leg **L2c** + pin **NEW-5**.
- **ARM B — outstanding obligation (b4's protection).** `P-ARM-B-PY` below. Status set `S-B`. Anchor = child prefix with the colon terminator; SQLAlchemy `autoescape=True` neutralises `%`/`_` in the id (raw SQL needs the matching `ESCAPE` clause). **`retrying` is deliberately EXCLUDED from `S-B`** (leader ruling 6 — a stuck `retrying` row must never become a new forever-block class): a report row in `retrying` does NOT block a cross-anchor second mint. Residual **R-K4**; made observable by `P-RETRYING-INFO-LOG` (below).
