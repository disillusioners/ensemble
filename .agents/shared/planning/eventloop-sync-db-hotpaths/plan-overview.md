## Objective

Every in-scope request-handler DB read path stops issuing synchronous round-trips on the event loop — each site either collapses to a batched statement count or executes on a dedicated off-loop DB **offload** pool — so that sustained-loop-lag wedge captures stop and the `/api/instances` floor holds under the loaded composite, while every response body stays byte-identical to BASE under the one adopted children-order normalization, and the change ships as a **schema-empty staged artifact that is never promoted**.

**Single-sentence test:** the Phase-0 harness — **repaired and committed at `c3d87af26`** (D-37; RULING 3 unit (i); **R1 REJECT on increment #1 ⇒ tester increment #2 IN FLIGHT**, review closes before any HEAD run) — re-run **in `--mode head` with `--reference`** on the same prod-shaped fixture, shows **zero instances-path frames on the loop thread**, a held `/api/instances` floor, and zero net-new test reds — with the release staged but the live daemon untouched.

**The claim this plan can support (binding honesty clause, D-50):** **SCOPED CLOSURE + enumerated residuals — NEVER class-closure.** A green G1 must never be quoted as "the incident class is closed" while a known routed-out site still wedges the loop. This phrasing is carried by the Objective, the G1 row, the closeout docs and the CHANGELOG; quoting a green G1 as class-closure is a **reporting defect**.

**The dependency the pre-fold objective hid (architect §2.2, D-41):** the bridge removes the event-loop bottleneck; it **MOVES** the DB/GIL bottleneck. The GIL is process-wide, so a bridge thread performing ~1,434 round-trips starves the loop exactly as a default-executor thread did. ⇒ **the relief comes from D-B (A-class), not from C-class (the bridge); G2 is D-B-dependent, not bridge-dependent.** With D-B rejected, a *perfect* bridge still fails G2. D-B is therefore **REQUIRED** (D-28), not a "beneficial extension".

## Implementation strategy per site-class (architect §2/§5 + analysis §2 — consumed, not re-argued)

**Mechanism vocabulary (Q3):** **A** = query-shape batch (N statements → 1); **C** = off-loop offload (unchanged sync callable executed on the dedicated executor thread). Async-native is D-19 and is **not** this lane's mechanism.

### The offload seam (shared by every C site)

- **New module** **`daemon/services/db_offload.py`** (**D-20** — renamed before the Phase-1 API freeze: "bridge" is already taken twice in `daemon/services/` with different meanings — `main_loop_bridge.py:1-2` bridges **toward** the loop, `tmp_image_bridge.py:1-3` is a path→data-URI transform; and `db_pool_manager.py` denotes a **different subsystem**). Public seam: **`await offload(fn, *args, **kwargs)`** (**D-25** — kwargs are mandatory: `daemon/routers/work.py:181` is keyword-only with **five** kwargs `project_id`/`instance_id`/`status`/`kind`/`root_only`, `:181-187` — **A-10**: "six kwargs" was a miscount, so nobody hunts a sixth).
- **Implementation shape:** a module-private `ThreadPoolExecutor(max_workers=<resolved runtime value>, thread_name_prefix="db-offload")` (**B7**) and `loop.run_in_executor(EXECUTOR, contextvars.copy_context().run, functools.partial(fn, *args, **kwargs))`. **No executor parameter is exposed** (**B6** — "a caller picked the wrong executor" becomes unrepresentable, not merely pin-detected).
- **Construction timing (D-55 / W-10 — BINDING):** the executor is built **LAZILY via `db_offload.configure(max_workers=…)`, called from the lifespan** — after config load, before the first request. **Never at import:** `config.limits.*` is manager-reachable while `offload()` is called from **routers**, so an import-time construction makes the env knob either **dead** or **import-order dependent**. The knob is read **once, in the lifespan**.
- **Sizing (D-21 — BINDING):** **6 workers.** The plan's 4 counted *endpoints*, not the *coincidence set*; the architect measured the coincidence set at HEAD as **already 4** (badge tick bridged legs {instances_flat, defer_blocked} = 2, home tick {instances BFS} = 1 — they coincide at lcm(8,10) = 40 s — plus `/api/work` = 1), with the FE's own agent traffic (T-1/T-2, unmeasured) on top ⇒ **4 = zero margin. "Drop to 3 for margin" is REJECTED — 3 is below the already-reachable burst of 4 ⇒ negative margin.** Little's Law (L ≈ 0.19) was the *wrong statistic* for a forkJoin burst; and **defer-blocked at ~729 ms is 25–30× every other shape**, so it sizes the pool almost entirely by itself.
- **Pool envelope (D-22 — capacity 25, NOT 15):** the manager engine is built at `daemon/repositories/factory.py:434-435` with the config-driven `manager_pool_size` (default **15**, `daemon/constants.py:264`) + `max_overflow=10` ⇒ **capacity 25**, matching `daemon/services/readiness.py:165` `MANAGER_POOL_CONFIGURED_CAPACITY = 25` and the D-57 equality pin (`tests/postgres/test_dbpool_probe_starvation_pg.py:96`). The pre-fold citations (`factory.py:143-144`, `:155-156`) were the **`DatabaseConfig` dataclass defaults** — the SQLite/generic path. **`max_overflow` is NOT a worker budget**: a bridge worker holds **at most one** connection ⇒ B workers consume ≤ B of 25 (worst case B=6: 6 + default-executor jobs ≤5 + readiness probe 1 + residual on-loop ~2 = **~14 of 25, 56 %**).

- **Admission gate (B4):** an `asyncio.Semaphore` acquired with `await` — **defer, never reject, never time out.** A per-call timeout is the trap: `run_in_executor` future cancellation does **not** stop the running thread, so on timeout the DB work continues, still holding its connection and its GIL share, while the endpoint must return something — a byte-different error (violating byte-identity) or a late reply to a gone client. **A timeout amplifies the load it is meant to shed.**
  **Specified by D-43 (C-2 — BINDING):** (1) **permits == the resolved `max_workers` value** (6 at the default tier — the value `configure()` receives; **not** a bare `DB_OFFLOAD_MAX_WORKERS` symbol, which exists nowhere per D-55) — the gate and the pool are the same size **by construction**; (2) the permit is **released in the EXECUTOR FUTURE'S DONE-CALLBACK** (thread-side truth) — **never the caller's `finally`**: releasing in `finally` returns the permit **while the thread still runs** (the gate stops bounding and the executor queue becomes the unbounded path B4 exists to close), and skipped releases on cancellation paths **leak permits** (the seam deadlocks permanently after N cancellations — worse than the B1 hazard that *is* guarded); (3) new **pins (ix)/(x)**: cancel while awaiting `acquire` / the result ⇒ the **NO-RESERVE invariants of D-79** hold (permits == in-flight; no cancelled-waiter residue in the deque; max concurrent thread executions ≤ W; the invariant restores once in-flight drains) Pin 1.9(vi) cannot see either (it never cancels); (4) the gate counts **waiters + in-flight** and alarms on the sum vs permits (D-53/W-15) — executor queue depth is ~0–1 behind the gate, so a queue-depth alarm is structurally blind.
- **Re-entrancy guard (B1):** a bridged callee that itself calls `offload` deadlocks iff **O ≥ W** — probe-confirmed at W=4: O=2 ✓, O=3 ✓, **O=4 → permanent deadlock**, i.e. the deadlock sits **exactly at the designed concurrency**. A runtime guard raises a **typed error, never hangs**, plus a pin driving the nested case.

The guard is defence-in-depth and makes **B7** load-bearing twice.
- **BaseException containment (B2):** a `KeyboardInterrupt`/`SystemExit` raised inside a bridged callable **escapes the event loop entirely** (CPython `Task.__step` re-raises them) ⇒ process death + systemd `Restart=on-failure` crash-loop (`scripts/systemd/ensemble-daemon.service:108`), not a 500. Contained and pinned. (A `CancelledError` raised in a sync callee instead cancels the awaiting task — it looks like a client disconnect.)

### The transaction-boundary rule (TB-1 … TB-8, architect §5.3 + D-64 — a developer applies it without asking)

A callable is **offload-eligible iff all hold**: **TB-1** atomic open/close inside the callable; **TB-2** no session across an `await` (sibling F8); **TB-3** no session across the offload boundary (the seam takes a **callable**, never a session); **TB-4** the callee must not await and must not return an awaitable; **TB-5** no callback into the loop (`asyncio.run_coroutine_threadsafe`, `loop.call_soon_threadsafe` to a coroutine). **AMENDED (round 4 / D-80, verbatim):** "Coroutine-scheduling callbacks into the loop remain FORBIDDEN (`run_coroutine_threadsafe`, `call_soon_threadsafe` targeting a coroutine). Thread-safe FUTURE RESOLUTION via `loop.call_soon_threadsafe` on a parked `asyncio.Future` is the SANCTIONED wake primitive and the only one."; **TB-6** no `WriteGuardSession` participant (`daemon/write_pause_guard.py:277`; `daemon/manager.py:2785-2799` — which resolves to **`_session_scope`**, a scope *provider*: **the TB-6 argument survives**, the write-path sessions flow through it; D-78 precision); **TB-7** **read-only**; **TB-8** **idempotent under concurrency + no new shared in-process mutation** (D-64; the one known instance is a disclosed log-rate-only waiver). Verified end-to-end by the architect on three callees (C-1, C-2, C-3); TB-1…TB-7 full text in `decisions.md` D-35, TB-8 in **D-64**.

### (e) Response-bytes diff gates — the adopted two-part children-order rule, with the FIVE corrections (D-34)
