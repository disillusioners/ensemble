## Sub-Defect Reference (SD1–SD4)

The technical analysis labels four sub-defects of the premature-completion class as `D1`–`D4`. **Renamed here to `SD1`–`SD4`** to avoid collision with Component 1's `C1-D1`..`C1-D6` namespace. Sub-defects are descriptive anchors, not decisions.

| ID | Sub-defect | Hops (per analysis) | Description |
|---|---|---|---|
| **SD1** | Child-side premature END | 1 | Child's first LLM turn produces text-only no-tool-call AIMessage; `should_continue` returns END before the child has done any work. |
| **SD2** | Report-content honesty | 6, 7 | Junk text is promoted to a report envelope (prefix + concat + persist) without inspection of `tool_calls`. Truncation guard short-circuits on short message histories (`child_reports.py:1312-1313`). |
| **SD3** | Parent-side adjudication | 9, 10 | Parent consumes the junk report, treats it as progress, completes. No scrutiny on tool-call evidence. |
| **SD4** | Gate blind spot — terminal-children-aware waiting | 10, 11 | Completion gate fires on "no actionable pending tasks + no bus-pending watchers" but does not check "did I declare myself waiting on a child that just completed?". Inter-report gap (between A's report consumed and B's terminal event) lets a parent COMPLETE while a child is terminal-and-unannounced. |
