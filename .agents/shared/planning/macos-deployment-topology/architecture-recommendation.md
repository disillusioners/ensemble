## Design Decisions (adjudication summary)

1. **Stage-2 stack = Family A "user-domain daemon + minimal root"** (council unanimous, dominant axis: Risk): daemon stays gui LaunchAgent `com.ensemble.prod` as the operator user — NEVER root; `/opt/ensemble` top level root:wheel 755 with writable set exactly `data/**` + `releases/` (operator-owned) and read-only `launcher.sh`, `ensemble-prod`, `agents/`, `frontend/`, `config.yaml`, `.env`; promote via `/usr/local/bin/ensemble-privrun` (C1 port of `scripts/protection/ensemble-promote` gates; shipped INERT, arm = user-gated window, password sudo only, never NOPASSWD) — the SOLE root touchpoint; backstops as root LaunchDaemons; watchdog stays gui. This is **strictly better than the VM's residual** (nea can delete its own tree + holds NOPASSWD:ALL ⇒ trivial root; here bare `rm -rf` fails at the first root-owned child).
2. **Rejected:** Family B root LaunchDaemon supervision (daemon RCE = root — worse than the VM it mirrors; gui loss kills the watchdog's osascript; `SSH_AUTH_SOCK` per-session socket unobtainable in daemon context ⇒ git-push lanes break) and Family C `_ensdep` two-user (buys nothing over root-ownership + sub-chown on a single-operator Mac).
3. **PATH = two complementary layers, both required:** (a) plist template gains a **stable-anchor** `EnvironmentVariables.PATH` (macOS supervisor-env layer — A/B-proven REQUIRED: minimal launchd PATH ⇒ context7 `FileNotFoundError`, `healthy:False`; PATH block ⇒ `healthy:True` [RA]); (b) launcher probe→no-op→synthesize block (cross-platform, VM no-op, dynamic `~/.nvm/alias/default` resolution — never a version dir; `ENSEMBLE_LAUNCHER_PATH` top-precedence override).
4. **STATE_FILE = env-driven relocation, default unchanged:** `ENSEMBLE_LAUNCHER_STATE_FILE` override wired at Stage 2 via install `.env` → `/opt/ensemble/data/.launcher-state`; default `$INSTALL_DIR/.launcher-state` everywhere else (VM untouched); `.sweep-defer-*` follows `dirname($STATE_FILE)`; watcher + `upgrade_tools.py` honor the override. This RESOLVES the council's top-dir writability seam (root-owned top dir ⇒ operator can't create state files there) — no ACLs (deploy.sh plain-cp drops them).
5. **Deletion backstop port:** macOS twins under `scripts/protection/` — `com.ensemble.snapshot` (1800 s) + `com.ensemble.treecheck` (60 s) root LaunchDaemons; store `/private/var/ensemble/{snapshots,alerts}` root:root 700 (NOT under `$HOME`, NOT colocated with `/opt`); `cp -Rc` clonefile (rsync 2.6.9 lacks `-X`, `flock`/`runuser`/`stat -c`/GNU `head -n -N` all absent — host-verified [B]); **treecheck watches what EXISTS on Mac (binary + launcher.sh), not the VM's `releases/state.json` sentinel — which does not exist in the Mac flat layout; a naive port is permanently green** [B].
6. **Gaps:** GAP-1 (exit-78) = refuse-marker + watchdog latch (observability; the 10 s no-op re-exec stays — launchd cannot discriminate exit codes; plist restructures REJECTED, man-verified race-prone/breaks stop semantics [C]); GAP-2 (deliberate stop) = **bootout ONLY** — live-proven [RA]; GAP-3 (stop budget) = `CHILD_STOP_WAIT_S=70` documented; bootout window **MEASURED on demo — TERM→exit 143 in 1–2 s ×4 bootouts, the 70 s budget never engaged, no KILL escalation** [RB][RC].
7. **v0.29.9 gate:** Stage 2 hardening is blocked on the launcher journal O(n) cure landing (`feature/launcher-journal-sweep-fix`, in flight — not this commission's branch to merge). The escape is the fast-path code, NOT journal size.

## (i) launchd ↔ systemd mapping + the three A-gaps

Direct-ported from the canonical VM unit (read at source, `ensemble-main.service` + drop-ins):

| systemd (VM, canonical) | launchd (Mac) | Delta / gap |
|---|---|---|
| `Type=simple`, `ExecStart=<install>/launcher.sh`, `User=nea` | gui LaunchAgent `com.ensemble.prod`, ProgramArguments[0]=`/opt/ensemble/launcher.sh` (post-Stage-1), runs as operator | Same shape: **launcher is the supervisor-in-the-loop** (exit-code map 0/75/78/other, backoff, burst budget stay in the launcher; the supervisor adds no second supervisor around it — unit template header P4 ruling) |
| `Restart=on-failure` + `RestartSec=10` | `KeepAlive {SuccessfulExit=false, Crashed=true}` + `ThrottleInterval 10` | Equivalent for crash-level revival; clean exit 0 stays down on both |
| `RestartPreventExitStatus=78` | **NO ANALOG — GAP-1** | See below |
| `SuccessExitStatus=143` | **INVERTED — GAP-2** | Exit 143 (graceful SIGTERM stop) is nonzero ⇒ launchd RESTARTS after 10 s. **Stop on Mac = `launchctl bootout gui/$(id -u)/com.ensemble.prod` — NEVER bare SIGTERM.** Live-proven on demo: bootout stays down at t+28 s; launcher exits 143 on graceful stop; bare SIGTERM re-engages KeepAlive [RA]. Applies day-to-day, troubleshooting, and every runbook step |
| `TimeoutStopSec=90` | **NO KNOB — GAP-3** | Stop budget = launcher `CHILD_STOP_WAIT_S=70` (launcher.sh:60-62). Document ≈70 s; **measured on demo: TERM→exit 143 in 1–2 s across 4 bootouts, the 70 s budget never engaged, no KILL escalation [RB][RC]** — only the >70 s pathological case is unexercised |
| `KillMode=mixed` | launchd default (TERM to job, then KILL) | Acceptable; single-TERM contract preserved via bootout path |
| `StandardOutput/Error=journal` | `data/launcher.err.log` etc. (stderr = the daemon log surface under launchd) | Era note: MCP health for older binaries is visible there, not in `/readyz` [RA] |
| Drop-in `Environment=` (full-list reset; ADR-014: `.env` authoritative) | launchd supplies a DEFAULT PATH; plist supplies whatever we put | **Two-platform env pattern:** Linux zeroes supervisor env so the env-file wins; macOS must *positively supply* supervisor-env PATH. See §iv |
| `LimitCORE=4GB` (drop-in) | none | Not ported (macOS core-dump handling differs; not required) |
| Root-owned unit 0600 (because it carries POSTGRES_* env) | plist under `~/Library/LaunchAgents` is operator-writable today | Optional layer O1 (§iii) |
| `WantedBy=multi-user.target` (boots at boot) | gui agent logs in with the user | Single-operator Mac: equivalent in practice; sleep/shutdown semantics differ (no `Persistent=true` catch-up — missed timer windows during sleep are skipped [B]) |

**GAP-1 mitigation (exit-78 refusal):** launchd cannot discriminate exit codes; today a 78 refusal re-execs one no-op childless launcher pass every 10 s (~4 log lines, zero operator signal) [C]. Mitigation = **observability, not churn elimination**: (a) launcher writes `INSTALL_DIR/.launcher-refused` (one line `epoch=<ts> reason=<binary|config|dir>`, atomic tmp+mv, `|| true`) on EVERY exit-78 path — including the pre-loop fatals at launcher.sh:2810/:2813/:2818/:2849-2850 which currently leave NO state trace at all (only the run-loop child-78 lands `last_exit=78` in `.launcher-state`, launcher.sh:2700-2702/:2744-2745) [B]; (b) marker auto-cleared at successful binary resolution (recovery self-heals); (c) watchdog alerts once per marker mtime (existing latch pattern, watchdog-watcher.sh:281-326) + alerts on `last_exit=78` from the state file it already reads [C]. VM no-op: systemd leaves the unit dead at 78; the marker is a passive file, cleared by the next successful boot. **Rejected:** PathState/KeepAlive plist restructures — `SuccessfulExit=false` is already satisfied (OR semantics defeats the marker) and pure PathState restarts on clean exit-0, breaking deliberate-stop; filesystem monitors are man-verified "inherently race-prone and lossy" [C].

## (ii) Supervision-artifact ownership options (Mac)

Council analyzed three families against identical obligations; full per-family detail in the council record. Summary:

| Option | Who can bootout | Env consequences | Watchdog notifications | Operator day-2 | Verdict |
|---|---|---|---|---|---|
| **A: gui LaunchAgent (daemon) + root-owned tree + root backstops** | The operator uid — **including agent lanes** (residual, §vii; healed ≤60 s by treecheck + optional R1) | Session env preserved (rich PATH, `SSH_AUTH_SOCK`, HOME) — git-push lanes and MCP tooling keep working | Watchdog stays gui — osascript works; gains root-alert relay channel | ~zero sudo daily; sudo only promote/restore/plist (VM parity: `sudo systemctl …` README:49) | ✅ **RECOMMENDED (unanimous)** |
| B: system LaunchDaemon (root or `UserName=` drop) | Root only — closes the agent-lane bootout class | Minimal PATH must be reconstructed root-owned (drifts); `SSH_AUTH_SOCK` is a per-session launchd socket — statically unobtainable (ps-verified) ⇒ **git-push lanes break**; HOME re-declared; lanes lose `~/.ssh`, gh tokens, worktrees, TCC | osascript CANNOT post from daemon context — the watchdog's entire purpose dies (launcher `_notify_once` is a log-only stub, launcher.sh:2409-2413) | sudo for every stop/start/log; `make install` as operator cannot stop a root job; `launchctl submit` cannot mint root work from non-root (man-verified) | ❌ **REJECTED** — daemon-as-root means any daemon RCE = ROOT, strictly worse than the VM model it mirrors (VM: `User=nea`, never root, service:87); B's one win (bootout immunity) is purchasable via backstop timers alone |
| C: two-user `_ensdep` ownership | As A | As A + second credential lifecycle | As A | `sudo -u` hops on all staging; ACL-inheritance churn | ❌ **REJECTED as primary** — unprivileged owner and root both deny unlink to the operator uid; buys nothing over A's root-ownership + sub-chown; fold-in: owner ≠ writer ≠ daemon-uid (A already realizes it) |

**Hybrid note (operator's hypothesis confirmed):** "daemon goes LaunchDaemon + watchdog stays gui" = family B — rejected because the daemon-side costs (root RCE class, SSH_AUTH_SOCK, PATH reconstruction) outweigh bootout immunity; the inverse split (daemon gui + backstops as root LaunchDaemons) IS family A and captures the root-privilege benefit where it's actually needed.

## (iii) Stage-2 layer recommendation — the stack (Family A, detailed)

**Mirror the VM's ACTUAL protection first — deploy/supervision gating + defense-in-depth — not filesystem self-delete-proofing** (the VM tree is nea:nea 775 and was deleted twice 2026-10-12 by agent test code; the backstop is what answered "prod vanished" in seconds):

1. **Ownership/mode plan for `/opt/ensemble`** (post-Stage-1 tree):
   - Top-level dir `root:wheel 755`; read-only subset root-owned: `launcher.sh`, `ensemble-prod` (binary), `agents/`, `frontend/`, `config.yaml`, `.env` (root:wheel; `.env` 600, daemon reads only).
   - Writable set operator-owned: `data/**` (instances.db config.py:1105/7311, `data/logs/` logging_setup.py:72, `tmp_images/` config.py:2895, launcher/watchdog logs+state plists:101-105, watchdog-watcher.sh:27/:56, vscode-user-data config.py:5629) + `releases/` (journal, staging, payloads — the promote allowlist already anticipates `releases/<ver>/scripts/upgrade/promote.sh`, ensemble-promote:112-113).
   - **`agents/` read-only = stated behavior change:** prompt edits flow repo→release payload only. Matches prod reality (prompts ship in the release; DB overlay rows override files; loader mtime cache reaches new spawns via release) [C].
   - **Top-dir state seam (council catch, supersedes sibling-writability assumptions):** `.launcher-state` (launcher.sh:2821) and `.sweep-defer-*` (launcher.sh:893) live in the root-owned top dir — POSIX create/unlink needs write on the containing dir. **Resolution = §v state-file relocation into `data/` via the env override** (rejected: top-dir ACL — deploy.sh plain-cp drops ACLs).
   - Effect: bare `rm -rf /opt/ensemble` from any operator-uid process (agent lane included) **fails at the first root-owned child**; `make uninstall` (`rm -rf`, Makefile:454-458) is guard-gated AND EACCES-blocked — belt and suspenders.
2. **Promote = `/usr/local/bin/ensemble-privrun`** — C1 port of the VM's `ensemble-promote` gates (canonicalize `readlink -f` → exact allowlist → invoker-ownership refusal; BSD `stat -f '%Sp'` replaces GNU `stat -c`; exits 76/77 on refusal) [C][B]. **Shipped INERT; arming deferred to a user-gated window** (arm = operator decision to run it via stock admin-group `sudo`, password each time; a granular sudoers Cmnd-alias pin is optional tightening). **Never NOPASSWD** (pre-C1 NOPASSWD = ACE, ensemble-promote:60-63 [C]). **Sole root touchpoint** — daemon NEVER root. Release-payload promotes (drop into operator-writable `releases/` + symlink flip inside it) need no root at all — **flip shape `ln -sfn releases/<ver> current.new.$$ && mv -hf current.new.$$ current`, `-hf` MANDATORY** (🔴 `mv -f`/bare `mv` onto a symlink-to-dir destination is a proven SILENT NO-OP — the temp link nests inside the old release, `current` unchanged; `-hf` matches the launcher twin `_js_flip_current`; GNU parity = `mv -T` [RC-F1]); flip verification = `readlink current` + binary sha256, never the `/livez` version string (this-era binaries collide on `"0.10.5"` [RC-F2]); no ETXTBSY (running binary inode never overwritten) [canonical README:109-113]. **Manual flips are invisible to `releases/state.json`** — journal `current` goes stale during any manual-flip window; reconcile or accept-and-revert [RC-F4].
   - **Deliberate divergence from VM:** Mac promote is human-gated (interactive sudo password — an agent lane cannot answer it), NOT agent-initiable-with-nonce like the VM's polkit promote. Stricter on purpose; revisit only if the operator wants agent-initiable promotes (Decisions Pending).
3. **Deletion backstop (Directive B port)** — see `stage2-hardening.md` §backstop for full spec: root LaunchDaemons `com.ensemble.snapshot` (StartInterval 1800, RunAtLoad) + `com.ensemble.treecheck` (60 s, RunAtLoad); store `/private/var/ensemble/{snapshots,alerts}` root:root 700 (self-enforced like snapshot.sh:50/:58-60); mechanism `cp -Rc` clonefile (host-verified clone probe; man-documented automatic fallback to copyfile(2); copies xattrs/flags which samba rsync 2.6.9 cannot [B]); `shlock` (flock absent); portable count-prune keep-96 (48 h); 5 GB floor guard (tree ≈122 MB, 96 clones share blocks); staging dir + atomic `mv` publish; **nothing excluded — `.env` and `data/` in** (a restore must reconstruct a working install; secrets protection = root-only 700 store — the VM's stated rationale, snapshot.sh:31-36) [B][C].
   - **Treecheck sentinel (🔴 false-safety trap):** the VM watches `releases/state.json` (treecheck.sh:41-44) — **that file does not exist in the Mac flat layout** (host-verified [B]). Mac treecheck must watch `[ -d /opt/ensemble ] && [ -x /opt/ensemble/ensemble-prod ] && [ -f /opt/ensemble/launcher.sh ]`, adding `state.json` when the releases/ layout is adopted (Stage-2 promote flow). A naive port is permanently green.
   - **Alert channel (both):** root-side syslog (unified log, `logger`) + world-readable `/private/var/ensemble/alerts/` file (outside the watched tree — never write alerts into the tree that may itself be deleted [B]); operator-side relay via gui watchdog reading the alerts dir; optional direct `launchctl asuser <uid> osascript` from the root daemon (gui-domain osascript itself proven exit 0 [RC]; the root→asuser arm documented, NOT live-tested — operator probe [B]). Detection ≤60 s treecheck + ≤15 min watchdog `/livez` second net (watchdog-watcher.sh `_notify` :221-236) [C].
4. **Watchdog stays gui** (`com.ensemble.watchdog`, StartInterval 300, explicit INSTALL_DIR arg) and gains: refuse-marker predicate + `last_exit=78` latch + root-alert relay — all with dedup latches (existing pattern :281-326) [C][B].
5. **GAP-2 ergonomics (optional, recommended):** `ensemble-svctl` shim mapping `systemctl stop`-shaped calls → `launchctl bootout gui/$(id -u)/<label>` via the existing `SYSTEMCTL_BIN` seam (stop-ensemble.sh:552-560); byte-identical pid path when unset (:40-42) [C]. Stop = bootout ONLY, everywhere.
6. **Detach-before-stop invariant (Directive F):** macOS ships no `setsid(1)` — actor helper = double-fork + `os.setsid()` via `/usr/bin/python3`, applied to EVERY actor path that stops/restarts the daemon (VM-proven residual bug README:162-169; Ari bootout self-kill exit −9) [C].
7. **Optional layers:** **O1** root-owned plist copy at `/Library/LaunchAgents` (closes plist tampering — `~/Library/LaunchAgents` is operator-writable today; caveat: loads at any login on a single-user Mac) [C]. **R1** root health timer — root polls `launchctl print gui/$(id -u)/com.ensemble.prod` + `/livez`, re-bootstraps from the root-owned plist on absent-job; heals the proven Ari-class gui-bootout silence within ~60 s [C]. *Architect concurs with the governor's include-adjudication: R1 is cheap and directly heals a twice-proven class; "optional" only because the daemon job remains gui-bootable for the detection window.*
8. **chflags uchg: REJECTED by default** (unanimous) — breaks every sanctioned mutation and guards only accidents the snapshots already cover. The narrow variant (`launcher.sh` + `current` symlink only) breaks in-place `make install` swap (needs `nouchg` runbook step) — documented as fallback, revisit only if wrapper arm slips or accidents recur [C].

**Survives `make install` + promote?** Guard already fail-closed (Makefile:22/:37-39 + `scripts/install-dir-guard.sh`) [C]. Raw top-level deploys (binary/launcher/agents direct cp) die at EACCES → **deploy becomes drop-into-`releases/` + promote** (deploy.sh:326-334 staging legs route through the wrapper); release-payload promote needs no root. VM rollback runbook (`make uninstall`) unaffected — see §viii guard row.

## (iv) PATH strategy in the shared launcher

**Two complementary layers, both required** (rehearsal-a A/B proof upgraded this from "belt-and-braces"):

- **Layer 1 — plist `EnvironmentVariables.PATH` (macOS supervisor-env layer):** REQUIRED, proven — same box, same demo install: minimal launchd PATH (`/usr/bin:/bin:/usr/sbin:/sbin`) ⇒ context7 pool spawn `FileNotFoundError: [Errno 2]`, `healthy:False`, primed 0/2; prod-pattern PATH block ⇒ `Context7 MCP Server v4.6.0 running on stdio`, `healthy:True`, primed 1/2 [RA]. The repo template `scripts/ensemble-prod.plist` **omits EnvironmentVariables entirely** (citing ADR-014) while the installed prod plist carries one — **next-install-born-broken template defect** [RA]. Fix: template gains `<key>PATH</key><string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin</string>` — stable anchors only, zero user dirs, zero nvm version dirs. The operator's installed copy (with its nvm path) is preserved verbatim through Stage 1 (the anchored sed never touches it — no `agents-ensemble` substring in the PATH value, host-verified [B] **and preservation re-proven by rehearsal-b: the PATH value stayed byte-identical across the move round-trip, context7 healthy at the drill path**) and converges to the staged template copy during Stage 2's plist touch.
- **Layer 2 — launcher probe/synthesize block (cross-platform shared-surface layer):** after `load_env_file` (launcher.sh:2827), before `_journal_sweep`/binary resolve (:2844):
  1. `ENSEMBLE_LAUNCHER_PATH` set → export verbatim (top precedence, return).
  2. Probe: `command -v npx && command -v uvx && command -v node` all resolve → log one line, change NOTHING (**VM no-op case** — system Node 22.23.2 at `/usr/bin/npx`, uv system-wide; packaging luck made it work, the probe makes it guaranteed).
  3. Synthesize (any missing): prepend existing dirs from stable anchors `/opt/homebrew/bin`, `/usr/local/bin`, `$HOME/.local/bin`, plus **dynamic nvm resolution** — read `$HOME/.nvm/alias/default`, glob `$HOME/.nvm/versions/node/v<alias>*`, take latest, verify `bin/node` executable (NEVER hardcode a version dir — `v22.21.1` rots when nvm updates). Export `PATH=<synth>:$PATH`, log additions.
  - Synthesis failure (nothing found) → loud WARNING, proceed — optional MCP tooling must never wedge daemon boot; behavior degrades to today's status quo.
- **ADR-014 compatibility statement (reconciled):** ADR-014's doctrine — Linux `10-zero-env-reset.conf` zeroes supervisor env so `INSTALL_DIR/.env` is authoritative — governs **env-file authority for application secrets/DB config/ports**. PATH is a **supervisor-environment and host-execution concern**, a different axis: on Linux systemd's default PATH happens to resolve the tools; on macOS launchd's default PATH does not, so the supervisor context must positively supply or the launcher must synthesize it. **PATH must never be persisted to `.env`** (environment rot across Node/tool upgrades). The template's ADR-014 citation conflated the two axes — that conflation is the defect [RA][L].
- Required-tools provenance: `npx` (context7.py:56), `uvx` (webfetch.py:36), `node` (npx runtime); spawn seam passes command verbatim PATH-resolved (connection_manager.py:218-221, warmup_pool.py:590-593) [L].
- **Supply-chain note (out of scope, stated per directive):** context7 spawns via unpinned `npx -y @upstash/context7-mcp` and drifted v4.0.3→v4.6.0 across demo boots [RA]. Pinning = separate work item; NOT scoped into this commission.
- Tests: source-guards in `tests/test_launcher.sh` — probe-before-any-`export PATH=`, no `v22.`-style version literals, override precedence, plus fake-HOME nvm-synthesis tests (patterns: `tests/upgrade_test_lib.sh:69`, `tests/unit/tools/test_upgrade_install_root_layer1.py:561`) [L].

## (vii) Residual risks — what remains unsafe even after Stage 2

Stated honestly (council §5 + worker findings + rehearsal):

1. 🟡 **Process-kill:** agent lanes (same uid) can `kill -9` the daemon — KeepAlive restores ≤10 s (flap; VM parity).
2. 🟡 **Gui-domain bootout, including the watchdog itself:** domain-inherent while the daemon is gui; only family B removes it, at unacceptable cost. With R1 the daemon job self-heals ~60 s; the notification relay remains the weak point (root treecheck detection + syslog always survive in Console.app / `log show`).
3. 🟡 **Writable-set destruction** (`data/`, `releases/`, journal, state): ≤30-min RPO via snapshots; PG `ensemble_prod` (homebrew, outside the tree) survives tree loss but has its OWN backup story — **flagged: no tree-snapshot coverage of the DB; separate DB backup item for the operator**.
4. 🟡 **Disk fill** via writable set / TMPDIR — snapshot `MIN_FREE_MB` floor mirrored (snapshot.sh:53 pattern).
5. 🟡 **Local API = full control, no native auth** — standing; guarded only on the public path (README:186-190).
6. 🟡 **`.env` readable by daemon/lanes** — VM parity (nea-owned there), accepted; root-owned `.env` 600 at Stage 2 improves it (lanes read via daemon… daemon reads only — actually root:wheel 600 `.env` means the DAEMON (operator uid) can no longer read `.env`! → **design note: `.env` must stay readable by the daemon uid (root:operator-group 640 or operator-owned with agent-lane read accepted as VM parity)** — carried into stage2-hardening.md ownership plan as an explicit adjudication: `.env` operator-readable, group `wheel`-free; the read-only guarantee for `.env` is sacrificed to keep the launcher's `.env` sourcing working (launcher runs as operator).**
7. 🟡 **New root surface (the wrapper):** bounded by C1 gates + password + no-NOPASSWD; wrapper integrity is load-bearing post-arm; snapshot store is root-only but not tamper-evident (VM has the same gap).
8. 🟡 **Sudo-capable actors sit above the backstop** (any process that can answer sudo) — same as VM; the Mac has NO NOPASSWD surface today and the design adds none (the VM's NOPASSWD:ALL analog does not exist here — keep it that way).
9. 🟢 **Supply chain:** context7 via unpinned `npx -y @upstash/context7-mcp` (drifted v4.0.3→v4.6.0) — pin is a separate work item [RA].
10. 🟢 **Demo tree not covered by snapshots** (disposable drill env — accepted scope).
11. 🟢 **launchd has no `Persistent=true`:** asleep machine = missed snapshot windows (tree only changes while awake — accepted).
12. 🟢 **Snapshots are per-file point-in-time, not tree-atomic** (a clone during a daemon write can capture a torn file) — same VM limitation, accepted.
13. 🟢 **Journal regrowth is structural** (~675 entries/day, `mcp_server_state`) — watch `state.json` size before restarts regardless of the fast-path fix (VM standing rule, README:233-235).

**Ranked vs the VM's residual** (nea deletes own tree + NOPASSWD:ALL ⇒ trivial root): **Family A is strictly better on both axes** [C].
