# SET-LEVEL DIGESTS — one identifier per preserved set.
#
# CANONICAL RECIPE (one form for EVERY set, re-anchored 2026-11-02 — the W-7 fix):
#
#     cd <the evidence dir>
#     sha256sum <the set's members, named explicitly> | LC_ALL=C sort | sha256sum
#
# Two things make this ONE recipe cover EVERY set:
#   1. the members are named EXPLICITLY (relative to the evidence dir), so a set may
#      SPAN SEVERAL directories — the P3 adjudication set spans two;
#   2. the sort is `LC_ALL=C` — a locale-dependent sort silently drops entries from
#      the manifest (the house comparator rule, D-d).
# The manifest lines are the TWO-COLUMN form (`<sha256>  <path>`) — the house
# manifest form (the same as `p1-p2-mutation-logs.sha256.txt` and the per-set
# preservation manifests) — so every manifest is CHECKABLE DIRECTLY:
#
#     cd <the evidence dir> && sha256sum -c <the manifest>
#
# (ND-3, cause corrected 2026-11-02: the P3 adjudication manifest had been captured
# with an EXTRA SIZE COLUMN — a three-column LAYOUT, `sha256 SIZE path`, written by
# the manifest's generator. That layout is NOT `sha256sum`'s default form: `sha256sum`
# prints TWO columns (`<sha256>  <path>`). The extra column is what `sha256sum -c`
# cannot parse — it took the SIZE column for the filename and reported "21 listed
# files could not be read". The manifest is now the two-column form and
# `sha256sum -c p3-adjudication.sha256.txt` reports **21/21 OK**. The per-file
# digests were never wrong; only the LAYOUT was.)
#
# THE AGGREGATE IS **NOT** A HASH OF A MANIFEST'S OWN LINES: it is the canonical
# recipe over the set's MEMBERS (their `sha256sum` output — `sha256sum`'s own
# TWO-column form, `<sha256>  <path>` — sorted with LC_ALL=C). Hashing a manifest's own two-column lines yields a DIFFERENT
# number — the per-file digests are the same, the aggregate is the recipe's.
# The per-set membership is stated in each set's own manifest file where one
# exists, and every aggregate below was RE-DERIVED with the recipe above.
#
# WHY THIS FILE WAS RE-WRITTEN (the W-7 defect): the previous form was
# `cd <set-dir> && sha256sum * | sort | sha256sum`, which (a) could not express a
# multi-directory set, (b) used a locale-dependent sort, and (c) did not carry the
# path prefix — so the digests are NOT comparable with the new ones. The OLD digest
# of every set is recorded below next to the NEW one, with the reason.
#

# NOT RE-DERIVABLE (28 candidate recipes excluded). Its REPLACEMENT, computed with
