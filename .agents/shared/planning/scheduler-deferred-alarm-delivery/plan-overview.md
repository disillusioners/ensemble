## (a) Problem + confirmed root cause

`self_alarm` in `reuse_instance` mode **silently DROPS** the alarm when the bound caller is busy at the fire instant; a one-shot is **consumed and lost**. No durable trace remains. Three drop sites, one mechanism (architect §1) — every one fires a completion callback on an `execution_id` that was never INSERTed (registry `registry.py:473-494` → `source/repository.py:618-643`, pure UPDATE on a missing row) and returns before `_execute_run`'s `triggered` INSERT (`scheduler.py:964`):

1. **Busy branch** `scheduler.py:1194-1213` — blocking set `{RUNNING, WAITING, WAITING_CHILDREN}` (the predicate is `:901-905`), bare `return` at `:1213`.
2. **Manual-trigger twin** `:1241-1258` — reuse-gated; **R9: deferred, disclosed non-goal** [DEC-3].
3. **Semaphore-timeout skip** `:909-942` — called at `:1189-1190` **before** the reuse check at `:1195` → **reachable for EVERY `instance_mode`** (probe P5).

Then `_run_schedule:620-632` consumes the one-shot **unconditionally** (`_is_one_time_executed=True` `:624`; `registry.py:514-525` stops + disables). `last_run_at` is derived from the latest execution row → **a lost alarm is observationally identical to a delivered one.** Busy-branch log is INFO.

**The delivery primitive exists.** `InstanceManager.enqueue_message_job` (`daemon/manager.py:9501-9515`) **always queues** — no inject-vs-queue branch inside it (RAM injection is a separate caller-level API, `set_injection` `manager.py:3742`; the scheduler is **not** in its caller list). The per-instance claim gate (`task/repository.py:2920`, inside the atomic claim UPDATE `:2799-3084`) is `AND instance_id NOT IN (SELECT instance_id FROM task WHERE status='running')` → a PENDING task for a busy instance is un-claimable until the turn ends → **it fires as the next turn** (pool re-attempt ≤3s, `worker_pool.py:1392-1443`). **No new table, service, polling loop or wake primitive** (architect §16).

## (b) Goals / NON-goals

**Goals** — G1 a busy caller still receives the alarm; G2 N busy fires coalesce into **one** delivery carrying the **live** missed-occurrence count; G3 every skip/defer/refusal/abandonment leaves a durable `schedule_executions` row; G4 the deferral is visible; G5 E1 — a bound caller that is **confirmed** gone never causes a stranger spawn.

**NON-goals (hard)** — manual-trigger twin (`:1241-1258`; **not changed**, [DEC-3]); G3 re-fire suppression (hard-reboot lane; **different** concern, keep separable); **no new table / migration / daemon service / polling loop** (architect §16: "NO" on all four); **no tool-category change** (`PRIVILEGED_TOOL_CATEGORIES` `daemon/tools/_tool_registry.py:290-477`, `self-alarm` #10 `:434`, exact-set pinned in 5 test files → `_tool_registry.py` and `instance.py` are **NOT touched**); **no changes under `agents/`** (new response fields ride the existing `agents/ari/meta.json` allow-lists `"scheduling"` `:34` / `"self-alarm"` `:40`); **no `create_instance_mapping` upsert change** (cross-source blast radius); **no teardown of a pending deferred delivery** and **no re-enqueue under a colliding key while a delivery is live** (architect §15.5-6).

**[LEADER-RULED — iter-003 B3] PRECEDENCE (stated once, here):** the **coalescing LIVENESS** test is the **MQ status guard** (`status IN ('ready','retrying')` — W9); the **Task check is the STRANDED-DELIVERY test, used at ENQUEUE TIME** for durable evidence (Blocking 1 — **UNCHANGED**: `PENDING` stays verbatim there). The **coalescing gate's** Task condition widens `pending` → **non-terminal** (exclude `COMPLETED|FAILED|CANCELLED`): the Task flips to **RUNNING at claim** (`task/repository.py:2801-2804`) **before** the MQ row leaves `ready` (`message_processing_pipeline.py:464` → `:678`; `message_queue/repository.py:325-375`), so a `PENDING`-only gate fails inside that code-verified window → branch C → a **SECOND LIVE DELIVERY while the first is in flight** (W9's forbidden outcome + an at-most-once breach + a count reset to 1). **Disclosure:** the `retrying` half of W9 is **defensive only** — `schedule_retry_for_stuck` has **zero production callers**.
**The async seam (should-fix c).** The adapter's repository work is synchronous and is reached through the manager facade's thread-offload, following the house pattern: `await asyncio.to_thread(self._queue_repository.claim_specific, message_id)` (`message_processing_pipeline.py:676-679`) and `await asyncio.to_thread(self._manager._job_queue_service._repository.stamp_message_id, job_id, ctx.message_id)` (`instance_messaging.py:3292-3296`). The deferred path follows the same shape: **await** the facade coroutine for the enqueue (`await manager.enqueue_message_job(...)`) and **await `asyncio.to_thread(<sync repo method>, <args>)`** for the synchronous work (state write, guarded update, Task lookup). **The Task check needs NO new repository method** — `TaskRepository.get_by_message(message_id)` already exists (`task/repository.py:664-670`) and answers it.

**Row-first ordering — SETTLED by leader ruling L-1: §15.8 GOVERNS, the literal order is SUPERSEDED.** Architect §3 step 2 lists *marker → enqueue → capture → DEFERRED row*; architect §15.8 says *audit-row-write failure fails CLOSED (no dispatch)*. **§15.8 governs**; the literal order is superseded. The invariant ordering is **start row → enqueue → complete row (DEFERRED | FAILED)** — rationale verbatim in `decisions.md` DEC-18 (L-1). **Two mandatory consequences:** **(a)** the `_defer_delivery` **enqueue-failure branch** MUST `record_execution_complete(execution_id, FAILED, ...)`, MUST **not** consume the one-shot, and MUST re-arm/report — never leave an unfinished `triggered` row; **(b)** one-shot consumption is permitted **only after confirmed durable evidence**, and that evidence is defined **once, in `decisions.md` DEC-9** (Blocking 1, leader-ruled): **a PENDING Task whose `message_id` EQUALS the `message_id` returned by THIS enqueue** — a real enqueue id **alone is NOT durable evidence** (the id is what the Task must **match**; it is also what the cleanup deletes by). The **disjunctive** form that stood here is **WITHDRAWN**: it is false on a live path (the question-pause marker window).

**Optional (a) — the `content=` kwarg typo: DO NOT COPY IT.** Architect §3 step 2 (`:45`) writes the enqueue as `manager.enqueue_message_job(instance_id=<pinned>, content=<composed with count=1>, …)`. **`content=` is a TYPO in the architect's prose** — the real keyword is **`message=`** (`daemon/manager.py:9504`, `async def enqueue_message_job(self, instance_id: str, message: str, source: str = "api", priority: int = 1, …)`, `:9502-9516`); `content=` raises `TypeError: enqueue_message_job() got an unexpected keyword argument 'content'`. The **SQL column** genuinely *is* `content` (`UPDATE message_queue SET content=:c`) — that is where the confusion comes from; the **column** is `content`, the **kwarg** is `message`. Every enqueue in this design uses `message=`.

**Marker-miss fallback (crash self-heal, architect §3.4).** If `_defer_message_id` is absent but a live deferred delivery may exist, the enqueue under the generation key produces a **dedup hit that returns the KEPT `message_id`** (verified: `instance_messaging.py:3266-3306` returns `original_message_id` from `JobItem-A.metadata.message_id`, never the phantom's) → persist it → the next coalesce update corrects the kept body. **No loss, no duplicate.**

**One-shot consumption — CONDITIONAL on durable evidence (ADR-3), GATED on `_fire_outcome` (CRIT-1, leader-ruled).** `_run_schedule:620-632` consumes the one-shot only when the fire produced a durable delivery — or was a **permanent refusal**. The per-fire flag on the adapter is **`_fire_outcome` ∈ `direct` | `deferred_durable` | `rearmed` | `refused_permanent` | `failed`** — **FIVE** values (the fifth is new, see `decisions.md` DEC-9's CRIT-1 amendment block):

| `_fire_outcome` | meaning | one-shot consumption |
|---|---|---|
| `direct` | delivered on the direct path | **consume** (today's behaviour, **exactly** unchanged) |
| `deferred_durable` | durable evidence — **a PENDING Task whose `message_id` EQUALS this enqueue's id** + the DEFERRED row written | **consume** |
| `refused_permanent` | **NEW** — a **permanent** typed refusal **at fire time** (the E1 confirmed-absence refusal): consume + a `failed` row carrying the **refusal reason** | **consume** |
| `rearmed` | re-armed for a later attempt, no durable carrier | **do not consume** → re-arm + `await asyncio.sleep(SCHEDULER_ERROR_RETRY_S)` + WARNING |
| `failed` | unexpected error — the intent may still be alive | **do not consume** (same re-arm + sleep) |

**The typed-error catch site (CRIT-1 part 2).** `_execute_run` gains a **NARROW catch for the mapper's typed refusal**, placed **BEFORE** the blanket `except Exception` at `scheduler.py:1028` — so the refusal is classified instead of swallowed: `except BoundCallerRefusal as refusal:` → `_fire_outcome = "refused_permanent"` + complete the execution row as `FAILED` with `error_message=refusal.reason`; the **blanket `except` at `:1028` stays exactly where it is** and still handles **unexpected** errors (`_fire_outcome = "failed"`). Python matches the first applicable `except`, so the **ordering is the mechanism**. A narrow catch written as `except Exception` is a **defect** — it would re-classify transient errors as `refused_permanent` and consume one-shots on them. **Why this matters:** without the fifth outcome, the refusal falls into `failed` ⇒ no consumption ⇒ a permanent **5s re-fire spin against a dead target** (past-due `_get_next_trigger_time` returns `now`, `:753`).
**Consumption justification (two different grounds — do not "unify" them).** `deferred_durable` consumes because a **durable delivery exists** (L-1 consequence (b)); `refused_permanent` consumes because the condition is **permanent** — keeping the intent alive is a spin, not a safety property. The implementation must comment them separately. **The DEC-21 arm-time refusal is NOT a `_fire_outcome` value** — it fires at **arm** time, so there is no fire and nothing to consume; it surfaces as a **tool-level typed error** (see C3).

**BLOCKING 1 — the PER-DELIVERY predicate + the `taskless_enqueue` leg (leader-ruled).** `deferred_durable` requires **a PENDING Task whose `message_id` EQUALS the `message_id` returned by THIS enqueue** (the Task row carries `message_id`, `instance_messaging.py:2316-2320`) — the definition lives **once**, in `decisions.md` DEC-9, and is cited here, in §(d) D1, and in §(e) pin #7. The check is **per-DELIVERY, not per-INSTANCE**: the claim gate excludes only `RUNNING` (`task/repository.py:2920-2935`), so a busy caller routinely holds **unrelated** PENDING tasks — a **DECOY** task would satisfy a per-instance form (pinned: the DECOY leg of pin #7 must still classify `taskless_enqueue`). A real `message_id` alone is **not** durable evidence. The **known live path** that breaks the old id-based predicate: the **`_deferred_question_pause` marker** (set `graph.py:10579-10595`, popped `instance_messaging.py:5183-5201`) makes `_prepare_enqueued_message` **SKIP PROCESS_MESSAGE Task creation** (`instance_messaging.py:2246-2249` + skip branch `:2301-2309`) while the instance's DB status is **still RUNNING** — the **MessageQueue row is created unconditionally** (`:2182-2210`) and READY rows have **no resume drain** (`:2221-2222`). The busy branch fires in that window (`scheduler.py:1194-1213`; the predicate itself is `:901-905`) ⇒ a REAL `message_id` with **NO Task**.
**A Task-less enqueue is classified `failed`, never `deferred_durable`:** (1) **best-effort cleanup** of the just-created MQ row — **delete by `message_id`**; if the cleanup itself fails, **log and continue**, **naming the stranded-row residue** (a surviving row is a live generation-pin); (2) complete the execution row to **`failed`** with the reason **`taskless_enqueue`**; (3) **do NOT consume** the one-shot; (4) **re-arm** on the existing 5s loop; (5) **open the non-delivery episode** (the carrier below). **The coalescing target and the `_defer_message_id` persistence are gated on the SAME check** — otherwise a Task-less `ready` row would pin the generation and a recurring alarm would absorb every later fire into a dead delivery. **A Task-less enqueue leaves NO JobItem either** (`instance_messaging.py:3000-3030` — the JobItem create is skipped with the Task, to avoid *"an item that has NO Task to claim"*) → the **idempotency key is NOT occupied** → after the MQ cleanup, **the deleted `message_queue` row is the attempt's SOLE residue** (plus the terminal `failed` audit row).

**BLOCKING 3 — ONE carrier, ALL legs (leader-ruled).** **`_defer_since` is the NON-DELIVERY EPISODE carrier**: set **set-if-absent (COALESCE, in the method signature)** at the **FIRST NON-DELIVERY outcome of ANY kind** — **defer** (a durably-deferred occurrence is **consumed-as-armed but NOT delivered**) · **re-arm** · **direct-failure** · **taskless-enqueue**. The carrier tracks **non-DELIVERY**, not non-consumption — this is the **one** enumeration (DEC-9's cap block states it identically). On the **24h breach** the episode terminates **visibly**, by the **ONE** rule: **(1)** abandon any still-pending delivery with **ONE** guarded statement (`WHERE status IN ('ready','retrying')` → terminal abandoned); **(2)** **if** it returns a **row** → the delivery is dead → **CONSUME** the occurrence + a **terminal `failed` row** (reason **`nondelivery_age_cap`**) + **WARNING**; **(3)** **if** it returns **no row** (nothing pending, or already claimed and **will land**) → **do NOT consume, do NOT write a failed row**; **(4)** the breach **never opens a fresh generation** (for a one-shot that would re-open the unbounded spin; for a recurring schedule the next occurrence is cadence-driven); **(5)** the carrier **clears** on a successful direct delivery **OR** on a terminal breach disposition — via a **clearing API surface** (`clear_since`/`clear_message_id`/`reset_count`), not set-if-absent only. **Fields the breach touches:** `_defer_since` (cleared) · `_defer_message_id` (cleared) · `_defer_count` (reset to 0) · `_defer_gen` (**not** bumped — the breach never opens a fresh generation). **The double delivery at the breach is PREVENTED** by rule (1): the pending delivery is abandoned, not duplicated. This closes the **direct-path `failed`** leg, which was bounded **by accident** (today's blanket `except` `scheduler.py:1028` → `_run_schedule` consumes at `:624`); under the plan `failed → do NOT consume`, a past-due one-shot re-triggers immediately (`:753`, lateness cap unset live, `config.py:2667-2673`) → ~**17,280** rows/day **forever**. `_defer_since` is cleared **ONLY on a successful direct delivery** (and by the cap's own terminal transition) and is **NEVER literally reset to null by a rollover** — a literal reset would **inert the cap**.

**Bounds — ADR-5, checked at FIRE TICKS ONLY (no polling loop).** Count cap 16 → saturate, body says "16+ occurrences coalesced", **never drop the delivery**. Age cap 24h → at the next fire tick the episode terminates **visibly** under the **ONE Rule-A outcome** (branch D above): abandon any still-pending delivery with **ONE** guarded statement (`WHERE status IN ('ready','retrying')` → terminal abandoned); **if** it returns a **row** → **consume** the occurrence + a terminal `failed` row (reason **`nondelivery_age_cap`**) + a **WARNING**; **if** it returns **no row** → **no consumption, no failed row** (the in-flight delivery will land); the carrier **clears**; the breach **NEVER opens a fresh generation**. **[SUPERSEDED-BY-RULE-A]** the prior form here (close the generation, then open a **fresh** one whose body carries `abandoned_prior=N`) is the **REJECTED Rule B** — it re-opens the one-shot spin and can double-deliver. `one_shot_max_lateness_seconds` is **not** reused (it measures fire lateness, is unset live, and the recurring alarm is structurally outside it — architect §6).

### C2. The semaphore site — TWO-BRANCH fix (ADR-10, supersedes my DEC-2)

`_acquire_execution_slot` timeout (`:909-942`) fires **before** the reuse check (`:1189-1190` vs `:1195`) → reachable for **every** `instance_mode` (P5). Two branches:
1. **Deferrable target** (reuse-mode with a resolvable mapping) → **defer to the pinned caller** — the identical mechanism as C1.
2. **No deferrable target** (new_instance / no mapping) → **RE-ARM**: write the execution row via start→complete with `DEFERRED` + a reason, **never consume the one-shot SILENTLY** (DEC-22, **generalized by Blocking 3**: after the 24h age cap it terminates **visibly** as a terminal `failed` row, reason **`nondelivery_age_cap`** — the token `defer_age_cap` is **superseded** because the cap is no longer re-arm-specific), and **MANDATORY `await asyncio.sleep(SCHEDULER_ERROR_RETRY_S)` (5.0s, `daemon/constants.py:376`)** — mirroring the `PAST_LATENESS_CAP` pattern at `:580-582`. **The sleep is NOT optional:** a re-armed past-due one-shot returns `now` from `_get_next_trigger_time` (`:753`) → `wait_seconds ≈ 0` → a proven hot loop when the lateness cap is unset (architect §3 alternative (iii)(b), §11).
**W5 — the semaphore branch structure (leader-ruled).** The deferrable-target test at the semaphore site is a **READ-ONLY mapping resolution performed at the call site**: it resolves the bound instance id **without** re-entering `mapper.get_or_create_instance` (whose mapping-miss branch is the only stranger-spawn surface, C3). A resolution that would otherwise *create* or *spawn* is treated as **no deferrable target** → branch 2. The defer branch is additionally **gated to the SCHEDULED path only**. **Manual-path delta (disclosed):** the manual-trigger twin (`:1239-1260`) never reaches the semaphore defer branch → it is **unchanged** — not routed through `_defer_delivery`, and it does not participate in the deferral episode state. This is a **scope statement, not a behaviour change** (consistent with L-G and DEC-3's non-goal).

**R20 — DISCLOSED VISIBILITY GAP (delta re-review).** The breach handler's **re-arm outcomes** — the claimed-delivery shape (delivery claimed and **will land**) and the lookup-failed shape — leave **NO `schedule_executions` row for that tick**: their visibility is the **WARNING log only**. **R21 — DISCLOSED RESIDUAL (B1 worst case, CORRECTED): the in-memory episode clock.** For an episode whose DB carrier write (`_defer_since`) **persistently fails**, the age is also tracked by an **in-memory clock — a RAM-only, adapter-lifetime bound**: it is set **ONCE (never re-stamped)** and **retired on the first successful carrier write**. *(The pre-fix worst case — a plain overwrite re-stamping the clock on EVERY failed carrier write, so every fire reset the age and the cap could never trip on an untracked episode, an unbounded re-arm spin — is REMOVED by the set-if-absent fix; the adapter-lifetime bound is the accurate residual.)* **Disclose at promote.**

**R1 (architect) — count-fidelity race.** A claim lands between the guarded update's lookup and its execute → the delivered body lags by **exactly one occurrence**. Likelihood Med (ms per coalesced fire), impact **Low** (advisory content) — the authoritative `_defer_count` is exact. **R2 (architect) — one-shot duplicate via terminal-bypass.** The delivery *completes* inside the enqueue→consumption window + a crash + a re-fire → a duplicate alarm. Low likelihood (needs crash + completion in a ms window), Med impact (visible duplicate). Mitigation: consume immediately after the enqueue returns; a once-per-`run_at` guard (the `:544-556` pattern); disclosed in DEC-9/DEC-18.
**R3 (architect) — generation-marker staleness.** A crash between the enqueue-commit and the marker write → an orphan live delivery + a stale marker. Low/Low. Self-heals via the dedup-hit → **kept `message_id`** → guarded update path. Mitigation: the enqueue-fallback is the recovery mechanism; pin the crash-window test.
**R4 (architect) — terminate-after-enqueue destroys the deferred Task/MQ** (the terminate cascade deletes both) → a recurring loss until the next fire; a one-shot loss. Low/Med — **visible now** (DEFERRED row + count + WARNING) versus today's zero trace. Recurring alarms self-heal at the next fire; the terminate-aware hook is a **named follow-up lane**, out of scope here.
**R5 (architect) — semaphore re-arm hot loop.** High if the sleep is forgotten, Med impact (CPU spin, log flood). Mitigation: the **mandatory** `SCHEDULER_ERROR_RETRY_S` sleep (mirrors `:580-582`); the age cap bounds total spin; pin test. **DEC-22 sharpens the bound: R5's real bound is the semaphore being RELEASED *or* the 24h cap terminating the episode VISIBLY** — the cap is now reachable on the re-arm leg too (`_defer_since` set at the first re-arm deferral), so the re-arm loop is **bounded at 24h** instead of unbounded. **Blocking 3 generalizes this to EVERY leg**: `_defer_since` is the **non-delivery episode carrier** (set set-if-absent at the first non-consuming outcome of ANY kind — defer / re-arm / direct-failure / taskless-enqueue), and the 24h breach terminates the episode **visibly** (`consume` + terminal `failed` row, reason **`nondelivery_age_cap`** + WARNING) **on every leg without exception** — which also closes the **direct-path `failed`** leg that was bounded **by accident** (today's blanket `except` `scheduler.py:1028` → consume at `:624`) and would otherwise have spun at ~**17,280** rows/day **forever**.

**R11 — the stranded-generation hazard CLASS (Blocking 1, Note 1).** ANY `ready` MessageQueue row with **no PENDING Task** pins the generation — the question-pause marker window (`graph.py:10579-10595` → `instance_messaging.py:2246-2249` / `:2301-2309`, MQ row unconditional `:2182-2210`, no READY resume drain `:2221-2222`) is the **known instance**, but the class is **general** — any Task-less enqueue path produces the same stranded row, and the generation then **never rolls over** (DEC-18's rollover keys on `rowcount == 0`). **Mitigated** by the **per-delivery Task-match predicate** (Blocking 1): `deferred_durable` requires **a PENDING Task whose `message_id` equals this enqueue's id** (a per-instance pending task is a DECOY and does **not** qualify), a Task-less enqueue is `failed`/`taskless_enqueue` + MQ cleanup + re-arm, and **both the coalescing target and the `_defer_message_id` persistence are gated on the same check**. **Pinned** by `::TestTasklessEnqueue::test_marker_window_enqueue_without_task_is_failed_not_deferred_durable`.
**R12 — REGRESSION ASYMMETRY vs today (Blocking 1, Note 2 — disclose at promote).** Today a busy fire that cannot be delivered is **dropped** and the schedule **self-heals on the next fire** (the drop leaves no pin). Under the **pre-Blocking-1** plan a stranded generation would have **absorbed recurring fires silently** — converting today's **self-healing** loss into a **permanent, silent** loss, in exactly the D6 scenario. **R13 — a stranded `triggered` execution row has NO reconciler, BY DESIGN (Blocking 1, Note 3).** The **no-polling-loop** hard non-goal means there is **no sweeper** to repair an execution row left at `triggered`. The stranded `triggered` row itself remains for the operator: the intended, disclosed trade.
**R14 — `schedule_executions` has NO retention sweep (under-disclosure 3).** The table has **no** time-based cleanup of its own: rows die only with their **source row** (the cascade), and `cleanup_old` on the message queue touches only `message_queue` rows (`message_queue/repository.py:979-1002` — completed/failed only). **R9 — BEHAVIOR CHANGE (arm-time refusal, DEC-21).** A `self_alarm` whose **binding write fails** is **no longer armed unbound**: previously the arm succeeded with `wake_target_bound:false` (an alarm that would never wake its caller, and could **spawn a stranger** on a later fire); now it is **refused loudly** with a typed error naming the binding failure. **R10 — BEHAVIOR CHANGE (THE ABANDONED-ALARM CASES — plural, DEC-22 + DEC-9's cap block).** **Two** occurrences can be abandoned-and-consumed at the 24h cap: **(i)** a one-shot re-armed for ≥24h; **(ii)** a **durably-deferred** occurrence whose delivery is still pending when the cap trips (a `deferred_durable` occurrence is consumed-as-armed but **NOT delivered**, so the defer leg opens the non-delivery episode too). The alarm is **lost**, but it is lost **visibly and with a reason**, exactly once, instead of being retried silently forever. This is the **only** case in the design where the alarm is abandoned. **Disclose at promote.**

## (g) Rollback story

**No migration** → the rollback is a **single revert commit**. The additive enum member (`ExecutionStatus.DEFERRED`) and the four JSON keys in `source_configs.config` are **inert to the old binary** (it ignores unknown JSON keys; `ExecutionStatus.is_valid` is consulted only on the write path with values the old binary itself supplies; rows with `status='deferred'` are simply unknown to its readers). The two `SchedulingConfig` fields are **pydantic-settings, not DDL** (architect §16) → the migration delta stays **EMPTY**; `idx_job_idempotency` is unchanged (no DDL); `_tool_registry.py` and `agents/**` are untouched → the privileged-pin set and the prompt-artifact seal are unaffected. `rollback_safe = true` (source=explicit) — empty delta, so `=1` is delta-empty-legitimate (the standing rule on non-empty deltas is not triggered).
