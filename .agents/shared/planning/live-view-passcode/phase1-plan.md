# Phase 1 — Storage + Service Layer (migration, ViewPasscodeService, crypto primitives)

## 1. Objective

Land the durable passcode substrate WITHOUT touching any HTTP surface: one additive
migration creating `view_passcodes` + `view_passcode_audit` (grouped two-table precedent:
`daemon/migrations/versions/20261017_000001_create_secrets_tables.sql`), SQLModel rows in
the secrets repository pattern (`daemon/repositories/secrets/models.py:99`), and
`ViewPasscodeService` with mint / verify / lock / refresh / audit — Fernet-encrypted at
rest (D1), constant-time compare, fail-closed on missing `SYSTEM_ENCRYPTION_KEY`, atomic
mutate+audit in one `engine.begin()` (exemplar: `daemon/services/secret_service.py:846-864`,
`_append_audit_in_conn` `:1015-1063`). Exit: unit suite green, zero router/tool changes.

## 2. Decisions

| ID | Decision | Rationale (anchors) | Rejected alternatives |
|----|----------|---------------------|------------------------|
| D1 | Passcodes stored Fernet-ENCRYPTED at rest via `SecretCipher` pattern; verify = decrypt once + `hmac.compare_digest` on casefolded strings | Plaintext-at-rest forbidden by requirement 9; `SecretCipher` (`daemon/services/secret_service.py:228-361`) is the proven fail-closed in-repo cipher; zero new deps | bcrypt/argon2 hash-only — INFEASIBLE: requirement 2 forces plaintext re-display on every `view_link` call (D6 deviation entry); reversible encryption is the minimum that satisfies both |
| D2 | One passcode row per `(root_name, rel_path)`; mint idempotent (return existing); `generation` int bumped on refresh | Requirement 7 lazy-mint + leader ruling "idempotent default"; generation bump kills outstanding grant cookies without a session table | Per-mint unique rows (row explosion, breaks idempotency); server-side grant table (leader ruled stateless grants) |
| D3 | Lockout = durable `failed_attempts` + `locked` flag on the row; persist-until-regenerate; NO time-boxed auto-unlock | Requirement 4 + leader ruling (spec default, not deviation); PG-backed via the same row | In-memory strike counter (lost on restart — requirement 4 says DURABLE); time-boxed unlock (would be a flagged deviation; not taken) |
| D4 | Passcode alphabet: 31-symbol unambiguous set `23456789abcdefghjkmnpqrstuvwxyz`, 6 chars, `secrets.choice` (crypto RNG), case-insensitive entry via `.casefold()` normalization | Requirement 1 (alnum, unambiguous, case-insensitive); 31^6 ≈ 8.9e8 ≈ 29.7 bits — ample under a 10-strike durable lock; excludes 0/O/1/I/l | Full 62-char alphabet (0/O/1/I/l confusion for humans reading codes aloud); longer codes (UX cost, no security gain under the lock) |
| D5 | Audit rows written in the SAME `engine.begin()` transaction as the mutation; `ip_hmac` = `HMAC-SHA256(ip, key)[:16 hex]` where `key` is a DOMAIN-SEPARATED derivation from `SYSTEM_ENCRYPTION_KEY` (HKDF `info="live-view-audit-ip-v1"` or `SHA256(SEK \|\| "live-view-audit-ip-v1")`) — NEVER the raw Fernet key as HMAC key (ADR D9:116). Rotation caveat: key rotation breaks cross-period IP correlation by design (raw IPs never stored; re-computation impossible) — noted in the rotation ceremony alongside the `wrapped_passcode` re-encrypt walk | Secrets precedent (`secret_service.py:846-864` atomic idiom); requirement 8 minimal durable log; keyed HMAC gives rotation-unlinkability + prevents forgery, where unsalted sha256 leaks /24 topology and is replayable across periods (ADR-rejected alternatives) | Separate audit write (torn state on crash); raw IP mandatory (privacy; requirement 8 says optional/hashed); unsalted `sha256(ip)[:16]` (SUPERSEDED by ADR D9 — leaks topology, forgeable, rotation-linked) |
| D6 | DEVIATION (flagged, reasoned — requirement 9 said "NOT plaintext at rest" and the hashed-at-rest suggestion is overruled here): tool result returns PLAINTEXT passcode at mint; at-rest form is Fernet ciphertext | Requirement 2 ("view_link ALWAYS includes the passcode") makes hash-only storage impossible — a hash cannot be re-displayed; encryption (not hashing) is the weakest at-rest primitive compatible with re-display | Hash-only + re-mint on every call (breaks idempotent-return ruling D2/leader); storing plaintext (worse than ciphertext, no benefit) |

## 4. Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC1 | `generate_passcode` emits 6-char codes from the D4 alphabet; `codes_match("AbC-23j", "abc23j")`-style normalization passes; comparison goes through `hmac.compare_digest` |
| AC2 | Migration file exists (ONE file, both tables), applies on fresh SQLite w/ F1 premark, and a parity test proves model ↔ DDL column agreement |
| AC10 | The 10th consecutive wrong verify attempt sets `locked=1` durably (proven across service re-instantiation on the same DB); no auto-unlock path exists in the service |
| AC11 | `refresh` regenerates the passcode, increments `generation`, zeroes `failed_attempts`, clears `locked`, and writes a `refresh` audit row |
| AC13 | With `SYSTEM_ENCRYPTION_KEY` absent, service construction fails closed with a typed error; no code path decrypts or mints without it |
