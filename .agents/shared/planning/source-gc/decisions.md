## D1 — Executions disposition vs FK physics — **FINAL: additive archive migration, copy-then-delete same-txn — minus the `credentials` column (AM-4), plain-INSERT archive PK policy (AM-3), race-safe txn (AM-1)**

**FINAL ruling (architect SP-4):** planner shape CONFIRMED — both tables (`schedule_executions_archive` + `source_configs_archive`), NO FK to existing tables, TEXT-only strings, unbounded retention with a written trip-point follow-up. Two amendments change the table/method spec:

- **AM-4:** drop `credentials` from `source_configs_archive`. Evidence (architect-verified): scheduler rows carry `credentials=None` always (zero credential references in the scheduler adapter); chat credentials that exist are Fernet ciphertext at rest (routers/sources.py:257 encrypt-before-insert) and can never enter this GC's reachable set. Always-NULL column = pointless second secret surface the scrub families don't know. Zero forensic loss. (Resolves the planner's council flag — no masking debate needed: the column does not exist.)
- **AM-3:** archive PK insert = **plain INSERT, fail-loud — NEVER `ON CONFLICT`**. The id collision is REACHABLE, not structural: the generic REST create path accepts `source_type="scheduler"` with a caller-supplied `source_id` (routers/sources.py:135-165; "scheduler" in supported_types :153; `create_source_config` honors caller ids). `ON CONFLICT DO NOTHING` would silently keep the STALE archive row and drop the fresh snapshot — audit corruption worse than a wedged row. Correct handling: `IntegrityError` → per-row defensive catch → WARNING naming the source_id ("archive id collision — stale archive row for a re-created source") → skip+count, sweep continues (per-source txn bounds blast). **W3 — per-source-id first-warning LATCH (plan council, binding):** without it, a re-created caller-supplied id colliding with an archived terminal row becomes PERMANENTLY UNCOLLECTABLE — hourly re-attempt + skip+WARNING ≈ 24 noise lines/day forever. The GC keeps a module-level `set` of already-warned source_ids: FIRST collision for an id warns loudly (and counts), subsequent ticks for the SAME id count SILENTLY (no log line). **Operator-resolution note extended (W3):** the operator resolves a collided id by re-creating with a FRESH id or purging the stale archive row (the latch resets on daemon restart — acceptable; the id-set is bounded by collided rows only).
- **AM-1 (CRITICAL):** the delete txn is RACE-SAFE — see D6. **Advisory A (plan council, BINDING hardening) folded into the method spec:** the final `DELETE` additionally pins the locked row's `updated_at` (`AND updated_at = :locked_value`) — on SQLite (where `with_for_update` renders no lock, instance/repository.py:1949-1954) this closes the residual micro-window (a resume re-stamp between the locked read and the delete makes the DELETE match 0 rows → raced-skip), and it gives the P16 re-assert mutation a SECOND teeth source.

Retained rationale: ADR-012 doctrine tension (cancel never purges history — repository.py:474-478 docstring, routers/sources.py:442-450 guard comment); phantom-queued ledger lowers diagnostic value but not existence value (`triggered_at` survives); FK physics (models.py:113/:168, NOT NULL, NO ACTION) make child-first mandatory regardless; additive CREATE TABLE IF NOT EXISTS = house rollback-safe class; FK relaxation rejected (ALTER on hot table). Approach scores (SP-4): planner shape 4.20 ✔ / scalars-only 3.90 ✘ (tombstone list — config snapshot is the only reconstruction input; update-of-missing raises) / full-row JSONB 3.10 ✘ (violates TEXT-only standing rule). Archive retention: unbounded + trip-point 4.80 ✔ (bounding it = GC-of-GC deletes the evidence D5 promised — the no-trace complaint returns one level up); trip-point **~50k rows / ~50 MB / first slow forensic query** — routed follow-up §9.

## D6 — Bulk delete method + REST surface — **FINAL: CONFIRMED as planned, hardened by AM-1 (race-safe txn), AM-2 (oldest-first), AM-9 (two-write crash-window pin); REST untouched**

- **AM-1 (CRITICAL — gates implementation entry):** in-txn predicate re-assert + row lock in `gc_archive_and_delete`. WHERE enabled=false AND status IN (...)` with rowcount-0 → raced-skip. - **AM-2:** `gc_find_candidates` orders `updated_at ASC` (oldest-first) — batch-cap remainder deterministic, newest rows defer.
