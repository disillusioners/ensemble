## Objective

Establish the **DB-backed prompt-version layer** so that a runtime prompt for an agent is resolved by `effective = selected_version > latest_approved_version > template_file`, with `.md` files under `agents/<agent>/` becoming **immutable base/template content** (runtime writes fail loud). The migration + SQLModel + repository + service + cache-invalidation + loader-hook + writer-guard pieces all land together so that **a spawn, a checkpoint-restore, and a message-reconstruction all resolve the same DB-versioned content** (F9), not whichever file happens to be on disk.

The phase-A outcome is testable as one sentence: **an agent whose `agents/<x>/soul.md` is deleted from disk still spawns with the same prompt it had before, because the resolution service returned the latest-approved DB version; runtime write attempts against the versioned artifact files raise a fail-loud refusal the agent can act on; and the SQLite/PG parity test plus the three named resolution-path tests pass on both engines.**

8. **Immutability guards** at every agent-facing write site that targets `agents/<name>/*.md`:
   - `daemon/tools/filesystem.py:write_file` (line 882-905) — guard inside/after `_resolve_within_workdir` (line 889) covering BOTH absolute and relative paths (closes the absolute-path bypass at `filesystem.py:205-209`).

   - `daemon/tools/agent_mother.py:agent_modify` (line 349-393) — shrink `modifiable_files` (line 359) to only artifacts carved out as non-versioned (per artifact-disposition fork below); the versioned-immutable subset returns the same refusal shape used today.

Phase-A closes the drift window by routing restore through the SAME resolution hook as spawn — a restored instance sees the resolved version, not the on-disk file mtime.
10. **Three named resolution-path tests + SQLite/PG parity + guard bypass tests + no-override no-regression** in `tests/test_prompt_version_resolution.py`.

## Forks (design alternatives)

This phase A locks the following forks per the dispatch. Each fork shows the chosen default + the alternative + rationale.

| Fork | Decision (Phase A) | Alternative | Rationale |
|---|---|---|---|
| **F1** | **Overrides-only** in DB. Template file stays the live fallback. First override per `(agent, artifact)` = v1. No full-content seeding in Phase A. | Full-content seeding (each new agent automatically gets v1 = current file content as a DB row) | Conservative default. Seeding is a Phase B convenience that can ship without schema rework because the schema supports both empty and populated version tables. Avoids migration cost when agents have no overrides. |
| **F3** | **Monotonic integer version** per `(agent_id, version_tag, artifact)`. "Latest approved" = `max(version)` where `state='approved'`. DB-side `UPDATE col = col + 1` for atomic bump (precedent `skill/repository.py:26-31, :102-116`). | Timestamp-based (`created_at`); UUID-based | Integer is closest to skill-evolution precedent (`Skill.generation`, `skill/models.py:44-49`). Atomic counter prevents the same race as R3. |
| **F5** | **Explicit user-settable selection pointer** per `(agent_id, version_tag, artifact)` via `is_selected` flag with repo-enforced one-pointer invariant. | Pointer row table; NULL-unique constraint | Repo enforcement is mandatory because NULLs are distinct in UNIQUE on both drivers (research §1). The flag-toggle pattern matches `Skill.is_active` (`skill/models.py:93-97`). |
| **F6** | **Precedence: `selected_version > latest_approved > template_file`**. Draft / pending_approval / rejected versions NEVER affect the effective prompt. | Include pending versions for preview; include rejected versions with debug-flag | Conservative: only approved content enters the prompt. Drafts are user-edited and unverified. Pending versions await human approval. Rejected versions are kept for audit but never execute. |
| **F8** | **Runtime write attempts against the versioned artifact `.md` files FAIL LOUDLY.** Refusal shape: typed error string `ERROR: REFUSED — {artifact} is an immutable prompt artifact for agent '{name}'; submit a prompt-version draft via the prompt-versions API instead. (file_path=…)`. | Silent drop; warning-only | Log-only | Fail-loud matches the project's fail-closed convention (upgrade lane, RAG authorization, WorkspaceGuard). Agents must be able to act on the refusal; an "agent contract" they can branch on is the only way the API substitution works in practice. |
| **F9** | **DB versions keyed by resolved agent identity `(agent_id, version_tag)`** so a tagged copy's overrides never leak into the base agent and vice versa. PromptCache invalidation extended to honor the version-tagged cache key (today's `invalidate(agent_id)` sites are base-key-only — known bug; Phase A fixes them at `agent_mother.py:380` and `inner_soul.py:1088/:1162/:1247/:1304/:1336`). | **Agent-id-only** with tag folded into artifact key | Reject: with agent_id-only, a `developer[v2]` override would silently match `developer` lookups because both share the same `agent_id`. That breaks the version-fork invariant. D15 + D16 from agent-versioning prior art establish version_tag as a first-class key dimension; F9 extends. |
