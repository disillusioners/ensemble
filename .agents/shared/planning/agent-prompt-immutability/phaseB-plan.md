## Objective

Turn the DB-versioned prompt layer Phase A lands into a fully working **submit → review → approve → effective** pipeline, with `inner_soul` and `agent_mother.agent_modify` re-routed to submit DB drafts (never file writes), the full approval REST surface exposed (human-only approve/reject, agent-lane submit/retract, selection control), and the inner_soul classification/redirect/reject grammar + memory landscape preserved verbatim. Outcome is testable as: an agent calling `inner_soul(target="soul", request="...")` produces a `pending_approval` row visible at the HTTP API; an authenticated human operator can approve it; subsequent `load_and_cache_prompt` calls return that approved content (not the file); the file-on-disk `soul.md` remains untouched; no inner_soul test that passed before Phase B regresses; the memory landscape (memories/, memory.md, RAG KB, user.md) keeps the same read/write paths it has today.

## Scope

### In Scope

1. **Approval service** — transition table, guards (human-only approve/reject, agent-lane submit/retract), append-only approved rows, audit events stamped from `AuthContext.subject`/`auth_method` and from internal lane sender identity.
2. **REST API** — full endpoint set: list versions (filters, pagination), get version + diff vs effective, approve/reject (human-lane enforcement), set/clear selection, agent-lane submit/retract, audit log read. Auth-OFF posture fail-closed. Scope names minted.
3. **`inner_soul` rewrite** — `soul` / `workflow` targets submit DB drafts (auto-submit to `pending_approval` by default; user/admin retraction after submit; re-submit after reject). `soul` history audit file → DB revision log. `user.md` joins the DB version model as a submittable persona artifact (NOT prompt-loaded). `memory` / `memories` targets UNCHANGED (file-based carve-out). ALL classification, redirect, reject, compound-split, RAG dual-state, redirect-before-reject, version-aware targeting semantics preserved. `invalidate(agent_id, …, version_tag)` threading fixed at all 5 sites.
4. **`agent_mother.agent_modify` disposition** — rewire to DB draft submission matching inner_soul semantics (NO direct file writes to versioned artifacts). Preserved exceptions: `agent_create` template copy, `routers/agents.py` POST template copy, `agent_delete` → `_trash`.
5. **Memory reconciliation table** — artifact → store → owner mapping; no double-store, no loss; carve-outs explicit.
6. **Seeding mechanics (F1 default)** — OVERRIDES-ONLY: template file stays the live fallback; first override per `(agent_id, version_tag, artifact)` = version 1; NO boot-time full seeding. Document the rejected alternatives (full-seed-at-boot, hash-guarded-lazy-seed) for morning review.
7. **Test strategy** — transition happy+illegal paths, human-vs-machine approval enforcement, inner_soul semantics parity (classification/reject/redirect pinned by tests), 28-agent no-regression, memory flows unchanged, auth-OFF fail-closed, dual-driver (SQLite+PG) parity.
8. **Tasks with file:line anchors**, dependencies, risks, acceptance criteria. Standard plan template.
