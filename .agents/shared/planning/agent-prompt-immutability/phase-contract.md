| **A5** | Service-level composite (per S15) | `create_and_submit(agent_id, version_tag, artifact, content_or_mutator, actor)` = `create_draft` + `submit_for_approval` in ONE `to_thread` call — the **CORE submission path** `inner_soul` (`:1237/:1295/:1327` for soul/workflow) and `agent_mother.agent_modify` (`:377`) use. Carries the **C4 composition rule**: `draft.content = f(get_effective(...), request)` — compose on the EFFECTIVE chain (selected > latest_approved > file), then apply the target-specific mutation (soul replace/append, `Learned:` append); consecutive un-approved calls chain on `max(version) WHERE state IN ('draft','pending_approval')`; a new draft **archives the prior pending row** (≤ 1 active pending per key). **(amended 2026-10-14, A5 journal, User Directive #3 SURFACES layer — dispatcher-approved post-hoc, morning-ratification pending)**: ``create_memory_version(agent_id, version_tag, artifact, content, actor)`` is the **MEMORY-class creator** — transition-free, born-effective at ``state='approved'``, ONE ``CREATED`` audit row stamped with ``payload.artifact_class='MEMORY'`` and ``via='create_memory_version'``. The class-aware dispatch picks the creator by ``class_for_artifact(artifact)``: CORE → ``create_and_submit``; MEMORY → ``create_memory_version``. The MEMORY creator does NOT carry ``file_fallback`` (transition-free; the row IS the live state; the on-disk file is the cold-boot F6 fallback only). **(amended 2026-10-14, A5 journal, leader-gate F5 — dispatcher-ratified, morning-ratification pending)**: the **composition base for the mutator path** is the **prior active (draft|pending) row's content** when one exists for the same key — NOT :meth:`get_effective`, which EXCLUDES pending rows. Only when no prior active row exists does the base fall through to the F6 effective chain (``get_effective → file_fallback``). Formula: ``base = prior_active.content if present else get_effective() else file_fallback``; the resolution happens INSIDE the ``engine.begin()`` block under the per-key advisory lock so the read is consistent with the INSERT. **Rationale** (closes the F5 regression): composing on ``get_effective``-only made approval a content-regression path — two consecutive un-approved mutator submissions on a CORE key (e.g. ``soul``) landed ``v2.content = f(template) + delta₂`` and approving ``v2`` silently lost ``delta₁`` (the exact regression the C4 "two calls = two appends" intent exists to prevent). The prior-active base preserves ``delta₁`` through the pending window; ``get_effective`` stays correct for the **no-prior-active** branch (first submission, post-approval re-submission). The ``str`` content path is unchanged. MEMORY-class rows are unaffected — ``create_memory_version`` is transition-free and not part of this path. |
