## 0. Context (what shipped, what is unproven, why this phase exists)

**Shipped.**
- **Phase A/B** — the center gateway: WS route (`daemon/api.py:4563-4600`), protocol vocabulary (`daemon/services/mcps_gateway/protocol.py`), the center (`service.py`, 1167 L), session lock (`sessions.py`), in-memory roster (`store.py`), the DB audit ledger (`daemon/repositories/mcps_gateway/` + `daemon/migrations/versions/20261022_000001_create_mcp_gateway_audit.sql`), the four agent tools (`daemon/tools/mcp_rpc_tools.py`). Merged `@ 9632badd4`.
- **Phase C** — the operator read surface (`daemon/routers/mcps_gateway_read.py`, 3 OAuth endpoints) + the Angular "Remote Hands / MCP Gateway" page (`frontend/src/app/pages/mcps-gateway/`). Merged `@ 9632badd4`.

**Unproven (the reason this phase exists).**
1. **The shipped Go client has NEVER spoken to this center.** The only peer is `tests/integration/mcps_gateway/fake_remote_client.py` — 855 L, **zero `daemon.*` imports**, transcribed from the SPEC alone (`harness.py:8-16`). "Works with our fake" ≠ "works with theirs".
2. **Audit rows have never been proven to reach a database.** The suite boots `lifespan="off"` (`harness.py:209`) ⇒ no `mcp_gateway_audit` table (`daemon/api.py:1003-1004`) and no manager-built sink (`daemon/manager.py:1453-1456`); the harness injects a `MemoryAuditSink` (`harness.py:187,192-193`) and the only audit assertion reads `audit_sink.records` (`test_mcps_gateway_protocol.py:1087-1113`). `COVERAGE.md:116-117` records that only the repository **constructor signature** was consulted.
3. **The route is boot-time-only and OFF by default** (`MCPS_GATEWAY_ENABLED` default false, `config.py:164`; route registration `api.py:4566`) ⇒ an OFF daemon answers **404** on the upgrade, which the client treats as transient ⇒ reconnect loop; a **401** is fatal (`daemon/routers/mcps_gateway.py:299-307`, `internal/remote/client.go:525-530`).
4. **Three read-surface defects** (§ D2/D3 below): a DB outage is **byte-identical to an empty ledger** (`repository.py:95-97` + `service.py:772-776` both swallow); a `status===403` is always labelled `SCOPE_INSUFFICIENT` (`mcps-gateway.service.ts:340-347`); audit paging has an unstable tie order (`repository.py:89`).

**Why Phase D1.** Convert *"probably conforms"* into *"proven against the shipped client, with the ledger proven in a real database"* — and close the three correctness riders before the gateway is ever activated.

**What Phase D1 does NOT do.** No gateway protocol change, no new center feature, no client change (the `mcps_client` repo is READ-ONLY), no activation.

**Design.**

1. **TLS material.** Per-run self-signed cert generated into a `tmp_path`:
   `openssl req -x509 -newkey rsa:2048 -nodes -days 1 -keyout key.pem -out cert.pem -subj "/CN=127.0.0.1" -addext "subjectAltName=IP:127.0.0.1"`.
   The client trusts it via `remote.ca_pem: <path to cert.pem>` (the client accepts a **path**, `config.go:239-241`); a pin is **optional** and does not replace chain verification (`transport.go:283-303`) ⇒ **do not** set `server_pin_sha256` in the primary fixture (avoid a second failure mode), and pin it only in a dedicated kit check.
2. **Server boot.** `create_app()` with the **real lifespan ON** (AD3): `uvicorn.Config(app, host="127.0.0.1", port=0, ssl_certfile=cert, ssl_keyfile=key, lifespan="on", log_level="warning", access_log=False)`; port read from `server.servers[0].sockets[0].getsockname()[1]`. Consequences that must be asserted, not assumed: the `mcp_gateway_audit` table exists (`daemon/api.py:1003-1004`); `app.state.mcps_gateway_service` is the **manager-built** service with the **DB** sink (`daemon/api.py:2401`, `daemon/manager.py:1453-1456`); the WS route is registered (`api.py:4566`, path `config.py:52`).

   **The disposable PG cluster (four traps, each fatal if missed).**
   - **`initdb -A trust -E UTF8 --locale=en_US.UTF-8`** — **NOT** `--no-locale`. A C-locale cluster makes psycopg3 return `pg_catalog.version()` as *bytes* and SQLAlchemy 2.0.48 crashes in `_get_server_version_info` with `TypeError: cannot use a string pattern on a bytes-like object`. (`C.UTF-8` is not installed on Homebrew; `en_US.UTF-8` is.)
   - **Postgres is MANDATORY — SQLite cannot boot.** The migration `daemon/migrations/versions/20260714_000001_widen_job_queue_type_constraint.sql` emits a PG-only `ALTER TABLE ... DROP CONSTRAINT IF EXISTS` ⇒ a fresh SQLite boot dies (W7: the observed text is `OperationalError near "EXISTS"`, not `near "CONSTRAINT"` — the conclusion is unchanged; and the migration's own header `daemon/migrations/versions/20260714_000001_widen_job_queue_type_constraint.sql:26-31` **falsely claims dual-driver support** — worth a one-line correction when that file is next touched). The research note "SQLite works, with caveats" is **refined** by this: do not use SQLite for this lane.
   - **Pre-seed `<data_dir>/ensemble.json` = `{"database":"postgres"}`** to FORCE the backend — auto-detection (`daemon/ensemble_config.py:82-89`) depends on the *inherited* shell's `POSTGRES_HOST`/`POSTGRES_DB`, which is exactly the thing that must not be trusted. (Pre-seeding is stronger than "the file must not exist", and it pins the backend rather than inferring it.)

> **Recommended amendment (§8.4).** §8.4 says "args hashed" and names neither an algorithm nor a canonicalisation. ## 4. Test strategy

**Lanes and mechanics.**
- `pytestmark = pytest.mark.integration` on every new test file — the default `addopts = "-m 'not integration and not postgres and not slow'"` (`pyproject.toml:86-97`) **deselects** them; run with `-m integration` or `--override-ini="addopts="`.
- Per-test timeout **30 s**, thread method (`pyproject.toml:96-97`). The real-pair test uses a **named compressed profile** (S5) — `MCPS_GATEWAY_HEARTBEAT_INTERVAL_MS=500`, `MCPS_GATEWAY_HEARTBEAT_TIMEOUT_MS=1500`, `MCPS_GATEWAY_CLIENT_DEAD_DETECT_MS=1500`, `MCPS_GATEWAY_COMMAND_TIMEOUT_MS=1200`, `MCPS_GATEWAY_READ_TIMEOUT_MS=500`, `MCPS_GATEWAY_SESSION_TTL_MS=60000`, `MCPS_GATEWAY_SESSION_IDLE_TIMEOUT_MS=30000`. Kill window: the monitor sweep runs at `min(interval, timeout/10)` (`service.py:191-192`) ⇒ ≈150 ms granularity ⇒ assert the kill within `[timeout, timeout × 2]` = **[1.5 s, 3 s]**. Client side: `remote.reconnect_initial_backoff_ms=250`, `remote.reconnect_max_backoff_ms=2000`, `remote.tool_call_timeout_ms=5000` (`internal/config/config.go:334-336`) so the **center's** arm wins the timeout race and the client's backoff does not eat the 30 s budget. The **heartbeat advertisement** assertions (§D1 #5) must read the **advertised** values, not the compressed ones; and the compressed values must satisfy the client's own validation (`heartbeat_timeout_ms ≥ 3 × interval`, `internal/remote/client.go:651-665`) or the client adopts them with a warning — pick `500/1500` deliberately, not arbitrarily.
- Env scrub: `scripts/run_tests_scrubbed.sh` (unsets `POSTGRES_*`, `DATABASE_URL_POSTGRES`, `POSTGRES_URL`, the bare libpq set; echo-verifies **zero** survivors; exits **78** on leak; `exec .venv/bin/pytest "$@"`, `:25-95`). It deliberately does **not** touch `PG_TEST_*` (`:36-40`).
- Dev-DB fence: `POSTGRES_DB` must be `ensemble_dev_test_only` / `ensemble_test_only` / unset; anything else ⇒ `pytest.exit(returncode=1)` (`tests/test_resource_monitor_api.py:47-63`). **The rewrite does not create the database** — `ensemble_dev_test_only` must actually exist (`.agents/tester/QUARANTINE.md:141`). **That fence is PER-MODULE, not a lane guard** — it fires only in the modules that copy it, so it protects nothing here. The harness's own engine assertions (R-16/R-17: pre-seeded backend, Postgres dialect, disposable DB name, engine identity) carry the **entire** burden of keeping this lane off prod.
- **Regression gate (Rev-2 — the numbers, collected via `pytest --collect-only`):** the `tests/integration/mcps_gateway/` **package** is **34 tests** (**35** post-P0, with `test_p0_gate.py`); the **three named unit files** collect **27 + 9 + 53 = 89 tests** (`test_mcps_gateway_read.py` 27, `test_mcps_gateway_audit_repository.py` 9, `test_mcps_gateway_service.py` 53 — parametrization makes collected ≫ defined). All must stay **green** — they are the regression gate for D2/D3 (the projection helper and the degraded envelope both touch the same read path), plus `tests/unit/test_mcps_gateway_docs.py`. **The 34-test package passing is necessary but NOT sufficient evidence for D2 — it does not assert the three envelope key sets, so `tests/unit/routers/test_mcps_gateway_read.py` must be run EXPLICITLY as part of the D2 gate** (it is where the exact-shape pins of §2.D2.1 live).
- Quarantine ledger: `.agents/tester/QUARANTINE.md` — any new environmental red is appended with (a) the exact node scope, (b) base-vs-branch attribution, (c) the deselect/workaround, (d) a retry budget.
- **Dual-layer timeout.** Outer `timeout 300` around the pytest invocation; inner `--timeout=30` per test (`pyproject.toml:96-97`). One layer alone is not enough — a hung client subprocess can defeat a single timer. The outer layer must actually **interrupt** (the `timeout` command or `subprocess.run(timeout=…)`), never a post-hoc check.
- **Deselect proof.** Verify that a default run (no `-m`) reports **`N deselected`** for the new packages — a package that is not actually deselected will silently pollute the default unit lane.
- **Package-scoped runs only** — never the full suite. **Run the new packages twice and confirm the same set of failures** (stability), and record the actual runtime of each run.
- **Reporting format** (per the house rule): one line per test — name + PASS/FAIL + **FINDING vs CLIENT-BUG**; every deviation quoted with a transcript excerpt; the actual runtimes; the explicit independence attestation; and any transient observation that self-resolved during the run (with the time it changed) noted rather than dropped.
- **Kit runner teardown.** `scripts/conformance/run.sh` owns the process lifecycle: `trap` on TERM/INT **and** EXIT, kill the **listener** PID (not `$!` — on macOS that is the wrapper), and verify the port is released with `lsof`.

> **Deviation note (2026-10-22, QA fix round).** As shipped, the runner does NOT use GNU `timeout(1)` and has NO `lsof` port probe: the outer bound is a portable bash watcher (sleep the budget → TERM → 5 s grace → KILL; 137/143 collapse to 124 only when the watcher actually fired — an OOM kill is not masked; the watcher is reaped on the normal path too), and the `lsof` probe was dropped as unreachable (it ran after `wait` had reaped the pid). C9's bound is TWO-LAYER as planned — request-level `asyncio.wait_for` + transaction-local `SET LOCAL statement_timeout` — but both layers share ONE millisecond budget through the single `load_gateway_config()` object rather than two knobs.

**How the OUTAGE SHAPE is proven (not just the healthy shape).** Three complementary constructions, all asserting the **wire body**:
1. **Dead engine.** Build a `McpGatewayAuditRepository(engine=<engine pointing at a closed/unreachable DB>)` and install it as the service's sink ⇒ `list_recent` raises ⇒ assert the audit endpoint body is `{"audit": [], "count": 0, "limit": 50, "offset": 0, "gateway_enabled": <flag>, "degraded": true, "error": "<short code>"}` — **200, not 500 and not 503**.
2. **Monkeypatched reader.** `monkeypatch.setattr(repository, "list_recent", raising)` ⇒ the same body via the service classification path (AD5) ⇒ proves the classification lives in `audit_tail`, not in the router.
3. **Unreachable-DSN engine** (replaces the earlier `engine.dispose()` construction, which was a **false premise** — `dispose()` merely refreshes the pool and the next read **succeeds**): build the sink on `postgresql+psycopg://127.0.0.1:1/ensemble_dev_test_only` (port 1 ⇒ connection refused, deterministically, no external service).
4. **Hung reader (B2) — the class constructions 1-3 do NOT cover.** The read is unbounded today, so a hung DB **hangs the request** and `degraded` never fires. Two parts: (a) the D2 implementation wraps the read in `asyncio.wait_for(..., MCPS_GATEWAY_READ_TIMEOUT_MS)` classifying `TimeoutError` ⇒ the same degraded body; (b) `test_audit_read_degraded_on_hung_reader` — the reader sleeps **10× the timeout** ⇒ assert **200** + `degraded:true` + `error` set + the **elapsed wall time bounded** by the timeout (not the sleep).
Plus the **repo-layer raising test** `test_audit_repository_raises_when_engine_dead` — the repository must **raise** (AD5 removed the swallow), asserted directly against a dead engine, so the classification contract cannot silently re-absorb the exception.
Plus the **consistency** assertions: `GET /machines` and `GET /sessions` answer `200` with `degraded: false` **and** `gateway_enabled` unchanged (orthogonality), the three envelopes **all carry** the `degraded` key (symmetry), and the FE renders a degraded banner **without** clearing the last audit page.
**Negative controls** (so the test cannot pass vacuously): a healthy read asserts `degraded == false`; a **write-only sink** (`NullAuditSink`, `audit.py:128-132`) asserts `degraded == false` with an empty list — a write-only sink is **not** an outage; `gateway_enabled == false` asserts `degraded == false` (disabled ≠ degraded).
**FE staleness under degradation (W8)** — prose-only today, so it gets a real test: flush a **healthy** audit page, then flush a **degraded** body ⇒ the **previous rows are still rendered** **and** the degraded banner shows. Mechanism (as shipped — `mcps-gateway.service.ts`, `fetchAudit`'s `res.degraded === true` branch): a degraded **200** takes an EARLY RETURN in the `tap` — the rows, the offset and the pager state survive untouched, the degraded flag rises and the error slot clears; the **error** lane also keeps the last page (`catchError` never touches the rows signal). Both lanes are therefore asserted as *rows survive + banner*, with the banner kind (degraded vs error) telling them apart.
