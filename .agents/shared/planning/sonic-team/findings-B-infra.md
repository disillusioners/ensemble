## 2. ONE-SHOT CODER MECHANICS — VERDICT: PARTIAL

**Multi-turn missions are effectively unbounded; a single sustained turn has three real ceilings — recursion budget (live 300, prod-proven), the 125-min task cap, and per-request timeouts. The loop breaker is NOT a risk for legitimate coding loops.**

### 2a. Loop breaker — safe by construction 🟢
- **Identity = tool NAME + canonicalized ARGS, not name-only.** `_compute_tool_signature` (`daemon/graph.py:1403-1423`): per AIMessage, sorted set of `name:<json.dumps(args, sort_keys=True)>` pairs joined `|`. Different bash commands ⇒ different signatures; parallel batch = one signature. Error direction is safe (can miss near-duplicates like trailing-space diffs, never conflate distinct commands).
- **Trigger = 3 CONSECUTIVE identical-signature units from the tail** (`graph.py:1499+, :1522-1532`, `LOOP_BREAKER_DEFAULT_THRESHOLD=3` `graph.py:197`, `LoopBreakerConfig` `daemon/config.py:6524-6530`). Any non-tool message (Human/plain-AI/System), any excluded-tools unit (`:1463-1465`), or a watchover-denied batch (`:1469-1502`) breaks the chain. Identical calls elsewhere in history don't count.
- **On trigger:** oldest duplicate unit KEPT as evidence (`:1534-1541`); newer duplicates removed; LLM repair summary prepended as SystemMessage (`:1847-1859`); injected HumanMessages re-appended. **In-memory only — checkpoint keeps original history** (`:1706-1716`). Budgets: per-turn `max_repairs=3` + durable `SYMPTOM_REPAIR_BUDGET=3` (`config.py:6528`; `daemon/services/symptom_repair_engine.py:85`); exhaustion → **loud turn-terminal** (instance survives; `graph.py:2507-2537`). Escape hatches: `LOOP_BREAKER_EXCLUDED_TOOLS` (default empty), `LOOP_BREAKER_ENABLED` kill switch.
- **False-positive analysis:** 15 sequential bash calls with different args — never triggers. Repeated edit_file on different files — never. Same `pytest -q` 5× *between* fixes (fix = different-signature unit) — chain resets each time, never. **Only exact-same-call 3× strictly back-to-back triggers — and it's non-fatal** (evidence kept, nudge prepended). Verdict: a legit build/fix loop will NOT false-positive. 🟢

- **Live effective:** worker/coder/designer/critic ×7 ⇒ **2100 steps**; developer/planner/architect/explorer/reviewer (no key) ⇒ **bare 300** (LIVE tree check matches origin/latest: `agents/coder/meta.json:19`, `agents/worker/meta.json:12`).

## 4. INSTANCE KEEP-ALIVE / REUSE — VERDICT: EXISTS (bounded)

- **Revive:** send_message to COMPLETED/TERMINATED/ERROR/FAILED → RUNNING via the durable enqueue lane (`daemon/services/instance_messaging.py:2560-2577`; A1 carve-out `:2433-2463`). Preserved: instance row, full message history, LangGraph checkpoint, instance_metadata. **Fresh turn over full checkpoint context — not mid-turn resume** (is_retry-checkpoint-resume is the PAUSED path). Revive-once guard: agent-tool path only, ERROR/FAILED-prior consumes an in-RAM budget (`daemon/manager.py:1707, :5240-5267`; refusal `daemon/tools/instance.py:5001-5006`); COMPLETED/TERMINATED revives are **free and unlimited**. Revive is cheaper than spawn (no create/prompt assembly) but the transcript only grows — turns get slower; a warm-started fresh instance carries bounded context instead.
- **Cap:** `max_children_per_instance = 50` per parent (roots exempt — `daemon/config.py:624`, `instance_lifecycle.py:2081-2090`). **No global total/concurrent instance cap.** (The "100" is `graph_recursion_limit`'s repo default, not an instance cap; `instance_cap=50` at `config.py:1036` is a metrics-sampler row cap.)
- **GC:** 24h maintenance sweep — terminal instances older than 168h are **hard-deleted** (checkpoint + row, `maintenance.py:1290-1310`; `repositories/instance/repository.py:3306-3320`); history cap keeps `MAX_INSTANCE_HISTORY=500` terminal instances (`constants.py:432`; docstring "300" is stale prose); pinned subtrees protected indefinitely. `agents/sweeper` is a SAST scanner, NOT instance GC.
- **Post-TTL:** revive impossible — row gone, send_message → "instance not found" (`instance.py:1826`). Multi-day reuse options: pin the instance (user-owned), or **mint a snapshot before the sweep and respawn warm** (the design-aligned route; snapshot rows survive GC).
- **Handoff latency (Leg A p50 775s / p90 4258s explained structurally):** round-trip = queue hop #1 (worker-pool thread free; **pool = 5 daemon-wide**, `constants.py:91` WORKER_POOL_SIZE — the fan-out ceiling) → specialist turn (LLM loop) → wake hop (child report + pending wake row, `daemon/services/report_delivery_recovery.py:1086`) → parent wake turn. p50 ≈ 1-2 specialist turns + 2 hops + 1 parent turn; p90 implies revision loops / pool contention. Sync alternative `invoke_agent_and_wait` (`daemon/utils.py:670-686`, default 300s, **terminates the child on timeout**) is to be avoided for long work (designer doctrine: async, ≥660s if ever sync). Designer-lane lesson for sonic-leader: **fan out coder→(reviewer,tester) in ONE wave, END TURN once; make reports verdict-bearing; round-trip COUNT is the first-order cost** — a 3-stage chain with one loop ≈ 35-60+ min at p50, hours at p90. Snapshot warm-start does NOT cut queue hops; it cuts ramp-up iterations inside the child's first turn (second-order).

## Synthesis

The sonic team is infrastructurally cheap where it needs to be cheap and precisely bounded where it needs care. **Adding the four agents is pure content work** — four `agents/sonic-*/` directories plus a baseline-file regeneration; zero daemon code, zero migrations, and peer-ness for sonic-leader is structurally free (root-ness is an instance/config property, not an agent-name privilege — the only `leader` hardcodes are feature-scoped privileges sonic deliberately should NOT inherit). **The one-shot coder works today only if the agent carries the recursion multiplier** — the live 300-step ceiling is not theoretical, it killed six real runs this week including a developer instance; the fix is one meta.json line sonic-coder should copy from coder, after which the binding constraint becomes the 125-minute task cap (long fixes must fit ~2h or split across turns, where budgets reset). The loop breaker cannot false-positive on legitimate build/fix loops (identity is full name+args equality, chain-of-3-consecutive), compaction handles very long turns mid-flight with pairing preserved, and there is no tool-rate limiter to dodge. **The neutralized-snapshot handoff exists in its useful form today** — a coder-derived sonic-coder can self-capture a snapshot from its final-turn checkpoint and specialists warm-start from it — gated on the R15 operator toggle, `snapshot_enabled` on consumers, and the mandatory explicit `snapshot_id` relay (the new agent-space scoping silently kills automatic cross-agent discovery); only byte-exact fixed-schema fidelity needs new code (a small passthrough-mint variant). **Reuse is real but window-bounded**: COMPLETED revives are free and unlimited with full checkpoint context, but the 168h sweep hard-deletes unreferenced terminal instances — snapshot-before-sweep is the design-aligned keep-alive, and it is cheaper anyway since revived transcripts only grow. **LLM lanes and giter need nothing**: agentic-for-reviewer is an allowed lane with clean per-agent or per-spawn pinning, and giter's worktree contract is already executing on this very commission (feature/sonic-team-v1 cut 19:43Z). The honest cost center is orchestration physics, not missing machinery: every dispatch→report round-trip is minutes-scale (p50 775s, pool ceiling 5 concurrent), so sonic's speed win must come from collapsing ROUND-TRIP COUNT (one-shot coder, one-wave reviewer+tester fan-out, pre-approved git gates) — the per-hop latency is structural.
