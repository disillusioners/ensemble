# Phase 5: Tests

## Objective

Provide unit + integration test coverage for the hook registry, hook function (including slug derivation + filename collision + format compatibility), config parsing, and integration with the completion path (including outcome-gating, hook-name filtering, timeout/cancellation behavior, and heuristic injection end-to-end). Tests follow the project's existing test conventions (pytest, `tests/unit/` and `tests/services/` directories).

## Coupling

- **Loose with all phases:** Tests depend on the code from Phases 1-4 being complete, but don't modify any production code beyond test fixtures.

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Integration test requires full InstanceManager wiring (heavy mock surface) | Medium | Follow the pattern in `tests/unit/test_root_instance_completion.py` — mock only the minimal surface (manager, instance_repository, registry). The dispatch is a single call; verify via mock assertion rather than full integration. |
| Registry state leaks between tests (module-level dict) | Medium | Add a `conftest.py` fixture that clears `_HOOK_REGISTRY` before each test, OR use `monkeypatch` to replace the registry with a fresh dict per test. |
| End-to-end heuristic injection test (task 11) is slow or flaky | Medium | Use `tmp_path` for the context dir; freeze the time via `freezegun` or inject a deterministic `datetime.now()` for the slug/timestamp; mock the LLM-side heuristic matching to use the existing function with a fixed query. Keep the test under 2s. |
| C4 regex update tests (task 5) don't cover all existing real-world filename patterns | Medium | Add a regression fixture that includes 3-5 actual filenames from the codebase's existing context dir (snapshot via the integration test harness) and run them through both regex sites. Confirms no existing file becomes un-matchable. |
| Timeout test (task 10a) is inherently slow (waits 5s) | Low | Override the timeout to a smaller value (e.g. 0.1s) in the test by parametrizing the `wait_for` call or using a helper function. Document that the production timeout is 5s but tests use a tighter bound. |
| `asyncio.CancelledError` test (task 10b) — pytest-asyncio interaction with `pytest.raises` | Low | Use `@pytest.mark.asyncio` decorator (matching the rest of the suite). Verify with `pytest.raises(asyncio.CancelledError)` in an async test. |

## Exit Criterion

All tests pass. Coverage includes: registry registration (including `hook_names` filtering — C1), dispatch ordering + error swallowing, `CancelledError` propagation (W3), slug derivation from headings (C3), filename collision + format compatibility (C4), hook file writing + error handling + `context_key is None` skip (W7), config field parsing + defaults, integration outcome-gating (only `regular_child_completed` triggers hooks), bus terminal hook surviving hook failure (W8 #7), timeout/cancellation behavior (W2/W3), missing/None context_key (W7), and end-to-end heuristic injection from sibling completion to sibling discovery (W8 #6). The feature is ready for developer implementation.
