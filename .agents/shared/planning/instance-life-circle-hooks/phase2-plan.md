# Phase 2: First Hook Function — add_to_shared_context_md_files

## Objective

Implement the first (and only, for now) hook function: `add_to_shared_context_md_files()`. This async function takes a `LifecycleHookContext`, derives a filename from the report's heading line (C3), and writes the child's `last_content` as a markdown file to the shared context directory identified by `context_key`. The actual file-write logic is delegated to a new shared helper `write_context_file()` extracted to `daemon/services/context_tools.py` (W5) so the hook does NOT create a third divergent copy of the existing `_save_explorer_result` / `_save_experience_result` patterns.

## Coupling

- **Loose with Phase 3:** Shares `context_tools.resolve_context_dir` (now used by both `write_context_file` and the existing context injection) — same infrastructure that `context_injection.py` reads from. No data contract dependency.
- **Independent of:** Phase 1 internals (only uses the registry interface from Phase 1).
- **Touches shared code (C4):** `_extract_slug_from_filename` in `context_injection.py` and `_TIMESTAMP_PATTERN` in `context_tools.py` — both used by existing context file parsing. Changes are additive (new pattern branch, not replacement). **Run all tests that touch context_files / context_injection to confirm no regression before merging.**

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| `write_context_file` is sync (mkdir + write_text), blocking the event loop if not wrapped | Medium | Phase 2 task 3 wraps the call in `asyncio.to_thread(...)` (S3). The hook itself is `async def` and runs inside the dispatcher's `asyncio.wait_for(..., timeout=5.0)` wrapper. |
| Two children complete simultaneously → same timestamp + same slug → filename collision | Medium | Filename includes `instance_id[:8]` suffix (C4) so two concurrent completions always produce distinct files, even in the same second with identical slugs. The heuristic matcher's 50-file mtime cap naturally bounds accumulation. |
| C4 regex update breaks existing files with the OLD format | High | The new pattern is a SECOND branch (additive), not a replacement. Both old (`{slug}_{YYYYMMDD}_{HHMMSS}.md`) AND new (`{slug}_{YYYYMMDD}_{HHMMSS}_{iid8}.md`) formats are accepted. Phase 5 includes regression tests for both. |
| Slug derived from `last_content` is empty (boilerplate-only reports) → filename is just timestamp+suffix | Low | Last-resort fallback produces `child-report-{instance_id[:8]}` so the slug is never empty. Regression-tested. |
| `except BaseException` accidentally introduced — swallows `CancelledError` (W3) | High | Mandate `except Exception:` everywhere. Place `except asyncio.CancelledError: raise` BEFORE the broad `except Exception` whenever cancellation must propagate. The slug derivation runs outside the try block so cancellation can short-circuit cleanly. |
| Heuristic matcher can't find the file because slug is taken from content (not filename source the matcher scores) — boilerplate slugs are invisible | Medium | C3 — slug is taken from the first `#` heading line (the formatted body starts with `# Child Report: {agent_id}`, but if the original report itself has a heading, that wins) or first substantive non-boilerplate line. The C3 test in Phase 5 verifies a topic keyword in the heading appears in the slug AND the file scores >= 0.10 in `_score_context_files`. |
| Atomic write (`os.replace`) fails on Windows (different POSIX semantics) | Low | The ensemble daemon targets Linux/macOS only (verified by existing dev environment). Document the POSIX-only assumption in `write_context_file()` docstring. |

## Exit Criterion

After Phase 2: (a) `daemon/services/context_tools.py` exposes `write_context_file()` with the new filename format including the `instance_id[:8]` suffix and the atomic write pattern; (b) `_derive_report_slug` produces matchable slugs from heading lines (C3 verified by Phase 5 test with `score >= 0.10`); (c) calling `dispatch_lifecycle_hooks("on_complete", ["add_to_shared_context_md_files"], ctx)` writes a `.md` file to the correct shared context directory; (d) the file is readable by `list_context_files()` and appears in heuristic-matching results for sibling agents; (e) `_extract_slug_from_filename` and `_TIMESTAMP_PATTERN` both accept the old AND new format (C4); (f) errors are logged, never raised; (g) `CancelledError` propagates. Phase 4 can call this hook via the registry.
