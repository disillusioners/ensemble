# Phase 4: Integration into Completion Path

## Objective

Wire the lifecycle hook dispatcher into `_dispatch_post_commit_side_effects()` in `daemon/services/child_reports.py`. When a regular child completes (`regular_child_completed` outcome — the only eligible outcome per W6), resolve the child agent's `lifecycle_hooks` config and fire the `on_complete` hooks (filtered to the configured names per C1) via `asyncio.wait_for(timeout=5.0)` with `try/except Exception` (W2, W3). This is the only code change to an existing file beyond the `daemon/registry.py` schema addition (Phase 3) and Wanderer's `meta.json` (Phase 3).

## Coupling

- **Tight with Phase 1:** Calls `dispatch_lifecycle_hooks(event, hook_names, context)` and constructs `LifecycleHookContext`.
- **Tight with Phase 3:** Reads `agent_meta.lifecycle_hooks` config to decide which hook names to dispatch.
- **Loose with Phase 2:** Does NOT reference the hook function name directly — it reads the list `["add_to_shared_context_md_files"]` from config and the registry resolves each name to a function. If Wanderer's config said different hook names, different functions would fire.

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| `asyncio.wait_for` adds up to 5s of latency to the post-commit path when a hook hangs | Medium | The 5s timeout is bounded and runs in the same async context as the existing side-effect chain. A slow hook triggers a `TimeoutError` which is caught by the `except Exception` and logged at WARNING — the method continues and the bus terminal hook still fires. In practice hooks should complete in milliseconds; the 5s ceiling is a hard upper bound. |
| `except Exception` accidentally catches `CancelledError` if order is wrong (W3) | High | The code is structured with `except asyncio.CancelledError: raise` placed BEFORE the broad `except Exception` so cancellation always propagates. This matches the codebase fix referenced in the C2 DB Torn State Fix critical note. |
| Hook dispatch fires for `idempotency_skip` or deferred outcomes | Medium | Impossible by construction — the dispatch code is inside the `if outcome == "regular_child_completed":` block, which is the ONLY branch that reaches it. All other outcomes hit earlier `return` statements. Verified in Phase 5 integration test. |
| Registry lookup (`get_version`/`get_resolved`) is sync and blocks the event loop | Low | Registry lookups are in-memory dict reads — sub-millisecond. No `asyncio.to_thread` needed. |
| `get_tree_root_id` blocks event loop (sync DB traversal up parent chain) | Medium | Wrap in `asyncio.to_thread()` — already planned. Prefer `_resolve_tree_root_id()` from `context_messages.py:856-897` (S4) which already has a traversal-depth bound and is the codebase's existing helper. If the helper is unavailable, the alternative is `instance_repository.get_tree_root_id()` (also wrapped in `asyncio.to_thread`). |
| `context_key` resolution returns `None` and the hook fires with bad key, writing to a wrong dir | Medium | W7 — three-tier fallback: (1) try `_resolve_tree_root_id`, (2) fall back to `instance_id`, (3) if no `instance_repository` at all, set `context_key = None` and skip the hook entirely. The hook function itself (Phase 2 task 5) also short-circuits when `context_key is None` as a defense-in-depth check. |
| Concurrent hook dispatches from many simultaneous completions could exhaust the event loop | Low | The 5s `asyncio.wait_for` ceiling bounds any single dispatch; combined with `asyncio.to_thread` for the actual file I/O, the event loop stays responsive. If profiling shows pressure, the future improvement is a semaphore-bounded dispatch queue — out of scope for this phase. |

## Exit Criterion

When a regular child instance (configured with `lifecycle_hooks["on_complete"]`) completes, the dispatcher runs the named hooks (C1 filtering) and a `.md` file appears in the shared context directory under `{slug}_{ts}_{iid8}.md`. When a child without `lifecycle_hooks` config completes, nothing happens (DEBUG log only). Root completions, tool-invocation completions, error / cancelled / watchover-terminated completions (W6) never trigger hooks. The bus terminal hook, SSE events, and report delivery are all unaffected by hook execution (even when the hook raises or times out — bus terminal hook still fires; "existing side effects not blocked" is asserted in Phase 5).
