# Phase 3 — Diff/provenance reporting

## 1. Objective

The report the tool returns: abbreviated diff (per-file line deltas + section-level added/removed headings), provenance (release version + file hashes + resolution/validation facts), fingerprint idempotence messaging, and the honesty constraints (F7/F8) that keep the report from claiming effects that do not exist.

## 2. Decisions

| ID | Decision | Rationale (anchors) | Rejected alternatives |
|----|----------|--------------------|-----------------------|
| D13 | Diff scope = loader-cached persona only (D5). The report NEVER diffs the post-cache-appended persona (instance_lifecycle.py:1244-1247 — runtime content kept out of the cache; re-appended fresh on next restore). Section-heading extraction operates on the loader-produced persona strings (diffing loader output = reporting, R2-allowed; NOT assembly). AM-8: the decision basis feeding this engine is tool-side per-file sha256 (not mtime/fingerprint); the tier-b exact diff fires ONLY under the stored-mtimes claim-guard (AM-13). | Prevents false deltas from runtime state; keeps R2 intact; mtime-independence per AM-8. | Full-persona diff incl. appends; own .md parsing for sections (R2 violation). |
| D14 | Abbreviated diff format (frozen for the tester gate): per artifact file → `+N/-M lines`, byte delta, sha256 before→after; section level → added/removed `#`/`##` headings (capped lists, e.g. ≤10 per side with `…and K more`); header line states outcome (`no_change` / `reloaded` / `forced_reload`) + release version + tri-state `current_matches_running` (AM-5) + the matching fixed disclosure line (false vs unknown — never collapsed). Envelope additions (AM-5/AM-7/AM-15): `manager_instances before→after` (D22 disclosure surface); `running_release` null-safe (only when `sys.frozen` AND exe-parent matches `^v\d+\.\d+\.\d+$`); `current_target` null-not-empty; `daemon_version` separate field; `hash_mtime_divergence` + `cache_busted` (AM-8); `mcp_tool_names_source` + `db_fingerprint` + `was_cached` (AM-9/AM-14). Companion observability (AM-15/D24): exactly ONE frozen-format INFO log line per tool call on EVERY terminal path (success AND refusal), pinned field order, counts/flags only — never persona or diff content; no journal, no ledger, no metrics family this lane (`prompt_reload_total{outcome}` ROUTED). | Dispatch: "per-file line deltas + section-level added/removed headings, abbreviated". Frozen format = testable; the disclosure lines + log format are grep-pin surfaces. | Raw unified diffs (unbounded tokens); no format contract (untestable); collapsing the tri-state or the two disclosure lines into one. |
| D15 | Honesty marks (F7): the provenance payload's per-artifact DB-row state carries explicit flags — `tools_note`: "DB override NOT applied (known defect F7i, routed)"; `user`/`growth`: "not part of the composed prompt (F7ii)". The diff section never lists these artifacts as changed-by-DB-override. **W5: the literals are CANONICAL — overview §10 bullet ids `S10-a` (F7i) and `S10-b` (F7ii); ONE literal each, referenced by id from here, never paraphrased** (one generated source; greppable copies acceptable). | F7 binding; prevents the report from over-claiming. Pinned by tests (T3.4) + M6. | Silent omission (loses provenance value); claiming the overrides work (false); two paraphrase families (unassertable "verbatim"). |
| D16 | F8 non-promise: result text carries a fixed line noting the FE-visible synthetic system message may lag the live persona until the next display rebuild — no parity claim. **W5: the literal is canonical — §10 bullet id `S10-c` — referenced by id, never paraphrased.** | F8 binding (persistence.py:910-1009). | Promising display parity; paraphrase families. |
| D17 | Idempotence message (R6 + AM-10 wording): fingerprint/hash-equal → outcome `no_change` whose message states FILE-LEVEL freshness — "no changes to the prompt files since the last cache fill" — and MUST NOT claim the closure persona is current (shared-cache multi-instance edge: another instance of the same agent refreshing the shared cache leaves THIS closure stale; `force=true` is the escape). Full provenance always included (the no-op path doubles as the free dry-run — D9). `force=true` → outcome `forced_reload`, pops anyway, message says so explicitly. Both success outcomes carry the next-turn sentence + the AM-4 marker. | R6; P3 (effect = next turn) stated in BOTH paths; AM-10 honesty wording prevents an over-reaching claim. | Suppressing provenance on no-op (loses the dry-run value); claiming closure currency on `no_change`. |
