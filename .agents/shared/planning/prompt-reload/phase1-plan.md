# Phase 1 — Manager primitive + resolver/validation

## 1. Objective

A typed, reusable manager-level primitive `refresh_instance_prompt` that performs the whole validate → compose → compare → pop cycle for ONE instance (the caller's own), returning a structured result. The `prompt_reload` tool (Phase 2) and the future compaction path (R8, NOT wired here) both call this. All reasoning anchors from plan-overview §4–§5 apply.

## 2. Decisions

| ID | Decision | Rationale (anchors) | Rejected alternatives |
|----|----------|--------------------|-----------------------|
| D1 | New service module `daemon/services/prompt_refresh.py` holding the logic; `Manager` gains a THIN delegate method `refresh_instance_prompt(instance_id, *, force=False) -> PromptRefreshResult` (R8 shape: manager-level callable). | manager.py is ~13.7k lines with a routed decomposition debt; house style is service modules (cf. `daemon/services/report_delivery_recovery.py`, `boot_epoch.py`). The delegate satisfies "manager-level primitive" without growing the monolith. | Logic directly in manager.py (grows routed debt); tool calls internal helpers directly (breaks the R8 callable shape). |
| D2 | Resolution = **registry / `metadata.path` spawn parity** (F5), NOT the `current` symlink. Provenance reports: resolved dir, resolution source, self_env, running release (`daemon.__version__`), install root, current-symlink target, `current_matches_running` bool. Validation is self-env-aware: live (`_self_env_marker()` == "live" / env) requires the resolved dir under `<install_root>/releases/<version>/agents/`; dev requires it under the repo `agents/` tree. | Spawn/restore use `metadata.path` (instance_lifecycle.py:1922) — single source of truth (R2 spirit). `current` can flip without a restart → divergence is real (F5 tension); reporting it beats resolving through it. Reuse upgrade_tools callables (`_self_env_marker` :563, `_resolve_install_dir` :665, `_current_symlink` :880, `_canonical_install_root` :423). | Resolve via `current` symlink (breaks spawn parity; silently loads a tree the running code does not match). |
| D3 | Manifest verification (F6): locate `manifest.json` at the release root (parent.parent of the resolved `agents/` dir; layout stage.sh:9-16). v1 default scope: the **calling agent's own file set** (per-file sha256 map entries under `agents/ari/…`). Whole-tree strict mode behind a config knob, default OFF (architect may flip — OQ2). Dev mode: repo root has no `manifest.json` → skip with provenance `manifest=absent(dev)` (disclosed, not a refusal). Live + manifest missing → typed refusal `prompt_reload_manifest_missing_live`. | Ari-files-only is O(agent files) and directly relevant; whole tree is the strict upgrade path (RA5). Nothing reads the manifest at runtime today (F6) — this is new, small logic by design. | Whole-tree always (cost + blast radius); no verification at all (violates the brief's guardrail). |
| D4 | Composition via the EXACT spawn-path builder: `load_and_cache_prompt(resolved_agent_id, agent_path, prompt_cache, mcp_tool_names, version_tag=…, is_custom_agent=…)` imported through `daemon.manager` (re-export manager.py:27 — tests patch it there), called with the same manager-owned `prompt_cache` and current `mcp_tool_names` the next restore would use (call shape instance_lifecycle.py:4808-4814). The tool NEVER reads/assembles .md files itself (R2). | Single source of truth (R2); a future approved DB row is honored automatically (F4). Cache mutation is safe: the fingerprint cache self-heals on next restore (loader.py:1452-1464; subtleties = OQ6). Passing current `mcp_tool_names` mirrors what the next cold restore would pass. | Own .md reading/diffing (R2 violation); building a second composition path (drift). |
| D5 | Changed/unchanged decision at the **loader-cached-persona level** (artifact-derived portion ONLY — never the post-cache-appended persona; see overview §5 addendum). Tiering: (a) fingerprint unchanged → no-change; (b) fingerprint changed → compose fresh, diff vs the cached persona (exact when cache == closure — normal case, P2); (c) old cached persona unprovable → honest fallback, report composition+provenance only with `persona_diff=unavailable`. Per-file sha256 before/after always reported (reporting, R2-allowed). | `_apply_post_cache_appends` keeps runtime content OUT of the cache deliberately (instance_lifecycle.py:1244-1247) — diffing appended personas yields false deltas from state the reload doesn't change. Closure introspection forbidden (R3). | Diffing the full appended persona (false deltas); closure-cell introspection (R3-forbidden). |
| D6 | Typed refusal ladder (draft, OQ5 for final): `prompt_reload_disabled`, `prompt_reload_not_ari`, `prompt_reload_agent_dir_unresolved`, `prompt_reload_dir_invalid`, `prompt_reload_manifest_missing_live`, `prompt_reload_manifest_mismatch`, `prompt_reload_agent_meta_invalid`, `prompt_reload_compose_failed`, `prompt_reload_db_unavailable`, `prompt_reload_internal_error`. Envelope = house REFUSED shape `Error: prompt_reload REFUSED — reason=<code>: <message>` (notify_user.py:314-321); unexpected errors use the FAILED shape (`prompt_reload_internal_error`). | notify-user 12-code D9 precedent (notify_user.py:176-196). Fail-closed on loader/DB errors per R6; `""`-fingerprint is the ABSENT-repo convention (loader.py:207-208), a FAILING repo is a typed refusal. | Untyped prose errors; fail-open on DB errors. |
| D7 | No prompt-artifact file changes in v1: ari's `tools_note.md` NOT amended; documentation surface = tool docstring/tool_help + `docs/runbooks/prompt-reload.md` (Phase 5). Prompt baseline stays 181 rows, no re-stamp ceremony. | The notify-user precedent DID amend doctrine files (tools_note etc.) — deliberately deviating: a tools_note touch would trigger seal re-pin + baseline regen for zero behavioral need (Ari sees the tool via tool_help; the runbook carries the doctrine). Called out explicitly because it deviates from precedent. | Amending tools_note.md now (unneeded baseline churn; deferable to any later ari prompt-touch lane). |
| D11 | Kill-switch `ENSEMBLE_PROMPT_RELOAD_ENABLED` (default ON), env-prefixed knob resolution in the notify-user N9 style (notify_user.py:106-115, :332). | Rollback posture: a single env flip disables the tool without a release. | No kill-switch (removal requires a release). |

## 4. Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC1.1 | `PromptRefreshResult` shape frozen: outcome, refusal code (or None), abbreviated diff summary (or `persona_diff=unavailable`), provenance block (per D2/D3/D5 fields). All 10 refusal codes exist as named constants. |
| AC1.2 | For a live-shaped layout the resolved dir equals the registry `metadata.path` equivalent and `current_matches_running` is computed correctly for matched AND diverged fixtures. |
| AC1.3 | Validation matrix (live-in-releases PASS / live-outside REFUSED / dev-repo PASS / dev-foreign REFUSED) green, each refusal typed. |
| AC1.4 | Manifest legs: mismatch (tampered COPY — never the live tree) → `prompt_reload_manifest_mismatch`; live-missing → `prompt_reload_manifest_missing_live`; dev-absent → skip with `manifest=absent(dev)` in provenance. |
| AC1.5 | Composition goes through `daemon.manager.load_and_cache_prompt` (patchable in tests) with the manager's `prompt_cache`; zero direct .md reads in the module (R2 — enforced by a test). |
| AC1.6 | Fingerprint-equal trees produce `no_change` and do NOT mutate `manager.instances`. |
| AC1.7 | Pop fires iff (changed OR force); module greps clean for `_release_cached_instance` and contains no graph construction (P4/P5 pins). |
| AC1.8 | `manager.refresh_instance_prompt(instance_id, force=…)` works and the compaction path is untouched. |
