## 1. Objective

The complete, explicit test enumeration the tester functional gate consumes. Environment: dev daemon :8079, throwaway PG, stub LLM (the probe's harness shape); **`ENSEMBLE_SELF_ENV=dev` pinned EXPLICITLY (B5)**. **Zero live contact for the whole gate.** FINAL MATRIX: **L1–L9 + M1–M6.** Suggested packs: `tests/unit/services/test_prompt_refresh_primitive.py`, `tests/unit/tools/test_prompt_reload_tool.py`, `tests/unit/tools/test_prompt_reload_refusals.py`, `tests/unit/tools/test_prompt_reload_pins.py`, + the dev-daemon E2E leg (probe harness shape).

**B3 split ownership + L1/L6 ordering (binding):** the IMPLEMENTER pre-stages the scratch seam — a dedicated scratch `agents/` tree (or harness worktree) at a FIXED, documented path (this section is the documentation of record; suggested: `<harness_dir>/scratch-agents/ari/`, wired via the harness's agent-dir override, NEVER a symlink into the release tree) — and the TESTER executes L1 against it and OWNS the restore post-condition: byte-exact sha assertion of every touched file + a `finally` restore. **The scratch tree is NEVER the release tree and NEVER the worktree's own `agents/`.** `agents/ari/rule.md` is simultaneously prompt-baseline-pinned (`agents/.prompt-artifacts.sha256:30`) AND in `SEALED_SHA_BASELINES` (`tests/test_chart_image_delivery_e2e.py:1507`) — a leftover sentinel is the exact prompt-artifact-mutation class the house has forensically handled three times; drift is not acceptable. **L6 ↔ L1 contradiction resolved by ORDER:** L6 baseline snapshot → L1 mutation (scratch seam only) → L1 restore in `finally` (sha-proven byte-exact) → L6 clean re-assert. Both legs then hold: L1 mutates only the scratch copy; L6's baseline-clean assertion is evaluated after the proven restore.

**L1(d) read path (Advisory 5):** message count is read via `GET /api/instances/{instance_id}/messages` → `get_instance_messages` (daemon/persistence.py:627; router `daemon/routers/instances.py:1390`), counting serialized messages before vs after — the synthetic-system entries are excluded from the count (they are display-side; the assertion is over persisted messages).
