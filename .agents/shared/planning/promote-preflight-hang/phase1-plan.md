# Phase 1 — D1: O(N) journal read / read-modify-write

**Deliverable:** D1 — ROOT-CAUSE FIX.
**Depends on:** P0 · **Blocks:** P2 (the watchdog must measure the fixed read), P5.

## 1. Objective

Remove the O(N²) per-character bash scans that made the 2026-10-28 preflight hang, **without changing a single
observable behaviour** of the journal read path:

* `journal_read` (`lib.sh:961`) — the balance scan that hung.
* `journal_update` (`lib.sh:1024`) — the RMW path, which inherits the read **and** carries its own per-character
  value scanner (`lib.sh:1046`-`:1070`).
* `_json_sub` (`lib.sh:589`) — the nested-object bracket counter (`lib.sh:600`-`:620`), also O(N²) on the journal string.
* The **stage-path** manifest-checksum burn (`stage.sh:436`-`:446`) — same symptom class (unbounded, unlogged CPU
  in an early pipeline phase), bounded rather than rewritten.

And make the *next* size cliff **loud** instead of a 61-minute stall: a journal size guard.

**Invariants this phase must not break**

| # | Invariant | Where it is enforced today |
|---|-----------|----------------------------|
| I1 | `journal_read` prints the journal JSON on stdout, byte-for-byte, and returns 1 on absent / empty / malformed. | `lib.sh:961`-`:999` |

> A case where the new scanner and BASE disagree is a **defect in the new scanner**, never a "correction".
