# Phase 9: Verification, bundle guard, packs, and close-out

## Objective

Prove the lane, on a **fenced dev daemon**, and hand over cleanly: the pixel
list captured, the bundle guard measured, both FE packs green, the routed-out
register closed, and the operator auth recipe handed over (never executed).

**This phase is where the lane proves its claims. It does not "make it
work"** — a failure here is a finding to be reported, not a thing to paper
over.

## Scope note

- The dev daemon runs on `127.0.0.1:8079`. **Never** `:9797`. **Never** the live
  daemon. Live config is out of bounds (D-2).
- Every capture is GET-only. The API census is asserted **0 non-GET**.
- **THE INTERPRETER IS PINNED (W9):** every command that runs python uses the
  house-certified interpreter
  **`/home/nea/ensemble-src/.venv/bin/python`** (Python 3.13.15, a uv-managed
  CPython) — **run from this worktree's cwd**. The worktree has **no** `.venv`
  and **no** `venv`, and **bare `python` does not exist on this host** (only
  `/usr/bin/python3`), so `dev.sh`'s fallback chain (`.venv/bin/python` →
  `venv/bin/python` → `python3`, `dev.sh:61-65`) would resolve to the
  **uncertified** system interpreter. **No command in this plan may invoke a
  bare `python`.**
- **THE MINT IS A DATABASE WRITE (B1).** The bearer-token mint INSERTS a row.
  The lane's **only** write is inside the **dev** database
  (`ensemble_dev`), and the fence in 9.3a proves it — before, during and after.
