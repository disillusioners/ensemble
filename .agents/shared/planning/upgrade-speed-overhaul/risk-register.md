## 2. Change-Rollback Plan (for the overhaul changes themselves)

If the v0.20.1 promote (the vehicle carrying the overhaul) misbehaves, escape in this order:

1. **Conservative-mode escape (env-only, immediate).** Operator sets `ENSEMBLE_PROMOTE_SOAK_S=300` (+ explicit budget knobs as desired) → ceremony behavior reverts to the current safety envelope (T-AC3 pins guarantee exactness). No code revert, no re-stage needed for soak/pacing-related misbehavior. This is the FIRST response to any "too fast, want the old ceremony back" report.
2. **Re-stage / quarantine-clear path.** A bad or stuck stage leaves the target quarantined; quarantine clears ONLY via re-stage (`stage.sh:616-618`) — there is no manual quarantine edit (fail-closed by design, pinned by `T-PIN-failclosed`). **Vehicle naming:** `stage.sh:361` derives the binary version `ENSEMBLE_BINARY_VERSION:-${VERSION#v}` — re-staging the SAME VERSION must either bump the version or set `ENSEMBLE_BINARY_VERSION` explicitly, or the stage may pick up a stale binary under the same name. Runbook must call this out.
3. **Code-level revert.** All overhaul changes live on `feature/upgrade-speed-overhaul` (worktree HEAD `c8a3fbf6`); `latest` without the branch behaves exactly as today (pre-overhaul ceremony). A full revert = promote from `latest` sans branch; `rollback_safe` derivation (`stage.sh:325-351`: unset + destructive-DDL ⇒ exit-78) is untouched by the overhaul and must remain so — the overhaul never flips this gate.
4. **Post-promote rollback of v0.20.1 itself.** v0.20.1's auto-rollback targets N-1 = v0.20.0 (proven machinery, `T-AC5a` matrix); manual `rollback.sh` remains available; the halt→re-promote chain (Oct 9 arc) is exercised by matrix cell 2 and remains automatic.

**Operator runbook entry should say** (with ALL FOUR C-11 controls + C-10b recovery step): (a) pre-ceremony — drill evidence link, **conservative-vs-fast decision recorded as `FAST` (D-P4.5/Q6b final)**, `ENSEMBLE_BINARY_VERSION` naming check; (b) during — journal tail command, expected event sequence, **C-10c** budget-breach = reason token `deadline-breach-<phase>` + `daemon-state` field; budget-breach = terminal-within-budget (do NOT intervene mid-rollback); **C-10b post-stop breach first-recovery-step**: if halt detail shows `daemon-state=stopped`, operator's first action is `verify/restart current` BEFORE re-promote; (c) post — §7 watch list (livez/readyz, soak/early-exit events, pending_op state, rollback-pointer currency, amnesty/audit events) **+ post-promote real-message smoke (mandatory) + first destructive blob-prune drain watch + no-key-rotation window + transient indicator list**; (d) incident paths — halt→re-promote recognition, boot_sweep commit-and-continue recognition (flip already recorded — do NOT re-run promote), quarantine re-stage procedure.
