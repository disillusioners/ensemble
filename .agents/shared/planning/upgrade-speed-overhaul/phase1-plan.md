## 1. Objective

Land the **N-1 invariant** end-to-end across the halt→re-promote chain (the Oct 9 arc) and the `boot_sweep_commit_and_continue` path. The bug class is "reading the wrong field" — `promote.sh:452-453` reads `journal.previous` to derive the auto-rollback target, but `journal.previous` is stale whenever the previous run halted AFTER the flip and BEFORE commit (or whenever boot_sweep minted a non-standard previous). The P1 fix is two-fold:

1. **Live lane** (decision (g) option A): replace the `journal.previous` read at `:452-453` with `$OLD_CUR` captured at `:227 :436` (single-source-of-truth: the version THIS run displaced); immediacy assertion at the commit-block set-previous moment ensures `journal.current == $VERSION` before the `previous` write.
2. **Boot-sweep lane** (decision (g) option C, **C-4**): stamp `in_flight.displaced_version = journal.current` at `journal_open_txn` time (`lib.sh:700-712` extended bash whole-object writer — NO new helper op, NO python dependency); `boot_sweep_commit_and_continue` reads `in_flight.displaced_version` and writes `previous = displaced_version`. Old-format in_flight (no `displaced_version`) → halt-for-human. This is the only path in launcher.sh that may update `previous` from boot-sweep land.

Plus polish (printf noise, harness comment honesty) that rides this PR. The original P1 plan's D-P1.1 rejected option C on the false premise that it required a new helper op and an in_flight schema expansion — it does neither, and the corrected shape is the right fit for boot_sweep.
