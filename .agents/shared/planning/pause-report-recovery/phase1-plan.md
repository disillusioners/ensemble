# Phase 1: DB-Persisted Delivery Marker + Drop-Site Fixes (v3, review-patched)

## Objective

Introduce the persisted delivery-obligation marker (DEFERRED state with UPPERCASE case parity, `deferred_reason` TEXT + `recovery_attempted_at` columns, nullable `report_message_id`, partial unique index on the obligation triple) and convert both drop sites into **recoverable deferrals** — with the Site 1 write hardened against pipeline cancellation using the precise W4 pattern (create_task + shield + detach). Re-entry is Phase 2.

## Exit Criterion

All DEFERRED writer paths persist markers on PG + SQLite **including under cancellation at Site 1** (detached-shield survives both cancel points); root instances marker-free under pause; both drop sites DB-observable; repo contract methods + IntegrityError absorption + count semantics shipped with unit tests (incl. the C1 raise-assertion); migrations idempotent with W3 pre-check + W8 runbook; `report_message_id` nullable with consumers audited. No behavioral re-entry yet (Phase 2).
