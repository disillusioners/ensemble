## Top-3 watchlist for the implementation lane (updated)

1. **R1** — the AC4 property is the reason this design is safe; do not "simplify" the ordering or add a reaper.
2. **R19** — the success-path terminalizer (Δ1) is THE pin that closes AC4 on the success path; if Δ1 is not in `_resume_processing_background`'s success branch, the FIFO wake lands at STR reap (~boot+10 min) and AC4 degrades from "deterministic FIFO" to "STR-mediated recovery". **r3 scope: the guard is the call-site gate `if task.auto_continued_at is not None:` wrapping the `await asyncio.to_thread(self._task_repo.complete_task, task.id, ...)` call** — the call-site gate scopes the terminalizer to direct-resume orphans only and prevents early-completion of FM-1 worker-claimed RUNNING rows (`daemon/manager.py:11115-11140`). The shared `complete_task` SQL keeps byte-identical semantics to pre-feature (no `auto_continued_at IS NOT NULL` conjunct added — the r2 scheme was REJECTED in D29 because it would silently make worker-pool / task-processor completion a no-op).
3. **R5/R8/R21** — touch nothing in `claim_pending_task` or the terminal-token set (R5/R8); verify the worktree/venv gate (R21) before any test runs. Full-dir + cascade gates + worktree-import-resolution are the tripwires. **R21 (r2):** the worktree gate is REMOVED/NEUTRALIZED in the MERGE commit (item 6, r2) so it does not falsely fail on main/remote VMs post-merge.
