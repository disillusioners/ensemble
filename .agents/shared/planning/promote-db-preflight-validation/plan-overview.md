## Objective

Add a daemon-tool-lane preflight check to the `system_upgrade` arm path that **validates the newest daily backup artifact** (from the cluster-side dump lane) by reading the lane's own registry metadata over the sanctioned PostgreSQL channel — instead of dumping the live database per promote. The check remembers the validated identity in a new top-level key `db_preflight` in `releases/state.json`, skips re-validation ONLY when the identity is unchanged AND every gate (`integrity_ok`, non-empty bytes, freshness) still passes on the re-fetched row (D4 amendment, cycle-2 F1), and refuses loudly (with eight distinct kebab-case tokens) when the registry relation is absent, no backup exists, the newest artifact is broken/empty/stale, the journal is torn, a `full-dump` opt-in is requested, or the mode is unknown. The check runs ONLY in the live environment (`self_env == "live"` — M2; the registry lives in `ensemble_prod`, so dev/demo/sandbox skip it entirely rather than always refusing). The shell ceremony (`promote.sh` / `lib.sh`) is **not touched at all**; the guarantee attaches to the daemon-armed ceremony and is disclosed as such.

## The Emperor's ruling (verbatim, arch §1)

Also don't need to validation all the time, we backup one a day, so check the lastest backup, remember it, if that backup already checked, skip."

## Architecture rulings adopted (verbatim, arch §3-§9)

- **D1 — WHERE THE VALIDATION LIVES:** the DAEMON TOOL LANE — a new check in the `system_upgrade` arm preflight, immediately after the scripts-provenance guard closes and immediately before the Step 0c comment header. Downstream of the 3-factor live gate and every busy/cooldown/lock refusal; under the held lock; precedes the nonce burn and the `pending_op` write; upstream of the executor spawn (gated on a matching durable `pending_op`, so a daemon-side refusal halts the ceremony entirely).
- **D2 — HOW "THE LATEST BACKUP" IS IDENTIFIED:** the newest row overall for the lane, by `finished_at DESC, artifact DESC`, then assert `integrity_ok` on that row. Read the TABLE, not the view (the view filters `WHERE integrity_ok` and would MASK a broken newest artifact). Identity tuple `(lane, artifact, bytes, finished_at)` + a `fingerprint_sha256` over the canonicalised tuple. Lane value constant `DB_PREFLIGHT_LANE = "pgdumpall"`.
- **D3 — WHERE THE REMEMBERED IDENTITY LIVES:** a new top-level key `db_preflight` in `releases/state.json` (`journal_path = install_dir / "releases" / "state.json"`), the seventh key added through `ensure_extensions`. One compact object (current-value slot), not an unbounded history.
- **D4 — WHAT "CHEAP AND MEANINGFUL" MEANS:** the lane's own verdict + non-empty bytes + age within bound + the newest-overall artifact being verified. Five assertions, one SELECT. Freshness bound 48 h (172800 s) measured on `finished_at` (normalised to `finished_at_utc` — cycle-2 F13), env-configurable via `ENSEMBLE_PROMOTE_DB_PREFLIGHT_MAX_AGE_S`. The bound is evaluated on EVERY invocation. **D4 AMENDMENT (cycle-2 F1 — amends arch §5 `:168`):** the identity-skip may short-circuit NOTHING. The skip predicate, on the FETCHED newest-overall row, is `identity_unchanged ⇔ (lane, artifact, bytes, finished_at, fingerprint_sha256) == remembered` and `skip ⇔ (identity_unchanged AND finished_at_age_s <= DB_PREFLIGHT_MAX_AGE_S AND integrity_ok IS TRUE AND bytes > 0)` — identical character-for-character to decisions.md §Skip predicate and the phase1-plan.md body. EVERY gate is evaluated on EVERY invocation; "skip" ONLY selects the `skipped` verdict and limits the record mutation to `last_checked_at` + `verdict`. Why: `integrity_ok` is the only registry field that can move under a fixed identity tuple (the publisher re-verifies the newest artifact every run), so a skip that did not re-assert it would let the arm proceed on a backup the lane's own verifier marks broken. Mutation proof: `test_skip_does_not_fire_when_integrity_flips_false_with_unchanged_identity`.
- **D5 — WHAT STALENESS DOES:** staleness FAILS the promote loudly. **Eight** distinct refusal tokens (one greppable family; the architect's nine-token family minus the dropped condition-(6) token — M1, see §DELETION RECORD): `db-preflight-registry-unavailable`, `db-preflight-no-backup`, `db-preflight-artifact-broken`, `db-preflight-artifact-empty`, `db-preflight-artifact-stale`, `db-preflight-journal-torn`, `db-preflight-full-dump-unavailable`, `db-preflight-mode-unknown`. No new exit code is claimed (the house's 0/75/76/78 vocabulary belongs to `scripts/audit/dump_lane_staleness.py`, a repo-only probe).
- **D6 — THE R6 OPT-IN:** the opt-in cannot mean "dump from the ceremony" — a VM-side full dump is impossible on five independent grounds. `full-dump` is recognised and refused loudly with `db-preflight-full-dump-unavailable`; an unrecognised value is refused (`db-preflight-mode-unknown`). The opt-in is a tool-call parameter `system_upgrade(..., db_preflight=...)`, bound into the `PendingOp`, never crosses the executor boundary, never appears in `EXECUTOR_ENV_ALLOWLIST` / `EXECUTOR_ENV_PREFIXES`, never becomes an argv flag, never requires a `promote.sh` `case` arm. Check 3 is unaffected.
- **D7 — THE SHELL PREFLIGHT IS UNTOUCHED BY CONSTRUCTION:** the new leg is daemon-side only.
- **D8 — THE DISCLOSURE:** the text in §"D8 disclosure text" below (arch §15 with five adjudicated corrections).
- **F1 — THE DIRECT-OPERATOR GAP:** arm-path only + disclosed. A deliberate direct `ENSEMBLE_UPGRADE_LIVE=1 bash promote.sh live` bypasses the validation entirely.

> **Backup validation at promote time is a metadata validation, not a byte-level one.** The ceremony reads the dump lane's own registry over the sanctioned PostgreSQL channel and asserts that the **newest artifact row** for lane `pgdumpall` carries the publisher's `integrity_ok = true` (a cluster-side `zstd -t` verdict), a **non-zero** byte count, and a `finished_at` within the **48-hour** freshness bound, measured on the artifact's own completion time — never on `first_seen_at`/`last_seen_at`, which measure the scanner's cadence rather than the backup's age. **The bytes are never re-read, checksummed, or restored by the ceremony**; a corrupted or truncated artifact that the publisher marked verified **will pass**. The registry publishes **no checksum**, so the remembered identity is `(lane, artifact, bytes, finished_at)` plus a fingerprint over that tuple.
>
