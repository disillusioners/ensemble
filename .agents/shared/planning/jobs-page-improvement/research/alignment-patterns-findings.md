## 1. Instances-Primary Tree (`models/instance-node.model.ts`)

**Design axiom (user-locked V1, 2026-09-08):** users think in INSTANCES (conversations), not missions. Tree = ROOT instances → child instances → job receipts at leaves (`instance-node.model.ts:1-26`, restated `components/job-queue-panel/job-queue-panel.component.ts:29-37`).

- **`InstanceRow`** — the flat `GET /api/instances` wire row: `instance_id`, `agent_id`, `status`, `parent_id`, `title`, `initiative_message`, `children: string[]` (child IDS, not nested), `pinned`, `pinned_at`, etc. (`instance-node.model.ts:140-158`). Docblock pins the BE contract: root-paginated, ALL descendants of the current root page BFS-included in the flat list (`instance-node.model.ts:8-14`).
- **`InstanceNode`** — row + nested `children: InstanceNode[]` + `attachedJobs: Job[]` (`instance-node.model.ts:166-174`).
- **`buildInstanceNodes(rows)`** (`instance-node.model.ts:194-227`): Map-based node lookup, parent-child attach via `parent_id`. NEVER-hide rule: a row whose parent is not in the page degrades to a ROOT so it still renders (`:177-183`). Cycle guard (W4): self-loop or parent-in-own-descendants → degrade to root, prevents stack overflow in the recursive walkers (`:184-211`).
- **`buildInstanceTree(roots, activeJobs, recentJobs) → InstanceTree`** (`instance-node.model.ts:346-453`), four buckets (`:260-270`):
  - `liveRoots` — root live itself OR any descendant live (`subtreeIsLive` `:307-311`), sorted pinned-first → `updated_at` desc → `instance_id` tiebreak, recursively (`compareInstanceNodes` `:283-296`, `sortInstanceNodes` `:298-305`).
  - `queued` — non-terminal jobs whose grouping key matched NO node (`:380,392`).
  - `recentRoots` — terminal roots, capped at **`MAX_RECENT_INSTANCE_ROWS = 10` JOB ROWS** (`:258`); instance headers "ride along" free (`:233-256`); partial-fit + overflow semantics (`:411-434`).
  - `recentFlat` — orphan terminal jobs; overflow lands here; ALWAYS surfaces (`:436-450`, never-hide `:327-328`).
- **Coalesced grouping key** `job.mission_id ?? job.instance_id` (`route()` at `instance-node.model.ts:382-394`, key computed `:383`): mission identity rule is `mission_id == instance_id`, but the jobs LIST wire ships `mission_id: null` for CHILD-bound rows (BE `root_only=True` enrichment drops them), so the fallback restores attachment under the child node; when both populated they are equal, so the fallback can never re-key a job to a different node (`:367-378`). Same story on the `Job` type (`models/job.model.ts:92-104`) and `InstanceNode` docblock (`:169-172`).
- **`shouldAutoExpandInstanceTree(liveRoots) → string[]`** (`instance-node.model.ts:497-502`): FIRST 2 live roots auto-expand (exactly 2, user-specified); returns IDS (not boolean) because expansion state is keyed by `instance_id`; terminal roots always start collapsed (`:21-23, 488-496`).
- **`visibleInstanceTreeItems(liveRoots, recentRoots, expandedIds)`** (`instance-node.model.ts:623-656`): flattens both trees in display order — node, then (if expanded) child instances recursively, then attached receipt jobs; collapsed nodes' descendants OMITTED entirely so ↑/↓ skip them. `InstanceTreeItem` union carries `kind: 'instance'|'job'`, `depth`, `parentInstanceId` (`:599-614`). The panel renders FROM this same list, so keyboard order == DOM order by construction (`job-queue-panel.component.ts:176-199`).
- **`nextInstanceTreeItem(items, idx, ±1)`** (`instance-node.model.ts:664-676`): CLAMPS at ends — no wrap (wrap in a two-tree layout reads as a glitch).
- Display helpers: `instanceDisplayTitle` — title → `agent_id · timeAgo(created_at)` honest fallback chain (`:509-530`); `instanceMetaLine` — `agent · N jobs · M agents · timeAgo(updated_at)`, zero-count segments dropped, "M agents" counts the BUILT nested children not the wire `row.children` (W3) (`:532-567`); `defaultInstanceTimeAgo` (`:570-584`); `collectSubtreeJobs` — children first (receipts are subtree LEAVES) then node's own jobs (`:471-485`).
- Full instance status value space quoted from BE with terminal/live split (`:35-92`) and badge palette `getInstanceStatusColor` (`:98-122`).

## 2. Panel Component Shape (`components/job-queue-panel/`)

- **Dumb/presentational** — all data in via `input()`s, events out via `output()`s; "the parent (job-queue-indicator) owns ALL fetching … and the navigation handlers" (`job-queue-panel.component.ts:51-55`). Inputs: `instances`, `activeJobs`, `recentJobs`, `projectNameMap`, `liveMissionCount` (`:93-120`; `liveMissionCount: number|null` — `null` = never received a good count so the empty-state subtitle never flips to "idle" during an outage, `:112-120`). Outputs: `jobClick`, `instanceClick` (ROW CLICK = NAVIGATE), `footerClick` (`:122-135`).
- **Expansion state** — one `Set<string>` keyed by `instance_id`, survives poll refreshes (`:137-143`). **`userTouchedInstances` (G1)** — ids the user manually toggled; auto-seed only acts on UNTOUCHED first-2-live ids, MERGES onto the existing expansion set, never un-toggles or re-expands a user-decided id across live-set drift (`:145-154`, effect `:239-291`, `toggleInstance` `:294-312`).
- **Chevron-only expansion** — real `<button type="button" class="instance-chevron">` with `aria-expanded` + `aria-label` bound (`job-queue-panel.component.html:72-79`, recent twin `:228-235`); chevron click `stopPropagation()` so a chevron tap never navigates (`job-queue-panel.component.ts:335-347`); glyph `expand_more`/`chevron_right` (`:320-323`). Native button activation covers Enter/Space — no separate keydown handler needed (`:340-343`, html comment `:32-37`).
- **Row click + Enter navigation & the F2 preventDefault trap** — every navigable row binds `(click)` AND `(keydown.enter)/(keydown.space)` with `$event.preventDefault()` (`html:67-69, 106-107, 166-167, 224-225, 264-265, 317-319`). Reason (live-reproduced 2×): Enter's default action synthesizes a click on the element focused at default-action time — `closeMenu()` restores focus to the menu TRIGGER mid-dispatch, so the synthetic click re-opens the menu right after close (`html:44-56`). ANY new row surface in a mat-menu must repeat this guard.
- **"Live conversations" section title** (`html:40`), tree roles `role="tree"` + `aria-label="Live conversations"` (`html:41`); Recent tree `aria-label="Recent conversations"` (`html:210`).
- **560px panel** — `width: min(560px, calc(100vw - 32px)); max-height: min(600px, …)` dark-slate `#1e293b`, mirrors notification-bell dropdown styling; list scroll capped 540px, `overflow-x: hidden` (rows truncate, never X-scroll) (`job-queue-panel.component.scss:1-20, 62-71`).
- **Never-hide principle** — every job surfaces exactly once: attached to a node, or `queued`, or `recentFlat` overflow (`job-queue-panel.component.ts:96-103`); Recent total rows may EXCEED the 10-cap by design when headers/overflow render (`:201-216`).
- **Honest fallback labels** — empty state: "No jobs" + subtitle "Queue is idle · N live missions still working" when liveMissionCount > 0, else "Queue is currently idle" (`html:14-25`); job title `resolveTitle`: `job_metadata.instance_name` → `agent_id` → first-8-chars id (`job-queue-panel.component.ts:508-517`); project label: name → shortened id, `—` when null (`:573-587`); instance title fallback chain (model, §1); meta line drops zero segments (`instance-node.model.ts:532-567`).
- Job receipt row anatomy: status spinner (processing) or status icon, title, project badge, `agent_id` badge, UPPERCASE status text, optional mission-liveness chip (click/keydown stopPropagation — chip never navigates), time-ago (`html:98-148`); Recent rows use `completed_at || created_at` (`html:300-302`) and terminal status CSS classes (`html:255-259`).
- Footer "Open full queue →" — sibling of `.panel-list` (W2: arrow keys typed while footer owns focus must not phantom-move the tree) (`html:366-384`); emits `footerClick`, indicator routes to `/jobs` (`job-queue-panel.component.ts:359-362`, indicator `:1132-1135`).
- Depth indent: `8 + depth*16` px (`job-queue-panel.component.ts:330-333`).

## 3. Indicator Fetch Discipline (`components/job-queue-indicator/job-queue-indicator.component.ts`)

- **ONE 8s tick, five legs, ONE `forkJoin`** — `POLL_INTERVAL_MS = 8000` (`:122`), `ngOnInit` starts `setInterval(fetchBadgeSignals)` (`:556-560`). Legs (`fetchBadgeSignals` `:657-722`):
  1. `active` — `JobService.listActiveJobs()` (`:659-664`; service: `GET /api/jobs?status=queued,active`, `services/job.service.ts:123-128`).
  2. `recent` — `JobService.listRecentJobs(10)` (`:665-670`; service: `status=completed,settled,failed,cancelled,dead_letter&limit=10`, `job.service.ts:138-145`).
  3. `liveMissions` (LEG A, badge) — `JobService.listMissions({liveness:'processing,pending,paused', limit:20})` (`:680-688`; service `GET /api/missions`, `job.service.ts:167-172`). `total` is the badge count; the same payload feeds the tooltip per-liveness breakdown — single source of truth (F-5 fix, `:188-210`). Degraded envelopes (`degraded:true`, `total:null`) NEVER clobber the last good payload (`:207-210, 796-816`).
  4. `instances` (tree) — `InstanceService.listInstanceTree(10)` (`:695-701`).
  5. `deferBlocked` — `JobService.listDeferBlocked()` (`:702-707`; `GET /api/queues/defer-blocked`, `job.service.ts:228-230`).
- **Per-leg `catchError` → `of(null)` + `recordLegError`** (`:660-707`, `:730-735`); the outer `forkJoin` error callback is a safety net only (`:717-721`). `null` ⇒ RETAIN last payload per leg (`applyFetchResults` `:780-847`): jobs lists retained (never a bare 0/0 that impersonates a healthy poll, `:767-772`), instance tree retained (never flashes empty, `:804-808`), missions count retained (`:793-803`), defer warning hides. `lastFetchAt` advances only when ≥1 leg returned data, so "refreshed Ns ago" never lies (`:831-842`); `lastIntakeError` clears only when ALL legs healthy (`:817-830`).
- **Badge = missions-based, tree = instances** — segmented pill states `segmented` / `missions-only` / `idle` (`:484-490`); `missionsSegmentText` = `liveMissionCount ?? 0` (`:509-511`); degraded aria-label on the missions segment so screen readers never read "0 live missions" in an outage (`job-queue-indicator.component.html:20-29`). Badge total may legitimately exceed the tree's top-10-roots slice by design.
- **Lazy `(menuOpened)` full-tree fetch** — `onPanelOpen()` fires `InstanceService.listInstanceTreeFull(10)` ONCE per open, guarded by `panelOpen` + `panelOpenFetchInFlight` (`:885-926`); writes `panelOpenInstancesPayload` only if still open (`:905-907`); error handler intentionally side-effect free (`:909-924`). `instanceRoots` computed swaps sources atomically: panel closed → `buildInstanceNodes(instancesPayload)`; panel open + non-empty open payload → open payload; else fallback to poll data (`:331-336`; rationale `:296-330`). `onPanelClose()` is STALE-KEEP — payload retained so reopen renders the last good tree immediately and a failed refetch can't flatten it (`:970-979`).
- **Navigation handlers** (menu closes FIRST, then tab/route mutation): `onJobClick` (`:1069-1085`), `onInstanceClick` → `/projects/<key>/instances/<id>` (`:1101-1120`), `onFooterClick` → `/jobs` (`:1132-1135`). Project tab opened via `TabStateService` with name-map/first-8-char fallback (`:1072-1079, 1104-1112`).
- Panel wiring: `[instances]="instanceRoots()"` + the three outputs (`job-queue-indicator.component.html:112-123`); menu opens leftward via `xPosition="before"` (`html:103-112`); `recentJobs` public computed filters terminal-only, sorts newest `completed_at||created_at`, caps 10 (`:146-155`).

## 4. `services/instance.service.ts` Contracts

- **`listInstanceTree(limit = 10)`** (`instance.service.ts:441-461`): `api.listInstances(limit, 0, undefined, true, undefined, 'activity', false)` — `exclude_kb=true`, `order='activity'` (live roots first even under 20+ pinned roots), **`include_descendants=false`** (poll-spam fix: no per-tick BFS; flat paginated slice, roots+children mixed, ≤limit rows; out-of-page children promoted to top-level nodes = degraded-but-sane tree). Deliberately STATELESS — does not touch the sidebar page's search/offset/SSE-merged state (`:396-439`).
- **`listInstanceTreeFull(limit = 10)`** (`instance.service.ts:498-506`): identical but `include_descendants=true` — BE re-engages per-root descendant BFS, full nested subtree. Fires only on panel-open (debounce-guarded); failures surface in the caller's subscribe error callback, NOT a forkJoin leg (`:463-497`).
- Return shape for both: `InstanceListResponse` whose `instances` are the flat `InstanceRow[]` of §1 (`instance-node.model.ts:140-158`). Separate sidebar lifecycle: `loadInstances` (60s poll, search-aware, SSE merge, root-based pagination with `has_more`) at `instance.service.ts:295-393` — the indicator never touches it.

## 5. Missions API Consumption in the FE Today

- **No `mission.service.ts` exists.** Grep for `api/missions|listMissions|MissionService` across `frontend/src/app` hits only: `services/job.service.ts` (`listMissions` `:167-172`, `listJobsByMission` `:210-217`), `models/mission.model.ts`, specs.
- **`GET /api/missions` is consumed in exactly one place**: the indicator's LEG A badge call (`job-queue-indicator.component.ts:680-688`) via `JobService.listMissions`.
- `models/mission.model.ts` holds the envelope types + `missionCountFromListResponse` (`total ?? missions.length`, degraded ⇒ `null`) (`mission.model.ts:26-55`); `MissionSummary` survives solely as the badge wire type (`job.model.ts:408-443`, historical note `:422-430`).
- `JobService.listJobsByMission(missionId)` (`GET /api/jobs?mission_id=…`, `job.service.ts:210-217`) is **deliberately UNWIRED** (leader decision 2026-09-07; docblock `:174-208`) — kept for a future lazy per-node fetch. `GET /api/missions/{id}` (detail) has NO FE service method at all. A Jobs page needing mission surfaces would be the first richer consumer; today the FE consumes missions only as a count + breakdown.

## 6. Settled / Receipt Vocabulary (two personalities: task=work, message=receipt)

- `JobStatus` union includes `settled` (M3, 2026-09-03) (`job.model.ts:11`); the two-personality split is documented at `:3-29`: `job_type='task'` = mission row (its status IS the lifecycle answer), `job_type='message'` = mirror/receipt row (status is the receipt answer; `mission_liveness` carries the parent answer). `MissionLiveness` value space `:31-41` (null ⇒ render nothing extra, never invent a state).
- Terminal set: `completed || settled || failed || cancelled || dead_letter` (`isTerminalStatus` `job.model.ts:154-156`).
- Helpers: `isReceiptRow` `:191-193`; `isLiveMissionLiveness` (pending/processing/paused) `:206-208`; `missionLivenessChip` → `{value, live, label: "mission: <value>", color}` or null `:253-272`; tooltip prose `:299-303` with the M3 rule: mission-side prose must NOT use the word `settled` (`:289-297`).
- Colors: `settled` = teal `#14B8A6`, deliberately distinct from `completed` green `#22C55E` so transport-handled ≠ work-done (`job.model.ts:343-351`).
- Glyphs (panel): `settled → receipt_long` (a settled mirror IS a delivery receipt, not a completed mission) vs `completed → check_circle`; spec-pinned `job-queue-panel.component.ts:611-630` + `job-queue-panel.component.spec.ts:623-630`. Status text rendered UPPERCASE verbatim in live rows (`html:134`), plain verbatim in recent rows (`html:292,345`).
- Chip component `app-mission-liveness-chip` embedded with click/keydown stopPropagation (`html:135-141, 293-299, 346-352`).

## 7. Keyboard / ARIA / Menu-Shell Patterns to Reuse

- WAI-ARIA tree pattern: `role="tree"`+`aria-label` per section, `role="treeitem"` + `aria-level` + `aria-expanded` on instance rows (`html:41, 57-62, 210, 213-218`); rows are `role="button" tabindex="0"` (`html:109-110`); chevron is a real button with `aria-expanded`/`aria-label` (`html:72-79`).
- Arrow-key model: ArrowDown/Up move REAL DOM focus via `document.getElementById(id)?.focus()` over the flattened `visibleItems` list, CLAMP at ends (no wrap); ArrowRight expands a collapsed instance (no-op on jobs); ArrowLeft collapses, and on a child row collapses the nearest ANCESTOR and refocuses it (WAI-ARIA) (`job-queue-panel.component.ts:402-477`; model `instance-node.model.ts:586-676`). Focus id single-writer = the row's `(focus)` event (`:370-380`). Enter/Space = activate (navigate) on the row itself; Esc handled by mat-menu (`:397-400`).
- Enter `preventDefault()` requirement inside mat-menus (F2 trap) — §2 above; applies to EVERY row binding (`html:44-56`).
- Footer is a sibling of the keydown container so tree nav can't phantom-move (`html:366-372`); footer supports Space activation (`html:378`).
- Material menu shell: Material 21 ships global `.mat-mdc-menu-panel { min-width:112px; max-width:280px; overflow:auto }` (`styles.scss:75-76`); per-menu `panelClass` override is a GLOBAL rule (CDK overlay mounts at `<body>`, component-scoped ::ng-deep can never match) — `.mat-mdc-menu-panel.job-queue-dropdown { max-width: calc(100vw - 16px); overflow-x: hidden }` (`styles.scss:93-96`, set via `<mat-menu class="job-queue-dropdown">` `job-queue-indicator.component.html:112`); width contract documented so the shell never under-cuts the panel (`styles.scss:87-92`). Header-right dropdown buttons anchor with `xPosition="before"` (`html:103-112`). Notification twin at `styles.scss:115-118`.
- Degraded-state a11y: lastIntakeError flips the missions segment into a `degraded` modifier + honest aria-label (`html:20-29`; ts `:605, 730-735`); tooltip stays present even when idle (`:526-537`).

## 8. Gap List — What the Panel Does NOT Do (Jobs PAGE territory)

- **No pagination anywhere**: instances fixed at top-10 roots (`listInstanceTree(10)`), Recent capped at 10 job rows (`MAX_RECENT_INSTANCE_ROWS`, `listRecentJobs(10)`); `JobFilters` has no limit/offset fields (`job.model.ts:118-125`); `listJobs` maps the whole envelope with no paging (`job.service.ts:85-106`). A page needs server-paged windows over `/api/jobs` and `/api/instances`.
- **No deep filters**: no status/source/agent/project/queue filter UI, no search box in the panel. (`JobService.listJobs` already supports `status,source,agent_id,project_id,queue_id,include_deleted` — `job.service.ts:85-96` — but nothing in the panel uses it.)
- **No row actions**: panel rows are navigate-only. No cancel / retry / resume / replay / cleanup / DLQ actions (service-side surfaces exist: defer-holder force-complete + resend `job.service.ts:240-269`, cleanup result types `:40-68`, DLQ replay types `job.model.ts:389-406`; the indicator exposes only the defer-holder unstick menu `job-queue-indicator.component.html:79-101`).
- **No detail inspection**: no job/mission drawer — only tooltips (`[matTooltip]=instance_id` `html:111,170,269,322`; project tooltip `html:128`). `GET /api/missions/{id}` has no FE consumer at all (§5).
- **No bulk views / cross-cutting slices**: no project-grouped or agent-grouped list views, no dead-letter queue view, no queue-level (queue.service.ts) view, no multi-select.
- **No alternative read model**: the unified `GET /api/work` surface (kinds job/report, filters `status/project_id/instance_id/kind/root_only`) is fully wrapped by `WorkService` (`services/work.service.ts:51-78`) whose docblock explicitly anticipates "the Jobs page can wire it alongside" JobService/QueueService (`work.service.ts:9-19, 27-29`) — the panel never calls it.
- **No SSE-driven updates**: panel data arrives solely via the 8s poll forkJoin (no `job-sse` subscription in panel/indicator).
- **Vocabulary decision the page must make**: panel is instances-primary and missions appear only as a badge count; the Jobs page must position itself (work/task list vs conversation tree vs both) without duplicating the panel's never-hide tree, and `listJobsByMission` (`job.service.ts:210-217`) is the pre-built lazy per-mission fetch if it goes mission-deep.
- Known BE-side context for page filters: `GET /api/jobs` accepts `mission_id` as canonical filter (`instance_id` deprecated alias) and `status` combos; the settled+failed combo drop defect is a pre-existing BE issue (flagged in project notes) the page's filter design should not depend on.

## Merge-Order Rules (`services/message-merge.util.ts`) — for transcript surfaces

- `mergeMessagesById` / upsert-in-place by `message_id`; genuinely-new rows append in incoming array order; **NO `created_at` re-sort, ever** — server array order (checkpoint order) is authority; `created_at` is display metadata only (`message-merge.util.ts:108-121`). Existing-only entries (provisional bubbles) preserved (`:95-107`).
- `earlierOf` stabilizes the DISPLAYED stamp only (MIN-4: metadata-less checkpoint rows carry a moving re-stamp) (`:38-59`); it must never drive position (`:48-54`).

---

**Summary for the planner:** the design language = *instances-primary tree + receipts as leaves + coalesced `mission_id ?? instance_id` grouping + NEVER-hide bucket routing + capped-Recent-with-overflow + user-touched-wins expansion + dumb panel / fetching indicator + one-8s-forkJoin with per-leg retain-on-failure + lazy full-tree on open + honest degraded states + WAI-ARIA tree with real-button chevrons + Enter-preventDefault in menus + per-menu global menu-shell widening*. A Jobs page should reuse the vocabulary (settled=`receipt_long` teal vs `check_circle`, mission chip), the retention/degradation discipline, and the service layer (`JobService` filters, `WorkService`, `listJobsByMission`), while adding what the panel deliberately lacks: pagination, filters, actions, detail inspection, and alternative groupings.
