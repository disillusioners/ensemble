# Phase 2 — Read-back surfaces, operator CLI, runbook, boot-mode surfacing

Phase objective: make the Phase-1 captures **retrievable and legible** — to an agent (privileged read-only
tool category), to an operator (CLI + runbook), and to the incident analyst (a status surface that answers
"was auto-continue ON in the epoch this capture came from, and is the watchdog armed right now?").

Depends on Phase 1 (the capture directory layout and the `wedge_captures` table are the contract).

Authoritative tree: `/home/nea/ensemble-src-wt-wedge-capture` (base `639b7129b`).

---

## 1. Objective

Ship three read-back surfaces over the Phase-1 capture store, plus the status surface:

1. **Agent-facing** — a new privileged tool category `wedge-capture` with two **read-only** tools
   (`wedge_capture_list`, `wedge_capture_get`), allow-listed to **ari + leader + maintenancer**, with the
   in-body agent gate as a **second** layer (the house two-layer posture).
2. **Operator-facing** — an admin HTTP API under `/api/wedge-captures` (list / fetch / manual-capture /
   status) and a **thin** CLI at `scripts/wedge_capture.py` that speaks only HTTP to that API.
3. **Document-facing** — a runbook at `docs/runbooks/wedge-capture.md` that states plainly what the
   instrument captures, what it does NOT do, and how to run the manual drill on a non-live host.

Plus: the **effective auto-continue mode** and the **watchdog status** surfaced through the same read-back.
