## Objective

Make the promote soak able to distinguish "busy but healthy" from "broken" without weakening the
never-green rollback. The daemon classifies each degraded readiness tick into exactly one failure
class, samples both pool states in-band, computes a pool-leak signature, and runs a class-gated,
doubly-bounded, leak-refusing grace whose state is published in the `/readyz` `detail` — the daemon's
verdict never changes (a grace-held daemon still answers 503 with its reasons intact). The gate
consumes that structured signal: it reads the probe body on the transient path, holds (never
advances, never resets) its green counter on grace-eligible observations, extends the soak window by
a bounded, spent-not-refunded amount, and fixes the `_PROBE_STATUS` aliasing defect in the same
change. In parallel, the auto-continue resume burst is deferred — not dropped — while a shell-owned
promote transaction is live (FOUR dispatch seams: the boot pass, the runtime resume dispatch, the eligible-pending sweep, and the sister orphan sweep `sweep_orphaned_live_turns` — `daemon/services/auto_continue_boot_pass.py:726-729`, wired `daemon/api.py:2708`), and the P2 checkpoint pool gets its sizing knob,
a bounded acquisition timeout, and a lock-contention-aware probe classification.

**Phase mapping (`requirements.md` §8 4-phase column):** (i) = phase 1 (A1–A4), (ii) = phase 2 (B1/B2-narrowed/B3), (iii) = phase 3 (C1–C4), **(iv) = the A5 cross-cutting pins + staged verification — carried by phase 3** (the execution layer ships three phase files).
