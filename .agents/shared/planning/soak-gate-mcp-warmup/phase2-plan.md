## Objective

Remove the verified event-loop blockers from the MCP warmup + session path and make both unbounded
waits bounded, so a warming — or permanently wedged — MCP server can never starve the single asyncio
thread again. **Framing (explorer-confirmed): no single long blocking call exists in `daemon/mcp/*` —
the loop starvation is CUMULATIVE CHURN.** B1's offload list is therefore: (a) the `/proc` child-stamp
scan — **W-3 shape (council-ruled; the fire-and-forget/deferred variant is REJECTED): `on_ready` is widened to
`Callable[[], Optional[Awaitable[None]]]`; the hook performs the scan OFF-loop (`asyncio.to_thread`) and the
transport AWAITS the returned awaitable BEFORE `_ready.set()` (work off-loop, await on-loop). A deferred
scan is unsafe: a deferred scan that finds a dead child returns [] ⇒ no reap handle, and the existing pin
`tests/test_resource_pid_registry.py:505-510` requires registration BEFORE `__aenter__` returns. Do NOT ship
fire-and-forget**;
(b) the **synchronous secret/KMS marker resolution** — `resolve_secret_markers`
(`daemon/services/secret_resolver.py:300`) and `resolve_env` (`daemon/services/kms_resolver.py:149`)
are plain `def`, called INLINE on the loop in the spawn path (`warmup_pool.py:256-268`,
`connection_manager.py:229-237`); (c) the in-loop per-line JSON-RPC parsing (SDK `_parse_line` +
pydantic, per child stdout line) and schema adaptation (`warmup_pool.py:315-324`). Each site is
individually short; cumulatively they are the peg. The transport handshake gets a hard bound strictly
inside the 60s warmup budget (**`HANDSHAKE_WAIT_TIMEOUT_S = 30.0` s — the value is normative in `requirements.md` §4.6 (P6); the 55 s value is **REJECTED**: 55+2+30+6 = 93 s > 60 s, 30+2+30+6 = 68 s ≤ 60 s**), and `__aenter__` moves inside that budget so the existing
`except BaseException` cleanup block becomes reachable. **BUT bounding the waits is NECESSARY, NOT
SUFFICIENT for B3 (explorer G1, verified at `stdio_wrapper.py:386-388` vs the `finally:` at
`:412-414`):** a cancellation during `__aenter__` re-raises through `_run` BEFORE the `finally:` can
install the SDK's `streams_cm.__aexit__` — the process-group shutdown (stdin close → killpg SIGTERM →
killpg SIGKILL) NEVER runs and any spawned child survives. `warmup_pool.py:333-344`'s cleanup cannot
repair it (after G1 the wrapper's task is already cancelled; `__aexit__` at `stdio_wrapper.py:352-363`
awaits a dead task and returns), and a bounded wait that times out routes through that same
cancellation path. B3 therefore ALSO guarantees the inner transport `__aexit__` (or an explicit
child-tree kill) on the cancellation/timeout path, and proves it by pid-liveness **exercising the
timeout/cancellation path**, not only the clean-failure path. The aiohttp clause is NOT claimed (N-2:
zero aiohttp in `daemon/mcp/` — routed to a follow-up; routing hint in the risk register). B2 delivers
only its narrowed content: a regression pin proving the readiness composite and `pending-count` are
MCP-independent. Per the D-5 adjudication (decisions §3e alternatives), the **targeted fix** is
implemented — thread hops for the named sites plus bounded waits — not a thread-ified warmup; the
loop-lag pin is the AC that decides adequacy. Off-loop precedent to copy: the loader-cache warm
(`await loop.run_in_executor(None, self._warm_loader_caches_sync)`, `daemon/manager.py:3910`); capped
executors: `plane_sync_service.py:253` (max_workers=2), `question_pause_set.py:137` (max_workers=1),
`upgrade_journal_sweep.py:228-236` (waitpid reaper pool); **no `set_default_executor` exists anywhere**
— `run_in_executor(None, …)` shares asyncio's default pool.
