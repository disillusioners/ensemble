## Coupling

- **Tight with:** Phase 2 (manager construction of the chat pool depends on `WorkerPool(worker_id_prefix=..., lane=...)`, `TaskProcessor(..., lane=...)`, `claim_pending_task(lane=...)`); Phase 3 (unit + integration tests assert the seam and the gate).
- **Loose with:** None.
- **Independent of:** Phase 2 — this phase can ship first **ONLY under the conditional fail-open semantics specified below** (B1 approver requirement). Phase 2 constructs the chat pool AND flips the default-lane strictness flag ON; both happen in the same merge. If Phase 1 ships alone (degenerate), the predicate's default-lane exclusion MUST fall back to "claim chat rows too" — i.e., fail-open — so a Phase-1-only deployment behaves identically to today (no telegram:/slack:/discord: row is permanently unclaimable).

**Conditional fail-open semantics (B1 — leader option b):** the chat-prefix `NOT EXISTS` predicate lands in P1 (Tasks #6-7), but **default-lane strictness activates ONLY WHEN THE CHAT POOL EXISTS**. Concretely: the default-lane claim predicate is gated by a **chat-lane-active flag** that the chat pool's construction sets to True and the chat pool's teardown sets back to False. The flag is consulted on **every default-lane claim** (or at minimum on both chat-pool construction AND teardown — implementation choice). The flag is **NEVER a one-way boot latch**: teardown restores fail-open, so a chat pool that fails to construct or that is stopped mid-lifecycle falls back to default-lane claims of chat rows (= today's behavior, safe). Three guarded states:

| State | Chat pool | Flag | Default-lane claim of chat-prefix rows | Test |
|---|---|---|---|---|
| Phase 1 alone (P2 not merged) | not constructed | False | **claims them** (fail-open = today) | required (B1 test, phase2 home — see S4) |
| Phase 1 + Phase 2 (normal) | constructed | True | **excludes them** (strict two-way) | covered by Tasks #6-7 (approver S3 — predicate/strictness tasks; NOT Task #5) |
| Phase 2 shutdown | stopped, cleared | False | **claims them** (fail-open restored) | required (B1 test, phase2 home — see S4) |

`USE_WORKER_POOL=false` path: no pools at all → no lane filtering anywhere (claims cannot happen; nothing to strand).

**Shared contracts (must be stable across Phase 1/2/3):**
- `claim_pending_task(worker_id: str, lane: str = "default") -> Task | None` — exact signature.
- `is_chat_source(source: str | None) -> bool` — pure helper; no side effects.
- `CHAT_WORKER_POOL_SIZE: int` and `CHAT_SOURCE_PREFIXES: tuple[str, ...]` — hardcoded constants.
- `WorkerPool(..., worker_id_prefix: str = "worker-", lane: str = "default")` — both constructor kwargs (F3).
