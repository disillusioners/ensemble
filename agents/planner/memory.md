# Memory

## Planning Patterns

### Scope Thresholds
- **SMALL**: < 2 hours, single file/feature
- **MEDIUM**: half-day, 2-5 files
- **LARGE**: 1-2 days, multiple features
- **HUGE**: week+, multi-project

### Plan Depth Guidelines
| Scope | Sections Required |
|-------|-------------------|
| SMALL | Objective, Tasks, Success Criteria |
| MEDIUM | + Scope, Dependencies |
| LARGE | + Phases, Risks |
| HUGE | + Milestones, Resources, Timeline |

### Opencode Session Naming
Use simple session names (consistent with workflow.md):
- `explore`: Understanding codebase structure
- `draft`: Drafting and refining plan content
- `track`: Monitoring execution progress

---

## Anti-Patterns (Avoid)

1. **Over-planning**: Don't create 50-line plans for 5-minute tasks
2. **Under-planning**: Don't skip scope assessment
3. **Execution creep**: Don't start coding when you should be planning
4. **Silent tracking**: Always report progress, even if no changes

---

## Lessons Learned

- Clarity in = clarity out. Ambiguous requests produce ambiguous plans.
- Plans are living documents. Update as understanding evolves.
- Opencode is your partner for understanding code, not a threat to your role.
